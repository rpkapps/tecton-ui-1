## Usage

```tsx
import {
  AppShell,
  AppShellActions,
  AppShellAside,
  AppShellBody,
  AppShellBrand,
  AppShellHeader,
  AppShellMain,
  AppShellNav,
  AppShellSidebar,
} from "@tecton/react/tecton/app-shell"
```

```tsx
<AppShell>
  <AppShellHeader>
    <AppShellBrand>Tecton</AppShellBrand>
    <AppShellNav>…</AppShellNav>
    <AppShellActions>…</AppShellActions>
  </AppShellHeader>
  <AppShellBody>
    <AppShellSidebar>…</AppShellSidebar>
    <AppShellMain>…</AppShellMain>
    <AppShellAside>…</AppShellAside>
  </AppShellBody>
</AppShell>
```

The shell fills the viewport (`h-svh`); the previews on this page pass a fixed height through `className`.

## Actions

`AppShellActions` is the global action cluster pinned to the end of the header: the command palette trigger, icon actions and the user menu. It belongs to the host application, so every mounted application shows the same cluster.

<ComponentPreview name="app-shell-actions" />

```tsx
<AppShellActions>
  <AppShellCommandTrigger shortcut="⌘K" onClick={openPalette}>Search or jump to…</AppShellCommandTrigger>
  <AppShellAction label="Help" shortcut="?"><CircleHelpIcon /></AppShellAction>
  <AppShellAction label="Settings" className="hidden lg:inline-flex"><SettingsIcon /></AppShellAction>
  <AppShellOverflow className="lg:hidden">
    <DropdownMenuItem onClick={openSettings}><SettingsIcon /> Settings</DropdownMenuItem>
  </AppShellOverflow>
  <AppShellDivider />
  <AppShellUserMenu user={{ name: "Sarah Elliott", initials: "SE" }}>
    <DropdownMenuItem onClick={signOut}>Sign out</DropdownMenuItem>
  </AppShellUserMenu>
</AppShellActions>
```

`AppShellCommandTrigger` looks like a search field from `md` up and is an icon button below it. `shortcut` on it and on `AppShellAction` only draws a key cap; the application binds the key. Hide icon actions below a breakpoint and repeat them in `AppShellOverflow`.

## Resizable split

Put the main area and a full-height aside in `AppShellSplit`, each in an `AppShellSplitPanel`, with an `AppShellSplitHandle` between them. Sizes take `"320px"`, `"25%"` or `"20rem"`. Give the aside `h-full w-full border-s-0`, since the handle draws the divider, and render it only on wide viewports with `useMinWidth`.

<ComponentPreview name="app-shell-split" />

```tsx
const showAside = useMinWidth(1280)

<AppShellSplit>
  <AppShellSplitPanel minSize="40%">
    <AppShellMain>…</AppShellMain>
  </AppShellSplitPanel>
  {showAside && (
    <>
      <AppShellSplitHandle />
      <AppShellSplitPanel defaultSize="384px" minSize="280px" maxSize="50%">
        <AppShellAside className="h-full w-full border-s-0">…</AppShellAside>
      </AppShellSplitPanel>
    </>
  )}
</AppShellSplit>
```

## Usage guidelines

### Use it when

- The outermost frame of an application: a top bar, an optional left rail, a work area, an optional right aside.
- The frame fills the viewport (`h-svh`) and clips its own overflow, so each region scrolls on its own.
- The header carries the host's own cluster — search, help, settings, the account menu — so every mounted application shows the same set.
- A tool panel lives beside the content and the user may drag the divider between them.

### Not for

- a titled tool surface inside the work area: use [Panel](/docs/tecton/panel)
- the title block at the top of the page inside the main area: use [PageHeader](/docs/tecton/page-header)
- actions that belong to the page rather than to the shell: use [PageHeaderActions](/docs/tecton/page-header)
- a panel that floats over the page and is dismissed: use [Sheet](/docs/components/sheet)
- a toolbar that folds into a More menu by measured width: use [Overflow](/docs/tecton/overflow)
- switching between applications from the header: use [AppFinder](/docs/tecton/app-finder)

### Do

<DoList>

<Do>

Compose it: `AppShellHeader` (with `AppShellBrand`, `AppShellNav`, `AppShellActions`), then `AppShellBody` holding `AppShellSidebar`, `AppShellMain` and `AppShellAside`.

</Do>

<Do>

Put the page content in `AppShellMain`; it is the scrolling region of the work area.

</Do>

<Do>

Give every `AppShellAction` a `label` — both the accessible name and the tooltip — separate groups with `AppShellDivider`, and on a narrow header hide the low-priority ones (`hidden lg:inline-flex`) in favour of `AppShellOverflow` (`lg:hidden`).

</Do>

<Do>

For a draggable divider, wrap the regions in `AppShellSplit` with an `AppShellSplitPanel` each and an `AppShellSplitHandle` between them, and gate a full-height aside on `useMinWidth(1280)`.

</Do>

<Do>

Inside an `AppShellSplitPanel` give the `AppShellAside` `className="h-full w-full border-s-0"`; otherwise `className` overrides the height alone (`h-full` in an embedded context) and the shell keeps its surfaces and borders.

</Do>

<Do>

Keep `AppShellNav` one level deep: a destination may open one `DropdownMenu`; anything deeper belongs in `AppShellSidebar`.

</Do>

<Do>

Every navigation area on a page has its own screen-reader name (`aria-label`): app nav, page-header nav, rails and any second breadcrumb.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="An icon Button with a title instead of AppShellAction">

<Wrong>

```tsx
<Button variant="ghost" size="icon-sm" title="Settings" onClick={openSettings}>
  <SettingsIcon />
</Button>
```

</Wrong>

<Correct>

```tsx
<AppShellAction label="Settings" onClick={openSettings}>
  <SettingsIcon />
</AppShellAction>
```

</Correct>

A `title` is a mouse-only hint that screen readers announce inconsistently and keyboard focus never shows, so an icon-only button with no text node is left without a reliable name; `AppShellAction` sets `aria-label` from `label` and wraps the button in a tooltip that also opens on keyboard focus.

</Dont>

<Dont severity="HIGH" title="Page content placed straight into AppShellBody">

<Wrong>

```tsx
<AppShellBody className="overflow-y-auto p-6">{page}</AppShellBody>
```

</Wrong>

<Correct>

```tsx
<AppShellBody>
  <AppShellMain className="p-6">{page}</AppShellMain>
</AppShellBody>
```

</Correct>

`AppShellBody` is the `flex min-h-0 overflow-hidden` row that holds the regions side by side, so content dropped into it is clipped at the fold and the sidebar and aside have nothing to sit beside.

</Dont>

<Dont severity="HIGH" title="The key hint mistaken for a binding">

<Wrong>

```tsx
<AppShellCommandTrigger shortcut="⌘K" onClick={open}>Search</AppShellCommandTrigger>
```

</Wrong>

<Correct>

```tsx
useEffect(() => {
  const onKey = (e: KeyboardEvent) => e.key === "k" && (e.metaKey || e.ctrlKey) && open()
  window.addEventListener("keydown", onKey)
  return () => window.removeEventListener("keydown", onKey)
}, [open])
return <AppShellCommandTrigger shortcut="⌘K" onClick={open}>Search</AppShellCommandTrigger>
```

</Correct>

`shortcut` (on `AppShellCommandTrigger` and `AppShellAction`) only draws a key cap; Tecton binds no keys, so the application registers the key itself or the hint promises a shortcut that does nothing.

</Dont>

{/* guidelines:end */}

## API Reference

### Layout parts

`AppShell` (grid, `h-svh`), `AppShellHeader`, `AppShellBrand`, `AppShellNav`, `AppShellActions`, `AppShellBody`, `AppShellSidebar`, `AppShellMain` and `AppShellAside` are styled elements that accept the props of the element they render.

### AppShellAction

Ghost icon `Button` with a tooltip. Accepts `Button` props.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | - | Accessible name and tooltip text. |
| `shortcut` | `ReactNode` | - | Key hint in the tooltip: a string is one key cap, a node is drawn as is. |

### AppShellCommandTrigger

Outline `Button` styled as a search field. Accepts `Button` props.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | `"Search"` | Placeholder text; a string is also the accessible name. |
| `shortcut` | `ReactNode` | - | Key hint at the end, from `lg` up. |

### AppShellUserMenu

Avatar button opening a dropdown menu.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `user` | `{ name: string; initials: string; image?: string }` | - | Avatar content; the accessible name is `"Account: {name}"`. |
| `children` | `ReactNode` | - | Menu contents: `DropdownMenuItem`, `DropdownMenuGroup`, … |
| `open` / `defaultOpen` / `onOpenChange` | `boolean` / `boolean` / `(open: boolean) => void` | - | Open state. |
| `className` | `string` | - | Classes of the trigger. |

### AppShellOverflow

Ellipsis button opening a dropdown menu. Same props as `AppShellUserMenu` without `user`, plus:

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | `"More"` | Accessible name of the trigger. |

### AppShellDivider

Vertical hairline (`role="separator"`) between groups of actions.

### AppShellSplit, AppShellSplitPanel, AppShellSplitHandle

Styled [Resizable](/docs/components/resizable) group, panel and handle; they accept the same props (`orientation`, `defaultSize`, `minSize`, `maxSize`, `collapsible`, …).

### useMinWidth

`useMinWidth(minWidth: number): boolean` — whether the viewport is at least `minWidth` px wide; `false` during server rendering.
