## Usage

```tsx
import {
  Composer,
  ComposerField,
  ComposerHint,
  ComposerInput,
  ComposerStatusMessage,
  ComposerSubmit,
  ComposerToolbar,
} from "@tecton/react/tecton/composer"
```

```tsx
<Composer status={status} onStop={stop} onSubmit={({ text }) => send(text)}>
  <ComposerField>
    <ComposerInput />
    <ComposerToolbar>
      <ComposerSubmit />
    </ComposerToolbar>
  </ComposerField>
  <ComposerHint />
  <ComposerStatusMessage />
</Composer>
```

It pairs with [Message](/docs/components/message) and [Message Scroller](/docs/components/message-scroller) for the transcript. The textarea stays enabled while a reply streams, so the next message can be drafted; it sends once `status` is no longer `submitted` or `streaming`. While busy, Send becomes Stop when `onStop` is set.

## Keyboard

| Key | Does |
| --- | --- |
| <Kbd>Enter</Kbd> | Sends; a new line with `submitMode="mod-enter"` |
| <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd> | New line |
| <Kbd>⌘</Kbd> / <Kbd>Ctrl</Kbd> + <Kbd>Enter</Kbd> | Sends, in either mode |
| <Kbd>Esc</Kbd> | Stops a reply that is arriving |
| <Kbd>↑</Kbd> / <Kbd>↓</Kbd> on the first / last line | Steps through `history` |

Enter never sends while an input method is composing text.

## Toolbar

`ComposerToolbar` takes any buttons, tooltip triggers included, as one tab stop moved through with the arrow keys; put `ComposerSubmit` last.

```tsx
<ComposerToolbar>
  <Tooltip>
    <TooltipTrigger render={<InputGroupButton size="icon-xs" aria-label="Attach file" />}>
      <PaperclipIcon />
    </TooltipTrigger>
    <TooltipContent>Attach</TooltipContent>
  </Tooltip>
  <ComposerSubmit />
</ComposerToolbar>
```

## History

Pass the prompts the user has sent as `history`, oldest first: <Kbd>↑</Kbd> on the first line loads the previous one, <Kbd>↓</Kbd> on the last line goes forward and, past the newest, brings back the draft. `historyLimit` caps how far back it goes.

```tsx
<Composer
  history={turns.filter((turn) => turn.role === "user").map((turn) => turn.text)}
  onSubmit={({ text }) => send(text)}
>
```

## Context and suggestions

`ComposerAttachments` lists what goes with the message besides its text as removable chips. A `ComposerSuggestion` fills the box to edit, sends at once with `submit`, or hands the click to `onSelect`.

## Commands

`ComposerCommands`, inside `ComposerField`, lists commands when the box starts with `/`. Typing narrows the list; <Kbd>↑</Kbd> <Kbd>↓</Kbd> move, <Kbd>Enter</Kbd> or <Kbd>Tab</Kbd> picks, <Kbd>Esc</Kbd> closes it. With no match Enter sends as usual. Picking empties the box and calls `onCommand` with the command and the composer's `setValue`, `send` and `focus`.

```tsx
<ComposerField>
  <ComposerCommands
    items={[{ value: "new", command: "new", label: "Start a new conversation" }]}
    onCommand={(item) => startOver()}
  />
  <ComposerInput />
</ComposerField>
```

## Announcements

`ComposerStatusMessage` announces the composer's own changes (sent, stopped, failed). The reply is the transcript's to announce: set `aria-busy` on `MessageScrollerContent` while it streams.

## Usage guidelines

### Use it when

- The user writes to an assistant or agent: the message box under a transcript.
- A reply streams back and the user must be able to stop it, and keep typing the next message meanwhile.
- The message carries something besides its text (a selection, a file) that the user can see and remove before sending.
- The user types slash commands (`/new`, `/summarise`) in the message box and picks one from a list.

### Not for

- a one-line search or filter box: use [InputGroup](/docs/components/input-group)
- a form field for a long description: use [Textarea](/docs/components/textarea)
- a structured question with choices for the user to answer: use [Questionnaire](/docs/components/questionnaire)

### Do

<DoList>

<Do>

Pass the chat's `status` (`"ready" | "submitted" | "streaming" | "error"`) and `onStop`; `ComposerSubmit` swaps Send for Stop and Escape stops the reply.

</Do>

<Do>

Keep `ComposerHint` (visible, or `visible={false}`) so the textarea is described by its keys, and `ComposerStatusMessage` for sent, stopped and failed.

</Do>

<Do>

Pair it with a transcript whose `MessageScrollerContent` has `aria-busy` while a reply streams, so the reply is announced once, complete.

</Do>

<Do>

Pass the prompts already sent as `history` (oldest first) for ArrowUp and ArrowDown, and use `submitMode="mod-enter"` for long-form input.

</Do>

<Do>

Put extra context in `ComposerAttachments`, prompts to start from in `ComposerSuggestions`, slash commands in `ComposerCommands` inside `ComposerField`, and your own buttons (`InputGroupButton`, with or without a tooltip) straight into `ComposerToolbar` before `ComposerSubmit`.

</Do>

</DoList>

### Don't

<Dont severity="HIGH" title="Disabling the textarea while a reply streams">

<Wrong>

```tsx
<InputGroupTextarea disabled={status === "streaming"} value={text} onChange={(event) => setText(event.target.value)} />
```

</Wrong>

<Correct>

```tsx
<Composer status={status} onStop={stop} onSubmit={({ text }) => send(text)}>
  <ComposerField>
    <ComposerInput />
    <ComposerToolbar>
      <ComposerSubmit />
    </ComposerToolbar>
  </ComposerField>
</Composer>
```

</Correct>

A disabled textarea drops focus to the page body mid-reply and stops the user drafting; `Composer` keeps it enabled and simply does not send until the chat is ready.

</Dont>

<Dont severity="HIGH" title="An Enter handler that ignores IME composition">

<Wrong>

```tsx
<InputGroupTextarea onKeyDown={(event) => { if (event.key === "Enter" && !event.shiftKey) send() }} />
```

</Wrong>

<Correct>

```tsx
<Composer onSubmit={({ text }) => send(text)}>
  <ComposerField>
    <ComposerInput />
  </ComposerField>
</Composer>
```

</Correct>

The Enter that confirms a Japanese or Chinese conversion arrives as a keydown too, and in Safari after `compositionend`, so the half-typed message is sent; `ComposerInput` ignores `isComposing` and key code 229.

</Dont>

<Dont severity="MEDIUM" title="One send button whose label flips to Stop">

<Wrong>

```tsx
<InputGroupButton aria-label={busy ? "Stop" : "Send"} onClick={busy ? stop : send}>
  {busy ? <SquareIcon /> : <ArrowUpIcon />}
</InputGroupButton>
```

</Wrong>

<Correct>

```tsx
<ComposerToolbar>
  <ComposerSubmit />
</ComposerToolbar>
```

</Correct>

Screen readers do not reliably announce a name that changes under focus, and a click landing as the state flips stops a reply the user meant to send after; `ComposerSubmit` renders two named buttons and moves focus between them.

</Dont>

{/* guidelines:end */}

## API Reference

### Composer

A `form` that holds the value and the chat's state for its parts.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onSubmit` | `(message: { text: string }) => void` | - | Required. Receives the trimmed text; the box is cleared after. |
| `onStop` | `() => void` | - | Stops the reply; Escape and the Stop button call it. |
| `status` | `"ready" \| "submitted" \| "streaming" \| "error"` | `"ready"` | The chat's state; nothing sends while `submitted` or `streaming`. |
| `submitMode` | `"enter" \| "mod-enter"` | `"enter"` | Which key sends. |
| `history` | `readonly string[]` | - | Prompts already sent, oldest first. |
| `historyLimit` | `number` | all | How many of the newest `history` entries are reached. |
| `value` / `defaultValue` / `onValueChange` | `string` / `string` / `(value: string) => void` | - | The text, controlled or not. |
| `disabled` | `boolean` | `false` | Disables the whole composer. |

### Parts

| Part | Props |
| --- | --- |
| `ComposerField` | The bordered field around the textarea and the toolbar. |
| `ComposerInput` | The textarea (`aria-label` defaults to "Message"); grows up to `max-h-48`, then scrolls. |
| `ComposerToolbar` | The row of buttons under the textarea; `aria-label` defaults to "Message actions". |
| `ComposerSubmit` | Send, or Stop while busy: `sendLabel` ("Send message"), `stopLabel` ("Stop generating"). |
| `ComposerHint` | The keys that send, linked to the textarea: `visible={false}` keeps it for screen readers only, `children` replaces the text. |
| `ComposerStatusMessage` | `messages`: `{ submitted?, stopped?, error? }` overrides the three texts. |
| `ComposerAttachments` | `items` (`{ value, label, description?, icon? }[]`), `onRemove(value)`, `aria-label` ("Attachments"). |
| `ComposerSuggestions` | A toolbar of suggestions; `aria-label` defaults to "Suggestions". |
| `ComposerSuggestion` | `value`, `submit` (send at once), `onSelect(value)`. |
| `ComposerCommands` | `items` (`{ value, command, label, description?, group?, icon? }[]`), `onCommand(item, { setValue, send, focus })`, `countMessage(count)`, `aria-label` ("Commands"). |

### useComposer

`useComposer()` returns `value`, `setValue`, `status`, `busy` (a reply is submitted or streaming), `canSubmit`, `submit`, `stop` and `focus`, for a component inside `Composer` — for example an application key binding that focuses the box.
