## Usage

```tsx
import {
  AppShell,
  AppShellHeader,
  AppShellBrand,
  AppShellNav,
  AppShellActions,
  AppShellAction,
  AppShellCommandTrigger,
  AppShellDivider,
  AppShellOverflow,
  AppShellUserMenu,
  AppShellBody,
  AppShellSidebar,
  AppShellMain,
  AppShellAside,
  AppShellSplit,
  AppShellSplitPanel,
  AppShellSplitHandle,
  useMinWidth,
} from "@tecton/react/tecton/app-shell"
```

```tsx
<AppShell>
  <AppShellHeader>
    <AppShellBrand>Tecton</AppShellBrand>
    <AppShellNav>…</AppShellNav>
    <AppShellActions>…</AppShellActions>
  </AppShellHeader>
  <AppShellBody>
    <AppShellSidebar>…</AppShellSidebar>
    <AppShellMain>…</AppShellMain>
    <AppShellAside>…</AppShellAside>
  </AppShellBody>
</AppShell>
```

<Callout>
  The shell fills the viewport by default. The previews on this page pass a fixed height through `className`.
</Callout>

## Composition

Use the following composition:

```text
AppShell
├── AppShellHeader
│   ├── AppShellBrand
│   ├── AppShellNav
│   └── AppShellActions
│       ├── AppShellCommandTrigger
│       ├── AppShellAction …
│       ├── AppShellDivider
│       ├── AppShellOverflow
│       └── AppShellUserMenu
└── AppShellBody
    ├── AppShellSidebar
    ├── AppShellMain
    └── AppShellAside
```

## Actions

`AppShellActions` is the global action cluster at the end of the header: the command palette trigger, the icon actions (help, settings, release notes, bug report) and the user menu. It is `ms-auto`, so it pins itself to the end of the header.

<ComponentPreview name="app-shell-actions" />

<Callout>
  These controls belong to the micro-frontend host, not to the mounted application. Every application sees the same cluster, and a change to it (moving bug reports into a drawer, say) ships once through the package.
</Callout>

```tsx
<AppShellHeader>
  <AppShellBrand>Tecton</AppShellBrand>
  <AppShellActions>
    <AppShellCommandTrigger onPress={openPalette}>Search or jump to…</AppShellCommandTrigger>
    <AppShellAction label="Help" shortcut="?"><CircleHelpIcon /></AppShellAction>
    <AppShellAction label="Settings" className="hidden lg:inline-flex"><SettingsIcon /></AppShellAction>
    <AppShellOverflow className="lg:hidden">
      <DropdownMenuItem textValue="Settings"><SettingsIcon /> Settings</DropdownMenuItem>
    </AppShellOverflow>
    <AppShellDivider />
    <AppShellUserMenu user={{ name: "Sarah Elliott", initials: "SE" }}>
      <DropdownMenuItem textValue="Sign out">Sign out</DropdownMenuItem>
    </AppShellUserMenu>
  </AppShellActions>
</AppShellHeader>
```

`AppShellAction` is a ghost icon button whose `label` is both the accessible name and the tooltip; `shortcut` adds the key hint in [Shortcuts](/docs/tecton/shortcuts) key syntax. `AppShellCommandTrigger` looks like a search field from `md` up and collapses to an icon button below it; its key hint defaults to `mod+k` drawn for the platform (⌘ K on Apple keyboards, Ctrl + K elsewhere). `AppShellOverflow` is the "More" menu for the actions a narrow header cannot show, and `AppShellDivider` is the hairline between groups.

## Resizable split

Wrap the main area and a full-height aside in `AppShellSplit`, each inside an `AppShellSplitPanel`, with an `AppShellSplitHandle` between them; the user drags the divider to resize. Sizes take the [react-resizable-panels](https://github.com/bvaughn/react-resizable-panels) units (`"320px"`, `"25%"`, `"20rem"`). Give the aside `h-full w-full border-s-0`, since the handle draws the divider.

<ComponentPreview name="app-shell-split" />

Render the aside panel only on wide viewports: `useMinWidth(1280)` returns whether the viewport is at least that wide, so a narrow screen gets the main area alone instead of a squeezed split.

```tsx
const showAside = useMinWidth(1280)

<AppShellSplit>
  <AppShellSplitPanel minSize="40%">
    <AppShellMain>…</AppShellMain>
  </AppShellSplitPanel>
  {showAside && (
    <>
      <AppShellSplitHandle />
      <AppShellSplitPanel defaultSize="384px" minSize="280px" maxSize="50%">
        <AppShellAside className="h-full w-full border-s-0">…</AppShellAside>
      </AppShellSplitPanel>
    </>
  )}
</AppShellSplit>
```

## Usage guidelines

### Use it when

- The outermost frame of an application: a top bar, an optional left rail, a work area, an optional right aside.
- The frame fills the viewport (`h-svh`) and clips its own overflow, so each region scrolls on its own.
- The header carries the host's own cluster — search, help, settings, the account menu — so every mounted application shows the same set.
- A tool panel lives beside the content and the user may drag the divider between them.

### Not for

- a titled tool surface inside the work area: use [Panel](/docs/tecton/panel)
- the title block at the top of the page inside the main area: use [PageHeader](/docs/tecton/page-header)
- actions that belong to the page rather than to the shell: use [PageHeaderActions](/docs/tecton/page-header)
- a panel that floats over the page and is dismissed: use [Sheet](/docs/components/sheet)
- a toolbar that folds into a More menu by measured width: use [Overflow](/docs/tecton/overflow)
- switching between applications from the header: use [AppFinder](/docs/tecton/app-finder)

### Do

<DoList>

<Do>

Compose it: `AppShellHeader` (with `AppShellBrand`, `AppShellNav`, `AppShellActions`), then `AppShellBody` holding `AppShellSidebar`, `AppShellMain` and `AppShellAside`.

</Do>

<Do>

Put the page content in `AppShellMain`; it is the scrolling region of the work area.

</Do>

<Do>

Give every `AppShellAction` a `label` — both the accessible name and the tooltip — separate groups with `AppShellDivider`, and on a narrow header hide the low-priority ones (`hidden lg:inline-flex`) in favour of `AppShellOverflow` (`lg:hidden`).

</Do>

<Do>

For a draggable divider, wrap the regions in `AppShellSplit` with an `AppShellSplitPanel` each and an `AppShellSplitHandle` between them, and gate a full-height aside on `useMinWidth(1280)`.

</Do>

<Do>

Inside an `AppShellSplitPanel` give the `AppShellAside` `className="h-full w-full border-l-0"`; otherwise `className` overrides the height alone (`h-full` in an embedded context) and the shell keeps its surfaces and borders.

</Do>

<Do>

Keep `AppShellNav` one level deep: a destination may open one `DropdownMenu`; anything deeper belongs in `AppShellSidebar`.

</Do>

<Do>

Every navigation area on a page has its own screen-reader name (`aria-label`): app nav, page-header nav, rails and any second breadcrumb.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="An icon Button with a title instead of AppShellAction">

<Wrong>

```tsx
<Button variant="ghost" size="icon-sm" title="Settings" onPress={openSettings}>
  <SettingsIcon />
</Button>
```

</Wrong>

<Correct>

```tsx
<AppShellAction label="Settings" onPress={openSettings}>
  <SettingsIcon />
</AppShellAction>
```

</Correct>

`title` is not a `Button` prop, and React Aria's `filterDOMProps` keeps only `id`, `data-*`, labelling and global DOM attributes, so it never reaches the `button`: an icon-only button with no text node is left with no accessible name and no tooltip either, while `AppShellAction` sets `aria-label` from `label` and wraps the button in the `TooltipTrigger` that also opens on keyboard focus.

</Dont>

<Dont severity="HIGH" title="Page content placed straight into AppShellBody">

<Wrong>

```tsx
<AppShellBody className="overflow-y-auto p-6">{page}</AppShellBody>
```

</Wrong>

<Correct>

```tsx
<AppShellBody>
  <AppShellMain className="p-6">{page}</AppShellMain>
</AppShellBody>
```

</Correct>

`AppShellBody` is the `flex min-h-0 overflow-hidden` row that holds the regions side by side, so content dropped into it is clipped at the fold and the sidebar and aside have nothing to sit beside.

</Dont>

<Dont severity="HIGH" title="The key hint mistaken for a registration">

<Wrong>

```tsx
function ShellSearch({ open }: { open: () => void }) {
  return <AppShellCommandTrigger shortcut="⌘K" onPress={open}>Search</AppShellCommandTrigger>
}
```

</Wrong>

<Correct>

```tsx
function ShellSearch({ open }: { open: () => void }) {
  useShortcut({ id: "shell.palette", keys: "mod+k", label: "Command palette", onAction: open })
  return <AppShellCommandTrigger shortcut="⌘K" onPress={open}>Search</AppShellCommandTrigger>
}
```

</Correct>

`shortcut` on `AppShellCommandTrigger` only renders a `Kbd` and binds nothing, so ⌘K never opens the palette and the key is missing from `useShortcuts()` — the list the shell's help dialog and command palette are built from.

</Dont>

{/* guidelines:end */}

## API Reference

### AppShellSplit, AppShellSplitPanel, AppShellSplitHandle

Styled [Resizable](/docs/components/resizable) group, panel and handle; accept all their props (`orientation`, `defaultSize`, `minSize`, `maxSize`, `collapsible`, `onResize`, …).

### useMinWidth

`useMinWidth(minWidth: number): boolean` — true when the viewport is at least `minWidth` px wide; false during server rendering.

### AppShell

Grid with the header row and the body; fills the viewport (`h-svh`).

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `className` | `string` | - | Override the height in embedded contexts. |

### AppShellHeader, AppShellBrand, AppShellNav, AppShellActions, AppShellBody, AppShellSidebar, AppShellMain, AppShellAside

Plain styled layout elements.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `className` | `string` | - |  |

### AppShellAction

Ghost icon `Button` wrapped in a `TooltipTrigger`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | - | Accessible name and tooltip text. |
| `shortcut` | `string` | - | Key hint rendered in the tooltip, in [Shortcuts](/docs/tecton/shortcuts) key syntax (`"mod+k"`, `"?"`, `"g w"`). |
| `onPress` | `(e: PressEvent) => void` | - | Press handler. |

### AppShellCommandTrigger

Outline `Button` that looks like a search field and opens the command palette. Below `md` it collapses to an icon button; the key hint shows from `lg`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | "Search" | Placeholder text; a string is also the accessible name (otherwise "Search"). |
| `shortcut` | `ReactNode` | `<ShortcutKeys keys="mod+k" />` | Key hint at the end. The default is platform-aware (⌘ K on Apple keyboards, Ctrl + K elsewhere); anything else you pass is rendered in a `Kbd` as is; `null` hides it. The hint only displays the key: register the binding with [`useShortcut`](/docs/tecton/shortcuts). |

### AppShellUserMenu

Avatar button opening a `DropdownMenu` anchored bottom-end.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `user` | `{ name; initials; image? }` | - | Shown in the avatar and used for the accessible name. |
| `children` | `ReactNode` | - | Menu contents: `DropdownMenuGroup`, `DropdownMenuItem`, … |

### AppShellOverflow

Ellipsis button opening a `DropdownMenu` for actions that do not fit a narrow header. Hide the icon actions below a breakpoint and show this instead:

```tsx
<AppShellAction label="Settings" className="hidden lg:inline-flex"><SettingsIcon /></AppShellAction>
<AppShellOverflow className="lg:hidden">
  <DropdownMenuItem textValue="Settings"><SettingsIcon /> Settings</DropdownMenuItem>
</AppShellOverflow>
```

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | "More" | Accessible name of the trigger. |
| `children` | `ReactNode` | - | Menu contents. |

### AppShellDivider

Vertical hairline (`role="separator"`) between groups of actions.
