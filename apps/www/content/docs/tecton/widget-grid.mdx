<ComponentPreview name="widget-grid-demo" />

Press **Edit layout**, then drag a widget by its grip, resize it from any edge, press a free space to add a widget, or remove one.

## Usage

```tsx
import {
  WidgetGrid,
  WidgetGridContent,
  WidgetGridHandle,
  WidgetGridItem,
  WidgetGridRemove,
  WidgetGridResizeHandle,
} from "@tecton/react/tecton/widget-grid"
```

```tsx
const [layout, setLayout] = React.useState([
  { id: "production", x: 0, y: 0, w: 8, h: 2 },
  { id: "pressure", x: 8, y: 0, w: 4, h: 2 },
])

<WidgetGrid value={layout} onValueChange={setLayout} editable={editing}>
  <WidgetGridContent>
    {layout.map(({ id }) => (
      <WidgetGridItem key={id} value={id} label={names[id]} render={<Panel />}>
        <PanelHeader>
          <WidgetGridHandle />
          <PanelTitle>{names[id]}</PanelTitle>
          <PanelActions>
            <WidgetGridRemove />
          </PanelActions>
        </PanelHeader>
        <PanelContent>…</PanelContent>
        <WidgetGridResizeHandle />
      </WidgetGridItem>
    ))}
  </WidgetGridContent>
</WidgetGrid>
```

## Composition

```text
WidgetGrid                      (the layout; holds your toolbar and catalog)
└── WidgetGridContent           (the CSS grid)
    ├── WidgetGridItem          (render={<Panel />})
    │   ├── WidgetGridHandle
    │   ├── WidgetGridRemove
    │   └── WidgetGridResizeHandle
    ├── WidgetGridSlots         (free spaces, to add widgets)
    └── WidgetGridPlaceholder   (optional: where a new widget lands)
```

Render each item as a [Panel](/docs/tecton/panel): the grip goes first in `PanelHeader`, the remove button in `PanelActions`, and the resize handle anywhere inside.

## The layout

`value` holds one entry per widget. It is plain data, made to be saved:

```ts
type WidgetGridLayoutItem = {
  id: string
  type?: string // the kind of widget, when several entries share one
  x: number // column, from the inline start (0-based)
  y: number // row (0-based)
  w: number // columns wide
  h: number // rows tall
  minW?: number
  maxW?: number
  minH?: number
  maxH?: number
  locked?: boolean // never moved, resized, pushed or removed
}
```

`onValueChange` hands back the whole new layout after each user change, never mid-drag or on mount. `eventDetails.reason` is `"move"`, `"resize"`, `"add"` or `"remove"`, `eventDetails.item` is the widget's `id`, and `eventDetails.cancel()` refuses the change. Refuse with `cancel()` rather than by not applying the change; either way, nothing is announced.

- **Order:** the layout comes back in reading order. Render it in that order and Tab follows what the user sees.
- **Repairs:** a saved layout that overlaps, overflows the columns or breaks a size limit is corrected as it shows. The next change hands back the corrected layout.

## Layout and placement

`columns` (default 12), `rowHeight` (px, default 64) and `gap` (default 4) size the grid, and all three can change at any time. `gap` takes a step of the spacing scale, as `gap-*` does: `0`, `1`, `1.5`, `2`, `3`, `4`, `5`, `6` or `8`. The layout counts cells, so changing `columns` doesn't rescale it. Double `x`, `w` and `minW` to keep its shape at twice the columns, as the demo does.

```tsx
<WidgetGrid value={layout} onValueChange={setLayout} columns={24} rowHeight={48} gap={2}>
```

With `compaction="vertical"` (the default), widgets float up, so the grid never has holes.

- **Dropping:** a dropped widget takes the place it's dropped on.
- **Swapping:** widgets it lands on that fit its old place swap into it.
- **Pushing:** anything else moves down below it.

With `compaction="none"`, widgets stay where they're put. Add `rows` to give the grid empty rows to place them in, like a board:

```tsx
<WidgetGrid value={layout} onValueChange={setLayout} compaction="none" rows={14}>
```

## Edit mode

Out of edit mode (`editable={false}`) there are no handles, and widgets are used like the rest of the page. In edit mode, the grid's cells show under the widgets.

Use an **Edit layout** button rather than leaving the grid always editable, so widgets aren't dragged by accident. Treat the edit as a draft: keep the layout it started from, so **Cancel** restores it.

```tsx
const draft = React.useRef(layout)

<Button onClick={() => { draft.current = layout; setEditing(true) }}>Edit layout</Button>
<Button onClick={() => { setLayout(draft.current); setEditing(false) }}>Cancel</Button>
```

## Moving and resizing

- **Moving:** only the grip moves a widget, so its content keeps working in edit mode. While dragging, a dashed placeholder shows where it will land and the others make way. Escape cancels, and the grid scrolls near its edges.
- **Resizing:** drag any side or corner. The widget snaps to whole cells within its limits, shows its size, and the opposite side stays put. Limit the sides with `edges`:

```tsx
<WidgetGridResizeHandle edges={["bottom", "end"]} />
```

Make `PanelContent` a size container (`@container`) to show more as a widget grows.

## Adding widgets

Every way of adding places the widget, focuses its grip and announces it.

### Free spaces

`WidgetGridSlots` shows the grid's free spaces in edit mode: the holes beside shorter widgets, and the area below all widgets (`slot.end`). Pass a function to offer what fits each space:

- `slot.add(widget)` adds it there, sized to fill the space within its limits. Below all widgets it keeps its own size.
- `slot.sizeFor(widget)` is the size it would get, to show before the user picks.
- `slot.fits({ w, h })` says whether a size fits without moving anything.

```tsx
<WidgetGridSlots minW={3} minH={2}>
  {(slot) => (
    <Popover>
      <PopoverTrigger render={<WidgetGridSlot />}>Add widget</PopoverTrigger>
      <PopoverContent>
        {catalog.map((widget) => (
          <Button key={widget.id} onClick={() => slot.add(widget)}>{widget.name}</Button>
        ))}
      </PopoverContent>
    </Popover>
  )}
</WidgetGridSlots>
```

The demo's picker is a searchable [Command](/docs/components/command) list: the search field takes focus, the arrow keys move, Enter adds, and Escape returns to the space. See its source above.

### Sources

<ComponentPreview name="widget-grid-custom-source" />

`useWidgetGridSource` turns any element into a source: press it to add the widget at the first free place, or drag it onto the grid. Pass your own props through `getSourceProps` to keep their handlers and refs:

```tsx
const source = useWidgetGridSource({ value: "uptime", label: "Uptime", w: 4, h: 2 })

<Item {...source.getSourceProps({ className: "cursor-grab" })}>Uptime</Item>
```

`WidgetGridSource` is the same as a ready-made `button`. To style the drop preview, render a `WidgetGridPlaceholder` in `WidgetGridContent`. It can show the incoming widget:

```tsx
<WidgetGridPlaceholder>{({ label, w, h }) => `${label} · ${w}×${h}`}</WidgetGridPlaceholder>
```

### More than once

By default a widget is added once: its `id` is the source's `value`, and the source turns off while it's on the grid. Set `multiple` for widgets that belong more than once, such as one per well. Each add then gets its own `id` (`pressure-2`) and `type: "pressure"`, so render each entry from `type ?? id`.

```tsx
<WidgetGridSource value="pressure" label="Wellhead pressure" w={4} h={3} multiple />
```

### From your own controls

`useWidgetGrid()` adds and removes widgets from anywhere inside `WidgetGrid`. `add` takes an `id`, or just a `type` to generate one, and returns the new `id`:

```tsx
const grid = useWidgetGrid()
grid.add({ type: "pressure", w: 4, h: 3 }) // "pressure-2"
```

When the layout is empty outside edit mode, render an [Empty](/docs/components/empty) spanning the grid (`col-span-full row-span-4 row-start-1`).

## Removing widgets

`WidgetGridRemove` removes its widget at once. The others close the gap, focus moves to the next widget's grip, and the removal is announced.

## Without dragging

Every drag has a single-press alternative, as WCAG 2.5.7 requires. Inside a `WidgetGridItem`, `useWidgetGridItem()` gives a widget menu its actions:
- `move("up" | "down" | "left" | "right")` and `canMove(direction)`;
- `resize({ w, h })` for size presets;
- `remove()`.

They act only in edit mode and never on a locked widget (`widget.editable`), and each change is announced once the layout shows it.

```tsx
const widget = useWidgetGridItem()

<DropdownMenuItem onClick={() => widget.resize({ w: 12, h: 4 })}>Large</DropdownMenuItem>
<DropdownMenuItem disabled={!widget.canMove("up")} onClick={() => widget.move("up")}>Move up</DropdownMenuItem>
```

## Keyboard and screen readers

- **Moving and resizing:** focus a grip and press Enter or Space to pick the widget up. The arrow keys move it a cell, Shift with the arrow keys resizes it, and each place is announced ("Production, column 4, row 1, 6 by 4"). Enter drops it and Escape cancels.
- **Touch screen readers:** activating the grip turns the possible places into buttons; double tap one to drop.
- **Adding and removing:** adding focuses the new widget's grip. Removing focuses the next widget's grip, or the grid when it was the last.

## Live data and performance

<ComponentPreview name="widget-grid-live" />

The grid never re-renders for live data, and a drag re-renders only the widgets that move. Keep it that way with two rules:

- **Each widget subscribes to its own data**, for example with `useSyncExternalStore` or your data library's hook inside the widget, not through the component that holds the layout.
- **Memoize the widgets:** render each one as a `React.memo` component that takes its `id`.

## Narrow screens

Below `stackBelow` px (default 640; `0` never), widgets stack in one column in reading order. Stacked widgets can still be resized in height, removed and added, but not moved, since a one-column order doesn't map back onto the full layout.

## Right to left

<ComponentPreview name="widget-grid-basic" direction="rtl" />

`x` counts from the inline start, so the same layout mirrors with nothing to convert. Resize corners, the pointer, the arrow keys and a menu's `"left"` and `"right"` all follow what the user sees.

## Animation

Widgets glide into their new places, new ones grow in and removed ones fade out. Nothing moves with reduced motion, and `animated={false}` turns it off.

## Usage guidelines

### Use it when

- The user arranges their own dashboard: moves widgets, resizes them by whole cells, adds them from a catalog and removes them.
- The layout is saved per user and restored later, as plain data (`{ id, x, y, w, h }` per widget).
- Widgets of several sizes share a grid of columns and rows and must never overlap or leave holes.

### Not for

- cards in a layout the user never changes: use [Card](/docs/components/card)
- bento tiles that trade fixed slots, or cards of one size put in order: use [Reorderable](/docs/tecton/reorderable)
- two or three panes the user drags apart: use [ResizablePanelGroup](/docs/components/resizable)

### Do

<DoList>

<Do>

Keep the layout in state, pass it as `value` and write `onValueChange`'s layout back; render each widget in the layout's order as a `React.memo` component taking its `id`, which subscribes to its own live data rather than receiving it from the dashboard.

</Do>

<Do>

Render each `WidgetGridItem` with `render={<Panel />}`, a `label`, the `WidgetGridHandle` first in its `PanelHeader`, `WidgetGridRemove` in `PanelActions` and a `WidgetGridResizeHandle` inside it.

</Do>

<Do>

Offer what fits each free space with `WidgetGridSlots` inside `WidgetGridContent` (`slot.fits`, `slot.add`); put a catalog inside `WidgetGrid`, as `WidgetGridSource`s or your own elements with `useWidgetGridSource().getSourceProps()`, each with the new widget's `value`, `label`, `w` and `h`, and `multiple` for a widget added once per well or pad (its entries share a `type`).

</Do>

<Do>

Turn the edit mode on with `editable` from an **Edit layout** button, and keep the layout the edit started from so **Cancel** restores it.

</Do>

<Do>

Give every widget a menu built on `useWidgetGridItem()` (`move`, `canMove`, `resize` with named size presets, `remove`) to arrange without dragging; set its limits in its entry (`minW`, `minH`), and render an `Empty` spanning the grid (`col-span-full row-span-4 row-start-1`) when the layout is empty.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="Positioning widgets by hand or with a drag library">

<Wrong>

```tsx
<div className="relative">
  {layout.map((item) => <div key={item.id} draggable style={{ position: "absolute", left: item.x * 100 }}><Panel>…</Panel></div>)}
</div>
```

</Wrong>

<Correct>

```tsx
<WidgetGridContent>
  {layout.map((item) => (
    <WidgetGridItem key={item.id} value={item.id} label={names[item.id]} render={<Panel />}>
      <PanelHeader><WidgetGridHandle /><PanelTitle>{names[item.id]}</PanelTitle></PanelHeader>
      <WidgetGridResizeHandle />
    </WidgetGridItem>
  ))}
</WidgetGridContent>
```

</Correct>

Absolute pixel positions do not mirror in a right-to-left page or follow the width of the grid, and native drag events never fire from the keyboard, a screen reader or a touch screen; `WidgetGrid` places the widgets on CSS grid cells and resolves every overlap.

</Dont>

<Dont severity="HIGH" title="Layout props from other grid libraries">

<Wrong>

```tsx
<WidgetGrid layout={layout} onLayoutChange={setLayout} cols={12}>
  <WidgetGridItem key="a" data-grid={{ i: "a", x: 0, y: 0, w: 4, h: 2 }} />
</WidgetGrid>
```

</Wrong>

<Correct>

```tsx
<WidgetGrid value={[{ id: "a", x: 0, y: 0, w: 4, h: 2 }]} onValueChange={setLayout} columns={12}>
  <WidgetGridContent>
    <WidgetGridItem value="a" label="Production" />
  </WidgetGridContent>
</WidgetGrid>
```

</Correct>

The layout is `value` with an `id` per entry, the change arrives in `onValueChange` and the column count is `columns`; `layout`, `onLayoutChange`, `cols`, `i` and `data-grid` are ignored, so nothing is placed.

</Dont>

<Dont severity="HIGH" title="Widgets outside WidgetGridContent">

<Wrong>

```tsx
<WidgetGrid value={layout} onValueChange={setLayout} className="grid grid-cols-12">
  {layout.map((item) => <WidgetGridItem key={item.id} value={item.id} label={names[item.id]} />)}
</WidgetGrid>
```

</Wrong>

<Correct>

```tsx
<WidgetGrid value={layout} onValueChange={setLayout} columns={12} gap={4}>
  <WidgetGridContent>
    {layout.map((item) => <WidgetGridItem key={item.id} value={item.id} label={names[item.id]} />)}
  </WidgetGridContent>
</WidgetGrid>
```

</Correct>

`WidgetGrid` holds the layout and the catalog around the grid; only `WidgetGridContent` lays out the `columns`, `rowHeight` and `gap` set on `WidgetGrid`, measures the grid for a drag and draws the cells and the placeholder.

</Dont>

## API Reference

### WidgetGrid

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `WidgetGridLayoutItem[]` | - | The layout (controlled). |
| `defaultValue` | `WidgetGridLayoutItem[]` | `[]` | The initial layout, when not controlled. |
| `onValueChange` | `(value, eventDetails) => void` | - | The new layout after each change. `eventDetails.reason`: `"move"`, `"resize"`, `"add"` or `"remove"`; `eventDetails.item`: the widget's `id`. |
| `columns` | `number` | `12` | The number of columns. |
| `rowHeight` | `number` | `64` | The height of a row, in px. |
| `rows` | `number` | - | The grid's minimum height, in rows. |
| `gap` | `0 \| 1 \| 1.5 \| 2 \| 3 \| 4 \| 5 \| 6 \| 8` | `4` | The gap, as a step of the spacing scale. |
| `compaction` | `"vertical" \| "none"` | `"vertical"` | Whether widgets float up. |
| `editable` | `boolean` | `true` | Edit mode. |
| `stackBelow` | `number` | `640` | The width, in px, below which widgets stack. `0` never stacks. |
| `animated` | `boolean` | `true` | Animates layout changes. |

Carries `data-editable` and `data-stacked`.

### WidgetGridContent

The CSS grid. Carries `data-editable`, `data-stacked`, and `data-active` while a widget is dragged or resized.

### WidgetGridItem

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | - | The widget's `id`. |
| `label` | `string` | - | The widget's name, for its controls and announcements. |
| `render` | `ReactElement \| function` | `<div />` | Replaces the element, usually with `<Panel />`. |

Carries `data-dragging` (`"pointer"`, `"keyboard"` or `"virtual"`), `data-resizing` and `data-locked`.

### WidgetGridHandle, WidgetGridRemove

Ghost icon buttons named `Drag {label}` and `Remove {label}`. Shown only in edit mode, and never on a locked widget.

### WidgetGridResizeHandle

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `edges` | `("top" \| "end" \| "bottom" \| "start")[]` | all four | The sides it resizes from. Stacked, only the bottom. |

### WidgetGridSource and useWidgetGridSource

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | - | The new widget's `id`, or its `type` when `multiple`. |
| `label` | `string` | - | The widget's name. |
| `w`, `h` | `number` | - | Its size, in cells. |
| `minW`, `maxW`, `minH`, `maxH` | `number` | - | Its size limits. |
| `multiple` | `boolean` | `false` | Each add is a new instance. |
| `disabled` | `boolean` | `false` | Turns the source off. |

The hook takes the same options and returns `getSourceProps(props?)`, `onGrid`, `count`, `disabled` and `dragging`.

### WidgetGridPlaceholder

The drop preview of a new widget. `children` can be a function of `{ id, label, w, h }`.

### WidgetGridSlots, WidgetGridSlot and useWidgetGridSlot

`WidgetGridSlots` takes `children` (nodes, or a function of the slot) and `minW` / `minH` to hide small spaces. A slot is `{ x, y, w, h, end, fits, sizeFor, add }`. `WidgetGridSlot` is its default dashed button. `useWidgetGridSlot()` reads the slot from inside it.

### useWidgetGrid

Returns `add(widget, { at?, label? })`, `remove(id)`, `count(type)`, `layout`, `columns`, `editable` and `movable`.

### useWidgetGridItem

Returns `{ value, label, layout, editable, move, canMove, resize, remove }`.
