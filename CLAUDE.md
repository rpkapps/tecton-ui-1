# Working in this repository

- **Never hand-edit** `packages/tecton-react/src/components/**`, `src/hooks/**`, `src/lib/**` or the structure of `src/styles/globals.css`. They are generated by the shadcn CLI from the `aria-tecton` style (`docs/UPSTREAM.md` has the pinned commit and commands). Update them with `shadcn add <item> --overwrite` and verify with `pnpm generated:check`.
- **The Tecton look of the generated components lives in the registry overlay** `scripts/registry-mirror/overlay/` (`style-tecton.css` = Tailwind class lists per component, `tecton.patch` = the extra variant axes on `alert`, `badge`, `separator`, `input`, `textarea`, `select`, and the Tecton tab colours on `tabs`, the ghost hover colours on `toggle`, logical corners on `button-group` and the outlined status colours on `sonner`). Change it there, then `scripts/registry-mirror.sh build`, re-add the affected items with `--overwrite` and run `pnpm generated:check`. Never restyle a generated component with `.style-*`, `[data-slot]` or `@layer` overrides.
- **Theme changes go through `packages/tecton-react/tokens/tecton.map.json`** (or `src/styles/tecton-tokens.css` for raw values), then `pnpm tokens:build && pnpm tokens:check`. Only the values of the shadcn CSS variables in `globals.css` may change.
- **The Tailwind palette is Tecton's**: `tokens/tecton.tokens.json` (Figma variables export, replace whole) → `src/styles/tecton-palette.css` (generated, `--color-<family>-<step>` after `--color-*: initial`). Never use stock Tailwind colour classes (`bg-red-500`, `text-zinc-400`): they produce no CSS. Use a semantic token, or a Tecton step (`bg-blue-120 text-blue-830`; steps are contrast levels, no `dark:` pair). Synced examples that use stock colours are rewritten in `sync-upstream-docs.mts` (`TECTON_PALETTE_REWRITES`).
- **The `aria-tecton` style exists only in the mirror**: every shadcn CLI command that touches `packages/tecton-react` needs `REGISTRY_URL=http://127.0.0.1:4000/r` with `scripts/registry-mirror.sh serve` running (`setup` once).
- Tecton-specific behaviour that is not a variant of a shadcn component belongs in `packages/tecton-react/src/tecton/` (shadcn conventions: `data-slot`, `cva`, `cn` from "cn", React Aria primitives, `onPress` not `onClick`). Do not add a Tecton component that duplicates a shadcn one; add the variant to the overlay instead.
- **The docs are split by audience.** `apps/www/content/docs/**` is written for people building applications with `@tecton/react` and must never name shadcn, React Aria or Radix, the registry mirror or the generated-file pipeline; how the library is produced belongs in `apps/www/content/docs/contributing/`. The sync enforces this for generated pages (`assertNoBaseLeak` throws), so a new leak is handled with a rule in `MDX_DELEAK` / `SAMPLE_REWRITES`, never by editing the output. `bun run apps/www/scripts/deleak-synced.mts [--check]` re-applies those rules to the already-synced files without an upstream checkout.
- Docs pages under `apps/www/content/docs/components/` and `content/docs/utils/`, and examples starting with `// Synced from shadcn/ui`, are generated by `pnpm docs:sync`; edit `apps/www/scripts/sync-upstream-docs.mts` instead. Tecton sections of a synced page go in `apps/www/scripts/docs-extras/<name>.mdx`.
- Docs-site CSS (`apps/www/src/styles/app.css`) must stay inside `@layer base` / `@layer components` / `@utility`, and prose rules go through the `typeset` system only. Never add unlayered or bare-element rules: they would override the example components, which must render exactly as in an application (`data-not-typeset` opts a subtree out of prose styling).
- Icons under `src/icons/` are generated by `icons:build` from the vendored Tecton export in `icons-src/tecton/*.ts` (never edit either by hand; replace the export); the manifest is `icons/icons.json`.
- **Only blocks are published to the `@tecton` registry**; components ship in `@tecton/react` and are imported from it. `registry:build` throws if a non-block item reaches `registry.json`. The consumer-facing guardrails live in `packages/eslint-config-tecton` (`@tecton/eslint-config`, wrapping `@shadcn/lint` but reporting under a `tecton/` prefix so applications never see the underlying plugin): `className` overriding what a Tecton variant owns, runtime-built class names, and imports from `components/ui/` (Tecton components only; `configs.strict` adds the project-wide colour/arbitrary-value checks). Verify with `pnpm --filter @tecton/eslint-config test`; document changes in `apps/www/content/docs/linting.mdx`.
- Package manager: pnpm (workspace). Scripts run with bun (`/root/.bun/bin/bun` if not on PATH).
