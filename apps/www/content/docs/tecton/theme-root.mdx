## Usage

```tsx
import { ThemeRoot } from "@tecton/react/tecton/theme-root"
```

```tsx
<ThemeRoot className="mfe-a" theme="inherit">
  <App />
</ThemeRoot>
```

## When to use it

An application that owns the document imports `@tecton/react/globals.css` and needs nothing here: the theme variables live on `:root` and every overlay can portal into `document.body`.

`ThemeRoot` is for the other case — a Module Federation remote, an embedded widget, any application mounted into a page that already has its own copy of Tecton. It marks that application's subtree with `data-tecton-root`, which is what `@tecton/react/styles/scoped.css` hangs its base-layer reset and its `@scope`-anchored rules on, and it owns the container the application's overlays portal into.

It does not bring theme variables with it. `scoped.css` declares none: the shell's `--primary`, palette, radii and current mode inherit into the subtree, so a remote follows the shell it is mounted in. A remote that runs without a shell, or deliberately on a different token set, imports `@tecton/react/styles/scoped-theme.css` after `scoped.css` and gets the full variable set on this element instead. See [Micro-frontends](/docs/micro-frontends) for the stylesheet and the build step that go with it.

## What it renders

```html
<div data-slot="theme-root" data-tecton-root class="dark mfe-a">…</div>
```

and, appended to `document.body`, one container with the same classes:

```html
<div data-slot="theme-root-overlay" data-tecton-root class="dark mfe-a"></div>
```

The container is handed to [`PortalProvider`](/docs/tecton/portal), so every Tecton overlay in the subtree — `Dialog`, `Sheet`, `AlertDialog`, `Popover`, `HoverCard`, `Tooltip`, `Select`, `Combobox`, `DropdownMenu`, `ContextMenu`, `Drawer` — renders inside it. That keeps the overlays out of any `overflow: hidden` ancestor while they stay inside the application's `@scope` rule, so the utilities that style them still apply.

Both elements carry `data-tecton-root`, which is the selector the scoped stylesheet uses, and the container mirrors the root's `className`: the scope class, a pinned theme and inline `[--token:…]` overrides all reach the overlays. The demo above is exactly that — an inline `[--primary:…]` on the root beats the value inherited from the shell, for the subtree and for the dialog alike, and it is how a remote overrides a single token for itself.

## Theme

`theme` puts the mode class on both elements:

| Value | Effect |
| --- | --- |
| `inherit` (default) | No class: the subtree follows the shell's `dark` class (or `data-theme`), which is what a remote mounted in a Tecton shell wants. |
| `dark` | Pins the subtree to dark. That switches the `dark:` utility variants inside it and, for a remote that imports `scoped-theme.css`, its variable blocks — a dark island in a light shell. |
| `light` | Pins it to light. Only meaningful with `scoped-theme.css`, and the weaker of the two: it flips that sheet's variables, while `dark:` variants written against an ancestor's `dark` class still apply. Prefer `inherit` or `dark` inside a dark shell. |

## Overlay container

Pass `overlayContainer` to take over the placement:

- **omitted** — `ThemeRoot` creates, styles and removes its own container.
- **an element** — used as is. It is neither restyled nor removed on unmount; give it `data-tecton-root` and the scope class yourself.
- **`null`** — no container. Overlays pass none and React Aria falls back to `document.body`.

```tsx
<ThemeRoot className="mfe-a" overlayContainer={shell.overlayLayer}>
  <App />
</ThemeRoot>
```

## Notes

- The container is created in an effect, so the **first paint has no container**: `usePortalTarget()` returns `undefined` and React Aria resolves its own default. Everything opened by an interaction — every overlay in practice — sees the container. Rendering is SSR-safe; nothing touches `document` during render.
- Each `ThemeRoot` owns exactly one container, and two roots on a page get one each.
- Variables can be overridden per root with an arbitrary property in `className`: `className="mfe-a [--primary:var(--tecton-palette-green-560)]"` retints that application, overlays included.
- `ThemeRoot` renders a plain `div`. It sets no layout of its own — give it the classes the mount point needs.

## API Reference

### ThemeRoot

A `div` element; every `div` prop is forwarded.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `theme` | `"dark" \| "light" \| "inherit"` | "inherit" | Mode class on the root and the overlay container. |
| `overlayContainer` | `HTMLElement \| null` | created | Element the overlays portal into. An element is used as is; `null` disables the container. |
| `className` | `string` | - | Scope class, theme overrides and layout; mirrored onto the overlay container. |
| `children` | `ReactNode` | - | The application. |

### themeRootVariants

The `cva` function behind the `theme` prop, for composing the same class on another element (a supplied overlay container, for example).
