Tecton UI supports **two icon libraries**:

- **Lucide** (`lucide-react`) — the library the generated shadcn components use internally (chevrons, check marks, close buttons…). It stays the CLI's `iconLibrary`, so generated files never change.
- **Tecton icons** (`@tecton/react/icons`) — the 18 domain glyphs of the design system (wells, horizons, seismic, drill bits…), the ones Lucide has no answer for. Every icon is a React component with the Lucide-compatible signature (`size`, `strokeWidth`, `className`, SVG props) plus `variant="outlined" | "filled"`.

```tsx
import { SearchIcon } from "lucide-react"
import { WellIcon, SeismicIcon } from "@tecton/react/icons"

<Button>
  <WellIcon data-icon="inline-start" /> New well
</Button>
<SeismicIcon variant="filled" size={20} />
```

<Callout title="Glyph sources">
  The glyphs come from the Tecton icon export vendored in `packages/tecton-react/icons-src/tecton/` (one `defineTectonSvgIcon` definition per icon with outlined and filled markup). The Tecton set's general-purpose glyphs (add, chevron, search…) are not vendored at all, because Lucide already provides them. `icons:build` generates a React component for every manifest entry marked `domain: true`, and every rendered `<svg>` reports its origin through `data-tecton-source` (`svg` for all 18 today). Drop a newer export into that folder and rebuild to update the set.
</Callout>

## Optical sizing

The Tecton export draws every glyph on a 16-unit grid with the glyph's own margin
baked in, so an unmodified Tecton icon looks noticeably smaller than a Lucide icon
rendered at the same width and height. `icons:build` corrects that: it measures the
real bounding box of both variants and crops the generated `viewBox` by up to one
unit on each side — `0 0 16 16` becomes `1 1 14 14`, about 1.14&times; larger — which
puts a Tecton glyph level with its Lucide counterpart at the same size.

The crop is clamped per icon by how much margin that glyph actually has, so nothing
is ever clipped: glyphs that already reach the edge of the box, such as
`AddPinIcon`, keep their original `viewBox`, and both variants of an icon always
share one crop so toggling `variant` never shifts or rescales the glyph. The path
data is never touched, and each generated file records what happened in its header
comment.

## Regenerating

```bash
# replace icons-src/tecton/*.ts with a newer Tecton export, then
pnpm --filter @tecton/react icons:build     # regenerates src/icons/*
pnpm --filter @tecton/react icons:build -- --check   # CI drift guard
```

Loose SVG files in `icons-src/outlined/` or `icons-src/filled/` override a definition for that variant (`icons:extract` can populate them from a Storybook).
