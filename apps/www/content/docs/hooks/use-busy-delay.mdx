## Usage

```tsx
import { useBusyDelay } from "@tecton/react/tecton/use-busy-delay"
```

```tsx
function SaveButton() {
  const [pending, startTransition] = React.useTransition()
  const busy = useBusyDelay(pending)

  return (
    <Button
      disabled={pending || busy}
      focusableWhenDisabled
      onClick={() => startTransition(save)}
    >
      {busy && <Spinner data-icon="inline-start" />}
      Save
    </Button>
  )
}
```

Drive the spinner, skeleton or busy label from the returned value. Disable the control while either flag is set: `pending` locks it from the first click, before the busy state shows, and `busy` keeps it locked while the spinner holds after the work is done. `focusableWhenDisabled` keeps keyboard focus on the button meanwhile.

## How it behaves

- Work that finishes within `delay` never shows a busy state at all, so a fast response does not blink a spinner.
- Once the busy state shows, it stays for at least `minDuration`, even when the work finishes right after, so it never appears for a single frame.
- If `isPending` turns back on while the busy state is still holding, it simply stays on; the minimum is measured from when it first showed.
- Every change of `isPending`, `delay` or `minDuration` cancels the previous timer before scheduling a new one, and unmounting cancels it too, so a timer left over from an earlier value can never change the result.

In the demo, the fast request never shows a spinner, the medium one shows it for the minimum 300 ms, past the end of the work, and the slow one shows it until the work ends.

## Options

```tsx
const busy = useBusyDelay(isPending, { delay: 400, minDuration: 600 })
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `delay` | `number` | `200` | How long `isPending` must stay `true`, in milliseconds, before the hook returns `true`. |
| `minDuration` | `number` | `300` | How long, in milliseconds, the hook keeps returning `true` once it has. |

The hook returns a `boolean`. The options type is exported as `UseBusyDelayOptions`.

## Usage guidelines

### Use it when

- A spinner, skeleton or busy label is driven by a pending flag: a transition, a mutation, a fetch.
- Most requests finish quickly and a spinner that appears for a frame would read as a glitch.
- The flag can toggle quickly (retries, refetches) and the busy state must not flicker.

### Not for

- the spinner itself: use [Spinner](/docs/components/spinner)
- a placeholder in the shape of the content that is loading: use [Skeleton](/docs/components/skeleton)
- progress through a task whose length is known: use [Progress](/docs/components/progress)

### Do

<DoList>

<Do>

Pass the raw flag (`const busy = useBusyDelay(pending)`) and draw the busy indicator (spinner, skeleton, busy label) from the result.

</Do>

<Do>

Disable the control while either flag is set, `disabled={pending || busy}` with `focusableWhenDisabled`: `pending` locks it from the first click, `busy` keeps it locked while the spinner holds.

</Do>

<Do>

Tune the timing with `delay` (200 ms by default) and `minDuration` (300 ms by default) instead of wrapping the hook in your own timers.

</Do>

<Do>

Call it once per independent pending source; each call owns its own timer and cancels it on unmount.

</Do>

</DoList>

### Don't

<Dont severity="HIGH" title="Hand-rolled timeouts around a pending flag">

<Wrong>

```tsx
const [showSpinner, setShowSpinner] = React.useState(false)
React.useEffect(() => {
  if (pending) setTimeout(() => setShowSpinner(true), 200)
  else setShowSpinner(false)
}, [pending])
```

</Wrong>

<Correct>

```tsx
const showSpinner = useBusyDelay(pending)
```

</Correct>

The hand-rolled effect never clears its timer, so a request that ends within 200 ms still turns the spinner on afterwards and leaves it on, and nothing holds the spinner for a minimum time.

</Dont>

<Dont severity="MEDIUM" title="Disabling the control from the delayed flag alone">

<Wrong>

```tsx
const busy = useBusyDelay(pending)
<Button disabled={busy} onClick={save}>{busy && <Spinner data-icon="inline-start" />}Save</Button>
```

</Wrong>

<Correct>

```tsx
const busy = useBusyDelay(pending)
<Button disabled={pending || busy} focusableWhenDisabled onClick={save}>{busy && <Spinner data-icon="inline-start" />}Save</Button>
```

</Correct>

The delayed flag is still `false` for the first 200 ms of the request, so the button stays clickable and a second click submits twice.

</Dont>
