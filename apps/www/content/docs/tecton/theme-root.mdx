## Usage

```tsx
import { ThemeRoot } from "@tecton/react/tecton/theme-root"
```

```tsx
<ThemeRoot className="mfe-a">
  <App />
</ThemeRoot>
```

An application that owns the document needs only [Tecton Provider](/docs/tecton/provider). `ThemeRoot` is for an application mounted into a page that already runs Tecton, such as a Module Federation remote or an embedded widget; [Micro-frontends](/docs/micro-frontends) covers the scoped stylesheet and build step that go with it.

It renders a `div` marked `data-tecton-root`, which the scoped stylesheet keys on, and a `TectonProvider` for the application. It also appends one overlay container to `document.body` with the same classes and `dir`, so the application's dialogs, popovers, menus and tooltips escape any `overflow: hidden` ancestor yet stay inside its scope and theme. It declares no theme variables: the shell's tokens and mode inherit into the subtree, and a class such as `[--primary:var(--tecton-palette-green-560)]` retints the application and its overlays, as in the demo. The root has no layout of its own; give it the classes the mount point needs.

## Theme

`theme="inherit"` (the default) follows the shell's mode. `"dark"` or `"light"` pins the subtree and its overlays to one mode, for a dark island such as a map in a light shell; see [Inverted sections](/docs/theming#inverted-sections).

## Direction and locale

`dir` and `locale` set the reading direction and language of an application that differs from its shell, with the same rules as `TectonProvider`. Without them the root inherits the page's direction.

```tsx
<ThemeRoot className="mfe-a" dir="rtl" locale="ar-EG">
  <App />
</ThemeRoot>
```

## Overlay container

The container mirrors the root's `className`; pass `overlayClassName` when only some classes should reach the overlays. Pass `overlayContainer` to use an element the shell owns (it is used as is: give it `data-tecton-root`, the scope class and `dir` yourself), or `null` to portal into `document.body`.

```tsx
<ThemeRoot
  className="mfe-a flex h-full [--primary:var(--tecton-palette-green-560)]"
  overlayClassName="mfe-a [--primary:var(--tecton-palette-green-560)]"
>
  <App />
</ThemeRoot>
```

The container is created after mount, so an overlay rendered open on the very first paint portals into `document.body`.

## Usage guidelines

### Use it when

- An application is mounted into a page that already carries its own copy of Tecton: a Module Federation remote, an embedded widget.
- A subtree must be pinned against the shell's mode — a dark map or log viewer in a light application.
- That subtree's overlays have to stay inside its own `@scope` rule instead of landing in a bare `document.body`.

### Not for

- the locale, direction or router of an application that owns the document: use [TectonProvider](/docs/tecton/provider)
- the header, rail and work area of an application that owns the document: use [AppShell](/docs/tecton/app-shell)

### Do

<DoList>

<Do>

Render it around the whole mounted tree with the deployable's scope class, and keep layout on an inner element: `<ThemeRoot className="mfe-a"><div className="flex h-full flex-col">…</div></ThemeRoot>`. The overlay container that mirrors `className` is `display: contents`, so layout utilities do nothing there while typography and colour classes reach every overlay.

</Do>

<Do>

Keep `theme="inherit"` inside a Tecton shell — the shell's variables, palette and mode inherit — and pin `dark` or `light` only for an inverted island.

</Do>

<Do>

Retint one root with an arbitrary property in `className`: `[--primary:var(--tecton-palette-green-560)]`, which is mirrored onto the overlay container; pass `overlayClassName` instead when only some of the root's classes belong on the overlays (the theme class is always added to it).

</Do>

<Do>

Pass `dir` and `locale` when the remote reads differently from its shell: `dir` lands on the root and on the overlay container, and both feed the `TectonProvider` it renders.

</Do>

<Do>

Pass `overlayContainer` to reuse an element the shell owns, or `null` to opt out; omit it and the root creates, syncs and removes its own.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="globals.css imported inside a mounted remote">

<Wrong>

```tsx
import "@tecton/react/globals.css"

createRoot(element).render(<App />)
```

</Wrong>

<Correct>

```tsx
import { ThemeRoot } from "@tecton/react/tecton/theme-root"

import "./styles/remote.css"

createRoot(element, { identifierPrefix: "mfe-a" }).render(
  <ThemeRoot className="mfe-a" theme="inherit">
    <App />
  </ThemeRoot>
)
```

</Correct>

`globals.css` carries preflight, the fonts and the whole variable set on `:root`, so a remote that imports it resets the document the shell owns and repaints the shell with the remote's version of the theme — a remote's sheet is `scoped.css`, scoped to the `data-tecton-root` marker `ThemeRoot` renders.

</Dont>

<Dont severity="HIGH" title="A theme applied as inline CSS variables">

<Wrong>

```tsx
<div style={{ "--primary": "#2f7d32" } as React.CSSProperties}>
  <App />
</div>
```

</Wrong>

<Correct>

```tsx
<ThemeRoot className="mfe-a [--primary:var(--tecton-palette-green-560)]">
  <App />
</ThemeRoot>
```

</Correct>

Inline variables reach only the elements under that `div`, and every `Dialog`, `Select`, `Tooltip` and `DropdownMenu` portals out of it, so the overlays keep the shell's colours; `ThemeRoot` copies its `className` onto the body-level container it owns, which is what carries an override across the portal.

</Dont>

<Dont severity="MEDIUM" title="The dark class toggled on a plain root element">

<Wrong>

```tsx
<div className={mode === "dark" ? "mfe-a dark" : "mfe-a"}>
  <App />
</div>
```

</Wrong>

<Correct>

```tsx
<ThemeRoot className="mfe-a" theme={mode === "dark" ? "dark" : "light"}>
  <App />
</ThemeRoot>
```

</Correct>

The mode class has to sit on the overlay container as well, or the subtree's portalled overlays render in the shell's mode; `themeRootVariants` and the sync effect are what put it on both and swap it when `mode` flips.

</Dont>

{/* guidelines:end */}

## API Reference

### ThemeRoot

A `div`; other `div` props are forwarded.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `theme` | `"dark" \| "light" \| "inherit"` | `"inherit"` | Mode class on the root and the overlay container. |
| `className` | `string` | - | Scope class, token overrides and layout; mirrored onto the overlay container. |
| `overlayClassName` | `string` | - | Classes for the created container instead of `className` (the theme class is always added). |
| `overlayContainer` | `HTMLElement \| null` | created | Element overlays portal into; `null` for `document.body`. |
| `dir` | `"ltr" \| "rtl"` | from `locale`, else inherited | Reading direction of the subtree. |
| `locale` | `string` | inherited | BCP 47 locale of the subtree. |

### themeRootVariants

The class behind `theme`, for putting the same mode class on another element, such as a supplied overlay container.
