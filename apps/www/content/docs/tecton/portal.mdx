---
title: Portal Provider
description: "Chooses the element that Tecton overlays portal into. For pages that render several isolated React roots."
---

## Usage

```tsx
import { PortalProvider } from "@tecton/react/tecton/portal"
```

```tsx
<PortalProvider container={overlayRoot}>
  <App />
</PortalProvider>
```

Every Tecton overlay — `Dialog`, `Sheet`, `Popover`, `Tooltip`, `Select`, `Combobox`, `DropdownMenu`, `CommandDialog` — portals into `document.body` by default. `PortalProvider` changes that target for its whole subtree without any prop on the overlays themselves.

## When to use it

Applications that render **several isolated React roots on one page** (micro frontends, embedded widgets) give each root a body-level container of its own. The overlays still escape any `overflow: hidden` ancestor, while the container carries that root's scoped styles, theme tokens and ownership attributes:

```tsx
const overlayRoot = document.createElement("div")
overlayRoot.setAttribute("data-mfe", "asset-tracker")
document.body.append(overlayRoot)

createRoot(mountNode).render(
  <PortalProvider container={overlayRoot}>
    <AssetTracker />
  </PortalProvider>
)
```

A single-root application does not need it.

## Notes

- The provider owns a Tecton container context. Each overlay passes its resolved target straight to the primitive underneath, so isolated React roots never have to share one private context.
- With no provider, or with `container={null}`, overlays pass no container at all and the default applies (`document.body`, once hydration is over).
- A submenu is the exception: it mounts inside the root popover's container, which is already in the provider's container. Overriding that would detach the submenu from its parent menu, so Tecton leaves it alone.
- `Drawer` is built on Base UI, which has no portal context; it keeps portalling into `document.body`.
- `container={null}` clears an outer provider and restores the default.

## API Reference

### PortalProvider

| Prop        | Type                                                 | Default | Description                                                                                            |
| ----------- | ---------------------------------------------------- | ------- | ------------------------------------------------------------------------------------------------------ |
| `container` | `HTMLElement \| null \| (() => HTMLElement \| null)` | -       | Element the overlays portal into. A function is called while each overlay renders. `null` restores `document.body`. |
| `children`  | `ReactNode`                                          | -       | Subtree whose overlays are redirected.                                                                 |

### usePortalContainer

`usePortalContainer(): HTMLElement | null` — the current portal container, or `null` when overlays fall back to `document.body`.

### usePortalTarget

`usePortalTarget(): HTMLElement | undefined` — what the overlays hand to the primitive underneath: the container, or `undefined` to let it resolve the target itself. Tecton's own overlays call it; applications use `PortalProvider`.
