## Usage

```tsx
import { ThemeRoot } from "@tecton/react/tecton/theme-root"
```

```tsx
<ThemeRoot className="mfe-a" theme="inherit">
  <App />
</ThemeRoot>
```

## When to use it

An application that owns the document imports `@tecton/react/globals.css` and needs nothing here: its variables live on `:root` and its overlays can portal into `document.body`.

`ThemeRoot` is for an application mounted into a page that already has its own copy of Tecton — a Module Federation remote, an embedded widget. It marks that application's subtree with `data-tecton-root`, which is what `@tecton/react/styles/scoped.css` keys on, and it owns the container the application's overlays portal into. It declares no theme variables: the shell's `--primary`, palette, radii and current mode inherit into the subtree. See [Micro-frontends](/docs/micro-frontends) for the stylesheet and the build step that go with it.

## What it renders

```html
<div data-slot="theme-root" data-tecton-root class="dark mfe-a">…</div>
```

and, appended to `document.body`, one container with the same classes:

```html
<div data-slot="theme-root-overlay" data-tecton-root class="dark mfe-a" style="display: contents"></div>
```

Every Tecton overlay in the subtree — `Dialog`, `Sheet`, `AlertDialog`, `Popover`, `HoverCard`, `Tooltip`, `Select`, `Combobox`, `DropdownMenu`, `ContextMenu`, `Drawer` — portals into that container. It keeps them out of any `overflow: hidden` ancestor while they stay inside the application's own `@scope` rule, so the utilities that style them still apply, and the container mirrors the root's `className`: the scope class, a pinned theme and inline `[--token:…]` overrides all reach the overlays too. The container is `display: contents` (set inline, so it wins over any `display` utility among the copied classes): it renders no box of its own, so a layout class on the root (`flex h-full p-4`) takes up no space at the end of the body and is no containing block for the overlays.

## Theme

`theme` puts the mode class on both elements:

| Value | Effect |
| --- | --- |
| `inherit` (default) | No class: the subtree follows the shell's `dark` class (or `data-theme`), which is what a remote mounted in a Tecton shell wants. |
| `dark` | Pins the subtree to dark — a dark island such as a map or a log viewer in a light shell. |
| `light` | Pins it to light, the same way round. |

A pinned mode inverts everything the subtree renders with: the `dark:` utilities, the palette ramps (`bg-blue-560`) and the shadcn variables (`--background`, `--primary`, …). The overlay container carries the same class, so the subtree's overlays are in that mode as well. See [Inverted sections](/docs/theming#inverted-sections).

## Overlay container

Pass `overlayContainer` to take over the placement:

- **omitted** — `ThemeRoot` creates, styles and removes its own container.
- **an element** — used as is. It is neither restyled nor removed on unmount; give it `data-tecton-root` and the scope class yourself.
- **`null`** — no container. Overlays pass none and React Aria falls back to `document.body`.

When only some of the root's classes should reach the overlays, pass `overlayClassName`: it replaces the mirrored `className` on the container `ThemeRoot` creates (the theme class is always added). List the scope class and the `[--token:…]` overrides the overlays need:

```tsx
<ThemeRoot className="mfe-a flex h-full [--primary:var(--tecton-palette-green-560)]" overlayClassName="mfe-a [--primary:var(--tecton-palette-green-560)]">
  <App />
</ThemeRoot>
```

```tsx
<ThemeRoot className="mfe-a" overlayContainer={shell.overlayLayer}>
  <App />
</ThemeRoot>
```

## Notes

- The container is created in an effect, so the **first paint has no container** and React Aria resolves its own default. Everything opened by an interaction — every overlay in practice — sees the container. Rendering is SSR-safe.
- Each `ThemeRoot` owns exactly one container, and two roots on a page get one each.
- Variables can be overridden per root with an arbitrary property in `className`: `className="mfe-a [--primary:var(--tecton-palette-green-560)]"` retints that application, overlays included. The demo above is exactly that.
- `ThemeRoot` renders a plain `div`. It sets no layout of its own — give it the classes the mount point needs.

## Usage guidelines

### Use it when

- An application is mounted into a page that already carries its own copy of Tecton: a Module Federation remote, an embedded widget.
- A subtree must be pinned against the shell's mode — a dark map or log viewer in a light application.
- That subtree's overlays have to stay inside its own `@scope` rule instead of landing in a bare `document.body`.

### Not for

- an overlay container without the root marker or a scoped stylesheet: use [PortalProvider](/docs/tecton/portal)
- the header, rail and work area of an application that owns the document: use [AppShell](/docs/tecton/app-shell)
- a right-to-left subtree: use [DirectionProvider](/docs/components/direction)

### Do

<DoList>

<Do>

Render it around the whole mounted tree with the deployable's scope class: `<ThemeRoot className="mfe-a" theme="inherit">`.

</Do>

<Do>

Keep `theme="inherit"` inside a Tecton shell — the shell's variables, palette and mode inherit — and pin `dark` or `light` only for an inverted island.

</Do>

<Do>

Retint one root with an arbitrary property in `className`: `[--primary:var(--tecton-palette-green-560)]`, which is mirrored onto the overlay container.

</Do>

<Do>

Pass `overlayContainer` to reuse an element the shell owns, or `null` to opt out; omit it and the root creates, syncs and removes its own.

</Do>

<Do>

Pair it with `@tecton/react/styles/scoped.css` and the PostCSS scope plugin, never with `globals.css`.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="globals.css imported inside a mounted remote">

<Wrong>

```tsx
import "@tecton/react/globals.css"

createRoot(element).render(<App />)
```

</Wrong>

<Correct>

```tsx
import { ThemeRoot } from "@tecton/react/tecton/theme-root"

import "./styles/remote.css"

createRoot(element, { identifierPrefix: "mfe-a" }).render(
  <ThemeRoot className="mfe-a" theme="inherit">
    <App />
  </ThemeRoot>
)
```

</Correct>

`globals.css` carries preflight, the fonts and the whole variable set on `:root`, so a remote that imports it resets the document the shell owns and repaints the shell with the remote's version of the theme — a remote's sheet is `scoped.css`, scoped to the `data-tecton-root` marker `ThemeRoot` renders.

</Dont>

<Dont severity="HIGH" title="A theme applied as inline CSS variables">

<Wrong>

```tsx
<div style={{ "--primary": "#2f7d32" } as React.CSSProperties}>
  <App />
</div>
```

</Wrong>

<Correct>

```tsx
<ThemeRoot className="mfe-a [--primary:var(--tecton-palette-green-560)]">
  <App />
</ThemeRoot>
```

</Correct>

Inline variables reach only the elements under that `div`, and every `Dialog`, `Select`, `Tooltip` and `DropdownMenu` portals out of it, so the overlays keep the shell's colours; `ThemeRoot` copies its `className` onto the body-level container it owns, which is what carries an override across the portal.

</Dont>

<Dont severity="MEDIUM" title="The dark class toggled on a plain root element">

<Wrong>

```tsx
<div className={mode === "dark" ? "mfe-a dark" : "mfe-a"}>
  <App />
</div>
```

</Wrong>

<Correct>

```tsx
<ThemeRoot className="mfe-a" theme={mode === "dark" ? "dark" : "light"}>
  <App />
</ThemeRoot>
```

</Correct>

The mode class has to sit on the overlay container as well, or the subtree's portalled overlays render in the shell's mode; `themeRootVariants` and the sync effect are what put it on both and swap it when `mode` flips.

</Dont>

{/* guidelines:end */}

## API Reference

### ThemeRoot

A `div` element; every `div` prop is forwarded.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `theme` | `"dark" \| "light" \| "inherit"` | "inherit" | Mode class on the root and the overlay container. |
| `overlayContainer` | `HTMLElement \| null` | created | Element the overlays portal into. An element is used as is; `null` disables the container. |
| `className` | `string` | - | Scope class, theme overrides and layout; mirrored onto the overlay container unless `overlayClassName` is set. |
| `overlayClassName` | `string` | - | Classes for the created overlay container instead of a copy of `className` (the theme class is always added). Ignored when `overlayContainer` is passed. |
| `children` | `ReactNode` | - | The application. |

### themeRootVariants

The `cva` function behind the `theme` prop, for composing the same class on another element (a supplied overlay container, for example).
