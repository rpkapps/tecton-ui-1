Tecton ships **one** icon set: `@tecton/react/icons`, 243 named components covering the generic vocabulary (chevrons, check marks, close buttons, search) and the subsurface domain (wells, horizons, seismic, drill bits, facies). There is no second icon package to install and no compatibility layer for another one — a Tecton name is the only name.

```tsx
import { Button } from "@tecton/react/components/button"
import { SearchIcon, SeismicIcon, WellIcon } from "@tecton/react/icons"

<Button>
  <WellIcon data-icon="inline-start" /> New well
</Button>
<SearchIcon />
<SeismicIcon variant="filled" size={20} />
```

Every icon is a plain function component taking `size`, `className`, `variant="outlined" | "filled"` and any SVG prop, and `strokeWidth` / `absoluteStrokeWidth` are accepted (and ignored) so an icon is a drop-in `<svg>`.

## Three fonts

An icon is a character, not a path. `packages/tecton-react/scripts/build-symbol-fonts.mts` builds three woff2 families, and `<Icon>` draws the right codepoint from them inside a 24×24 `<svg>` host. The browser picks, per character, the first family that has a glyph, so the three are one fallback chain:

| Family | Carries |
| --- | --- |
| `Tecton Symbols` | Material Symbols Sharp, **weight 300, optical size 24, grade 0**, with the FILL axis kept variable |
| `Tecton Symbols Domain` | Tecton's own drawings, outlined and filled as two codepoints |
| `Tecton Symbols Fallback` | every codepoint the other two could use, mapped to one "unknown icon" glyph |

The axis preset is not a taste call. Tecton's own strokes measure **0.0599** of the icon box; Material Symbols at optical size 24 measures **0.0625** at weight 300 and 0.0833 at weight 400, so weight 300 is the only setting where a Material glyph and a Tecton drawing sit next to each other without one looking heavier. Grade 0 and optical size 24 are pinned for the same reason. FILL stays variable because it is what `variant="filled"` moves; Tecton's own drawings carry the two variants as two codepoints instead.

<Callout title="Glyph sources">
  196 icons render a Material Symbols Sharp glyph, 46 render Tecton's own drawing (vendored in `packages/tecton-react/icons-src/tecton/`, one `defineTectonSvgIcon` definition per icon), and `StrataIcon` stays an inline SVG because it is drawn in colour. Every rendered `<svg>` says which it is through `data-tecton-source` (`symbol`, `domain` or `svg`), and which icon through `data-tecton-icon`.
</Callout>

## `Icon`, the named wrappers, `MaterialSymbol`

```tsx
import { Icon, WellIcon } from "@tecton/react/icons"

<WellIcon size={20} />   {/* the named component */}
<Icon name="well" />     {/* by name, for data-driven icons */}
```

`Icon` is the primitive; each named wrapper is a one-line `tectonIcon("<slug>")` around it, so the two render the same thing. `Icon` is what you want when the name comes from data (a nav table, a status map); the named wrapper is what you want everywhere else, because a typo is a build error rather than a runtime placeholder. A name the set does not have renders the reserved unknown-icon glyph and warns once in development.

### A raw Material glyph

**A Tecton name always wins.** If the set has the icon, import the Tecton component, so the drawing and the gallery stay in one place. For the rest of Google's catalogue there is an explicit escape hatch on its own subpath, deliberately awkward enough that it is a decision (the 4,284-name table is not loaded by anything else):

```tsx
import { MaterialSymbol } from "@tecton/react/icons/material"

<MaterialSymbol name="rocket_launch" variant="filled" />
```

A raw Material glyph is the exception, not a shortcut: reach for it for a one-off that will never be part of the design system, and open an icon request for anything that will.

## Loading the fonts

`@tecton/react/globals.css` does **not** import the fonts. The application shell loads `@tecton/react/styles/tecton-symbols.css` once — the woff2 files sit in `./fonts/` next to it — and preloads the three files, because they are needed for the first paint of every screen:

```css title="src/styles/app.css"
@import "@tecton/react/globals.css";
@import "@tecton/react/styles/tecton-symbols.css";
```

```tsx title="the document head"
import domainFont from "@tecton/react/styles/fonts/tecton-symbols-domain.woff2?url"
import fallbackFont from "@tecton/react/styles/fonts/tecton-symbols-fallback.woff2?url"
import symbolsFont from "@tecton/react/styles/fonts/tecton-symbols.woff2?url"

const links = [symbolsFont, domainFont, fallbackFont].map((href) => ({
  rel: "preload",
  as: "font",
  type: "font/woff2",
  href,
  crossOrigin: "anonymous" as const,
}))
```

<Callout title="One shell, one stylesheet">
  A [micro-frontend](/docs/micro-frontends) mounted inside a Tecton shell loads **nothing**: fonts are document-level, the shell already declared the three families, and a remote that imports the sheet again only makes the browser parse a second identical set of `@font-face` rules. Only the application that owns the document loads it.
</Callout>

Fonts arrive asynchronously, so the host reports `data-state` and never changes size between states:

| `data-state` | What is drawn |
| --- | --- |
| `loading` | a skeleton block, invisible for the first 150 ms so a warm cache never flashes, with the glyph hidden behind it |
| `ready` | the glyph |
| `unavailable` | no font after 5 s: a dashed placeholder that needs no font at all |

A font that arrives late still flips the state to `ready`. An application that never loads the stylesheet paints nothing at all before the placeholder — no tofu — because the fallback family maps every codepoint either of the other two could use to one blank "unknown icon" glyph.

### Spacing inside a control

An icon or `Spinner` inside a `Button`, `Badge`, `Chip`, `TabsTrigger` or `InputGroupAddon` carries `data-icon="inline-start"` or `data-icon="inline-end"`, which is what gives it the gap the component owns:

```tsx
<Button>
  <AddIcon data-icon="inline-start" /> New horizon
</Button>
```

## Adding an icon

```bash
# 1. add an entry to packages/tecton-react/icons/icons.json:
#      { "name": "Valve", "label": "ValveIcon", "slug": "valve",
#        "description": "…", "symbol": "<a Material Symbols name>" | null,
#        "domain": true | false }
pnpm --filter @tecton/react icons:build            # regenerates src/icons/*
pnpm --filter @tecton/react icons:build --check    # CI drift guard
```

An entry needs exactly one primary source and the build fails without one: a `symbol` from `icons/material-symbols.codepoints` (two entries may not claim the same one), or a drawing. A symbol wins over a drawing of the same icon, which stays in the domain font as a reserve.

For a **drawing**, replace the vendored Tecton export in `icons-src/tecton/*.ts` (never edit it by hand) and rebuild the fonts first, because the drawing needs a codepoint before the component can name it:

```bash
pnpm --filter @tecton/react icons:fonts            # rebuilds the three woff2 families
pnpm --filter @tecton/react icons:fonts:check      # CI drift guard
pnpm --filter @tecton/react icons:build
```

Loose SVG files in `icons-src/outlined/` or `icons-src/filled/` override a definition for that variant (`icons:extract` can populate them from a Storybook).

## For design review

Two kinds of entry in the set are a judgement call rather than a measurement, and are listed here so a designer can settle them. Nothing below is broken; each is a choice that can be changed with a one-line manifest edit and a rebuild.

**Icons whose drawing differs between Tecton and Material.** Where Tecton's own drawing was kept, the Material glyph is not used at all; where the Material glyph was taken, Tecton's drawing stays in the domain font as a reserve.

| Icon | Draws | Note |
| --- | --- | --- |
| `SettingsIcon` | Tecton drawing | a plain gear; Material's `settings` gear has a different tooth count and centre |
| `MoreVertIcon` | Tecton drawing | three vertical dots, spaced differently from Material's `more_vert` |
| `AppsIcon` | Material `apps` | Tecton's 3×3 grid of dots reads lighter than Material's |
| `FilterIcon` | Tecton drawing | a funnel; Material's `filter_alt` funnel has a different taper |
| `CopyIcon` | Tecton drawing | two overlapping rounded squares; Material's `content_copy` offsets them differently |
| `AddPinIcon` | Material `add_location_alt` | Tecton draws the plus at the top right of the pin, Material inside it |
| `ExportUploadIcon` | Tecton drawing | arrow up out of a tray; Material's `upload` has no tray |
| `EditSquareIcon` | Material `edit_square` | Tecton puts the pencil over the top-right corner of the square |
| `ChevronDownSmallIcon`, `ChevronLeftSmallIcon`, `ChevronRightSmallIcon`, `ChevronUpSmallIcon` | Tecton drawings | Material has no second, smaller chevron — these exist only as Tecton drawings |
| `CloseSmallIcon` | Tecton drawing | same: Material's `close_small` is a different construction |
| `ValveIcon`, `StrataIcon` | Tecton drawings (domain) | Material happens to ship a close match for both; they are kept as Tecton drawings because they are domain marks |
