# Tecton components

Components that exist only in the Tecton design system and have no shadcn counterpart.

Source: /docs/tecton/index.md

The Tecton theme applies the design system through the shadcn CSS variables and a Tecton style overlay, so every component in [Components](/docs/components.md) is the shadcn/ui React Aria implementation generated by the CLI. Tecton semantics that do not fit into variables are carried by that overlay as extra variants of the shadcn components: the status colours and surface styles of an alert are `Alert` `variant` and `appearance`, a chip's colours and outlined look are `Badge` `variant` and `appearance`, the three text-field surfaces are `Input`, `Textarea` and `SelectTrigger` `variant`, the divider emphases are `Separator` `emphasis`, and the floating action button is a `Button` recipe. Each synced component page documents its Tecton variants in a section inserted by the docs sync.

What remains here are the patterns shadcn does not have at all — a selectable tag group, a segmented meter, a tree view, an app shell. They compose the shadcn primitives where they exist or build directly on React Aria, follow the same `data-slot` and `class-variance-authority` conventions, and are installed the same way.

All of them are exported from `@tecton/react/tecton/<name>`.
