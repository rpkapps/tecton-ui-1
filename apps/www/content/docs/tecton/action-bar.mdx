## Usage

```tsx
import {
  ActionBar,
  ActionBarActions,
  ActionBarMessage,
  ActionBarSelection,
} from "@tecton/react/tecton/action-bar"
import { OverflowItem, OverflowLabel } from "@tecton/react/tecton/overflow"
```

```tsx
<ActionBar open={selected > 0} onOpenChange={(open) => !open && clear()} aria-label="Selected wells">
  <ActionBarSelection count={selected} total={wells.length} onClear={clear} />
  <ActionBarActions aria-label="Selection actions">
    <OverflowItem value="tag" label="Add tag" icon={<TagIcon />} onClick={addTag}>
      <Button variant="outline" size="sm">
        <TagIcon data-icon="inline-start" />
        <OverflowLabel>Add tag</OverflowLabel>
      </Button>
    </OverflowItem>
    <Button size="sm" onClick={assign}>Assign</Button>
  </ActionBarActions>
</ActionBar>
```

`ActionBarActions` is an [Overflow](/docs/tecton/overflow) toolbar: actions wrapped in `OverflowItem` move into a More menu as the bar narrows, a bare action stays. After that, the selection summary compacts from "12 of 340 selected" to "12 selected" and then to a count badge; a live region always announces the full text.

## Floating

`placement="floating"` is a sticky card at the bottom of its scroll container, not the viewport. The default, `placement="toolbar"`, fills the row a table toolbar occupies, as in the first example.

## Usage guidelines

### Use it when

- Rows are selected in a table or list and the actions apply to that selection.
- A form has unsaved changes and needs Save or Discard without moving the page.
- The bar should exist only while there is something to act on, then disappear.

### Not for

- a permanent row of page actions: use [ButtonGroup](/docs/components/button-group)
- a transient confirmation that carries no actions: use [toast](/docs/components/sonner)
- a list of actions behind a single button: use [DropdownMenu](/docs/components/dropdown-menu)

### Do

<DoList>

<Do>

Control it with `open` / `onOpenChange` (called with `false` when the user dismisses it); the bar owns Escape and the enter transition.

</Do>

<Do>

Give it an `aria-label`; it renders a `div` with `role="region"`.

</Do>

<Do>

Summarise with `ActionBarSelection` (`count`, `total`, `label`, `onClear`) or with `ActionBarMessage`.

</Do>

<Do>

Put the actions in `ActionBarActions`, wrapping collapsible ones in `OverflowItem` and leaving the primary action bare.

</Do>

<Do>

Choose `placement="toolbar"` to fill a table's toolbar row, `"floating"` for a sticky card inside the scroll container.

</Do>

</DoList>

### Don't

<Dont severity="HIGH" title="A hand-written selection summary and Clear button">

<Wrong>

```tsx
<ActionBar open={selected.size > 0} aria-label="Selected wells">
  <span>{selected.size} of {wells.length} selected</span>
  <Button variant="ghost" size="sm" onClick={clear}>Clear</Button>
</ActionBar>
```

</Wrong>

<Correct>

```tsx
<ActionBar open={selected.size > 0} onOpenChange={(open) => !open && clear()} aria-label="Selected wells">
  <ActionBarSelection count={selected.size} total={wells.length} label="wells" onClear={clear} />
</ActionBar>
```

</Correct>

`ActionBarSelection` carries the visually hidden `aria-live` announcement and the container queries that compact the text to "12 selected" and then to a count badge; a plain span announces nothing and overflows as the bar narrows.

</Dont>

<Dont severity="HIGH" title="Bare buttons inside the ActionBarActions toolbar">

<Wrong>

```tsx
<ActionBarActions aria-label="Selection actions">
  <Button variant="outline" size="sm"><TagIcon data-icon="inline-start" />Add tag</Button>
  <Button size="sm" onClick={assign}>Assign</Button>
</ActionBarActions>
```

</Wrong>

<Correct>

```tsx
<ActionBarActions aria-label="Selection actions">
  <OverflowItem value="tag" label="Add tag" icon={<TagIcon />} onClick={addTag}>
    <Button variant="outline" size="sm"><TagIcon data-icon="inline-start" /><OverflowLabel>Add tag</OverflowLabel></Button>
  </OverflowItem>
  <Button size="sm" onClick={assign}>Assign</Button>
</ActionBarActions>
```

</Correct>

`ActionBarActions` is an overflow `Toolbar`, and only an `OverflowItem` can be measured and moved into the More menu, so unwrapped actions never collapse and the row clips instead.

</Dont>

<Dont severity="MEDIUM" title="A floating bar sized with w-fit">

<Wrong>

```tsx
<ActionBar placement="floating" className="mx-auto w-fit" aria-label="Selected documents">
  <ActionBarSelection count={selected.size} onClear={clear} />
</ActionBar>
```

</Wrong>

<Correct>

```tsx
<ActionBar placement="floating" className="mx-auto max-w-md" aria-label="Selected documents">
  <ActionBarSelection count={selected.size} onClear={clear} />
</ActionBar>
```

</Correct>

The bar is its own `@container`, so a fit-content inline size resolves from its padding alone: the toolbar measures no room and collapses every action into the More menu.

</Dont>

{/* guidelines:end */}

## API Reference

### ActionBar

A `div` with `role="region"`; give it an `aria-label`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `placement` | `"toolbar" \| "floating"` | `"toolbar"` | Fill the toolbar row, or float as a sticky card. |
| `open` | `boolean` | `true` | Render the bar. |
| `onOpenChange` | `(open: boolean) => void` | - | Called with `false` on Escape while focus is inside the bar. |

### ActionBarSelection

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `count` | `number` | - | Selected items. |
| `total` | `number` | - | Total items; adds "of N". |
| `label` | `string` | - | Noun after the count, e.g. `"wells"`. |
| `onClear` | `() => void` | - | Renders the Clear button. |
| `clearLabel` | `string` | `"Clear selection"` | Accessible name of the compact Clear button. |

### ActionBarMessage

A `p` for a text summary.

### ActionBarActions

An [Overflow](/docs/tecton/overflow) `Toolbar`; `aria-label` defaults to `"Actions"`.
