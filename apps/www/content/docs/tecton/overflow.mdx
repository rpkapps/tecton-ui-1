## Usage

```tsx
import {
  OverflowDivider,
  OverflowItem,
  OverflowLabel,
  Toolbar,
} from "@tecton/react/tecton/overflow"
```

```tsx
<Toolbar aria-label="Well actions">
  <OverflowItem value="share" label="Share" icon={<ShareIcon />} priority={1} onClick={share}>
    <Button variant="outline">
      <ShareIcon data-icon="inline-start" />
      <OverflowLabel>Share</OverflowLabel>
    </Button>
  </OverflowItem>
  <OverflowDivider />
  <OverflowItem value="delete" label="Delete" variant="destructive" labelBehavior="keep" onClick={remove}>
    <Button variant="destructive">Delete</Button>
  </OverflowItem>
  <Button>New well</Button>
</Toolbar>
```

Wrap every control that may leave the row in an `OverflowItem`, as a direct child of the row; unwrapped children never leave, so the primary action goes in bare. Put the label text in an `OverflowLabel` so an item whose control has an icon can drop to icon-only. The More menu is added at the end automatically.

`Toolbar` is one tab stop: the arrow keys move between its visible controls (Left and Right swap under a right-to-left `TectonProvider`) and Tab leaves the row. Use `Overflow` for a row that is not a toolbar, such as a header with a tab list.

## How it collapses

As the container narrows, the row gives up space in stages and takes it back in reverse, without ever reordering items:

1. `elastic` items shrink to their minimum.
2. Every collapsible label drops at once; those items become icon-only with a tooltip.
3. Items move into the More menu, lowest `priority` first, ties from the end of the row.
4. When the fixed items alone do not fit, the row wraps (`lastResort="wrap"`) or scrolls.

## Priority

`priority` decides who leaves first, never where an item sits; the menu keeps source order. `labels="always"` skips the icon-only stage.

## Other controls

A button needs nothing more: its menu item is built from `label`, `icon`, `shortcut` and `onClick`, and `onClick` and `disabled` also reach the control itself. Any other control passes its menu form as `overflow`:

| Control | `overflow` |
| --- | --- |
| Toggle | `DropdownMenuCheckboxItem` bound to the same state |
| Dropdown trigger | `DropdownMenuSub` with the same items |
| Select | `DropdownMenuSub` with a `DropdownMenuRadioGroup` |
| Text input | `DropdownMenuItem` that opens a `Dialog` with the same input |
| Must never leave | `"never"` |

A text input is usually `elastic`, and a dropdown trigger keeps its label (`labelBehavior="keep"`). `OverflowGroup` shows its hidden members as a labelled menu section; `collapse="together"` moves the whole group at once. A divider becomes a menu separator and disappears when one side of it is empty.

## Vertical

`orientation="vertical"` makes a column: items leave from the bottom and the More menu opens to the side. A tool rail is icon-only already, so give it `labels="never"`.

## Usage guidelines

### Use it when

- A row of controls has to survive a container that gets narrow: a panel toolbar, a table header, a card's action row.
- The actions matter enough to stay reachable, so hiding them outright is not acceptable.
- The row is measured by its own width, not by a breakpoint — the same toolbar sits in a wide page and a 320 px aside.

### Not for

- two or three buttons welded into one control: use [ButtonGroup](/docs/components/button-group)
- actions that appear only while rows are selected: use [ActionBar](/docs/tecton/action-bar)
- every action behind one button from the start: use [DropdownMenu](/docs/components/dropdown-menu)

### Do

<DoList>

<Do>

Wrap every control that may leave the row in an `OverflowItem` with a stable `value`; leave the primary action unwrapped so it is fixed and never collapses.

</Do>

<Do>

Put the text in an `OverflowLabel` beside an icon and describe the menu entry with `label`, `icon`, `shortcut` and `onClick`; only an item with a `label` and an icon in its control goes icon-only, a text-only item keeps its label.

</Do>

<Do>

Decide who leaves first with `priority` (higher stays longer); the menu always keeps source order.

</Do>

<Do>

Use `Toolbar` with an `aria-label` when the row is a toolbar (arrow keys move between every visible control, Tab leaves it) and `Overflow` when it is not, such as a chip row or a header with a tab list.

</Do>

<Do>

Give a non-button its menu form through `overflow`: a `DropdownMenuSub` for a select or submenu, a `DropdownMenuItem` opening a `Dialog` for a text input, or `"never"` to pin the item in the row.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="Bare controls in the row">

<Wrong>

```tsx
<Toolbar aria-label="Well actions">
  <Button variant="outline"><TagIcon data-icon="inline-start" />Add tag</Button>
  <Button variant="outline"><ShareIcon data-icon="inline-start" />Share</Button>
  <Button onClick={create}>New well</Button>
</Toolbar>
```

</Wrong>

<Correct>

```tsx
<Toolbar aria-label="Well actions">
  <OverflowItem value="tag" label="Add tag" icon={<TagIcon />} onClick={addTag}>
    <Button variant="outline"><TagIcon data-icon="inline-start" /><OverflowLabel>Add tag</OverflowLabel></Button>
  </OverflowItem>
  <OverflowItem value="share" label="Share" icon={<ShareIcon />} onClick={share}>
    <Button variant="outline"><ShareIcon data-icon="inline-start" /><OverflowLabel>Share</OverflowLabel></Button>
  </OverflowItem>
  <Button onClick={create}>New well</Button>
</Toolbar>
```

</Correct>

Only an `OverflowItem` registers itself with the row's store, so only it can be measured, collapsed or moved into the menu: a row of bare buttons is entirely fixed, no More button is ever rendered, and the row wraps or scrolls instead.

</Dont>

<Dont severity="HIGH" title="Label text that is not in an OverflowLabel">

<Wrong>

```tsx
<OverflowItem value="export" label="Export" icon={<DownloadIcon />} onClick={exportRows}>
  <Button variant="outline"><DownloadIcon data-icon="inline-start" />Export</Button>
</OverflowItem>
```

</Wrong>

<Correct>

```tsx
<OverflowItem value="export" label="Export" icon={<DownloadIcon />} onClick={exportRows}>
  <Button variant="outline"><DownloadIcon data-icon="inline-start" /><OverflowLabel>Export</OverflowLabel></Button>
</OverflowItem>
```

</Correct>

The icon-only stage works by putting `sr-only` on `OverflowLabel` alone, so plain text keeps its width: the item never reaches a compact size, the measured pair is wrong, and the row skips the collapse stage and starts hiding items instead.

</Dont>

<Dont severity="HIGH" title="The handler on the button instead of on the item">

<Wrong>

```tsx
<OverflowItem value="delete" label="Delete" icon={<Trash2Icon />} variant="destructive">
  <Button variant="destructive" onClick={remove}><Trash2Icon data-icon="inline-start" /><OverflowLabel>Delete</OverflowLabel></Button>
</OverflowItem>
```

</Wrong>

<Correct>

```tsx
<OverflowItem value="delete" label="Delete" icon={<Trash2Icon />} variant="destructive" onClick={remove}>
  <Button variant="destructive"><Trash2Icon data-icon="inline-start" /><OverflowLabel>Delete</OverflowLabel></Button>
</OverflowItem>
```

</Correct>

The item's `onClick` (and `disabled`) is both the handler of the generated `DropdownMenuItem` and passed on to the single control element inside the item, so it fires in both places; left on the button alone, the More-menu entry is built with no handler and does nothing once the item is hidden.

</Dont>

{/* guidelines:end */}

## API Reference

### Toolbar, Overflow

`Toolbar` is a `div` with `role="toolbar"` (give it an `aria-label`); `Overflow` is a plain `div`. Both accept `div` props and:

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` | Axis of the row. |
| `labels` | `"auto" \| "always" \| "never"` | `"auto"` | `auto` collapses labels before hiding items, `always` keeps them, `never` is icon-only from the start. |
| `minimumVisible` | `number` | `0` | Items kept in the row regardless of width. |
| `lastResort` | `"wrap" \| "scroll"` | `"wrap"` | When fixed items alone do not fit. A vertical row scrolls. |
| `menu` | `boolean` | `true` | Render the More menu; `false` to place an `OverflowMenu` yourself. |
| `overflowBadge` | `boolean` | `false` | Show the number of hidden items on the More button. |

### OverflowItem

A `div` around one control.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | - | Stable identity of the item. |
| `priority` | `number` | `0` | Higher stays in the row longer. |
| `label` | `string` | - | Menu item text, tooltip, and accessible name while icon-only. |
| `icon` | `ReactNode` | - | Icon of the menu item. |
| `shortcut` | `ReactNode` | - | Key hint shown in the menu item. |
| `onClick` | `() => void` | - | Called by the menu item and by the control. |
| `disabled` | `boolean` | - | Disables the menu item and the control. |
| `variant` | `"default" \| "destructive"` | `"default"` | Menu item variant. |
| `labelBehavior` | `"collapse" \| "keep"` | `"collapse"` with a `label` and an icon, else `"keep"` | Whether the label can drop to icon-only. |
| `tooltip` | `boolean` | `true` unless `labelBehavior="keep"` | Show `label` as a tooltip while icon-only. |
| `elastic` | `boolean \| { min?: string; max?: string }` | - | Shrink between these sizes (default `12rem` to `100%`) before anything collapses. |
| `overflow` | `ReactNode \| "never"` | - | Menu form; `"never"` keeps the item in the row. |

### OverflowLabel

A `span` for an item's label text; visually hidden while the item is icon-only.

### OverflowDivider, OverflowSpacer

A separator between items, and a flexible space that pushes what follows to the end. Both disappear when one side of them is empty.

### OverflowGroup

Renders no element: `value`, `label` (menu section heading) and `collapse` (`"individually"` or `"together"`).

### OverflowMenu

The More button and its menu, placed by hand in a row with `menu={false}`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | `"More actions"` | Accessible name of the default trigger. |
| `trigger` | `ReactElement` | - | A trigger element, e.g. `<Button variant="outline">More</Button>`, instead of the ellipsis. |
| `badge` | `boolean` | `false` | Show the number of hidden items on the trigger. |
| `className` | `string` | - | Classes of the wrapper around the trigger. |

### useIsOverflowItemVisible

`useIsOverflowItemVisible(value: string): boolean` — whether the item is currently in the row.
