## Tecton recipes

Tecton ships no `DataTable` component: build tables with [TanStack Table](https://tanstack.com/table/latest) and the `Table` components, as the guide above does. Each recipe below is a self-contained starting point built on `useTable`.

### Density and alternating rows

Density is nothing more than Tailwind classes on the `Table`: an emphasised header (`[&_thead]:bg-muted`), alternating rows (`[&_tbody_tr:nth-child(even)]:bg-surface-alt`) and, for the compact variant, shorter rows and smaller text (`[&_th]:h-8 [&_td]:py-1 text-xs`).

### Row selection

`Table` is a plain HTML table, so selection is TanStack's `rowSelection` state: add a display column with a `Checkbox` in the header (`checked` when every row is selected, `indeterminate` when some are, `onCheckedChange` → `toggleAllRowsSelected`) and one in each cell (`row.getIsSelected()` / `row.toggleSelected`), and mark selected rows with `data-state="selected"`. Summarise the selection below the table.

<ComponentPreview name="data-table-selection" align="start" />

### Bulk actions

While rows are selected, replace the table toolbar with an [Action Bar](/docs/tecton/action-bar): the count and a Clear control, then the actions in an overflow toolbar that collapses into a More menu when the table is narrow. Escape, while focus is in the bar, clears the selection.

### Pagination

Register `rowPaginationFeature` with `createPaginatedRowModel()`, keep the `pagination` state in React and render previous/next buttons, a page-size `Select` and a "Page x of y" label in a footer line.

### Small screens

Hide low-priority columns below `md` with `hidden md:table-cell` on both the header and the cell, and let the primary cell carry that information as a subtitle so nothing is lost on a phone.

<ComponentPreview name="data-table-small-screen" align="start" />

### Column resizing

Register `columnSizingFeature`, keep the `columnSizing` state in React and put a [Table Column Resizer](/docs/tecton/table-column-resizer) on the end edge of each `TableHead` (`className="relative"`, `style={{ width: header.getSize() }}`). Give the `Table` `table-fixed` and the total width (`table.getTotalSize()`), and let cells `truncate`. The limits come from `defaultColumn` (`minSize`, `maxSize`) or each column's own; `resetValue={column.columnDef.size}` is what Enter and a double click go back to. The resizer is a focusable separator: the arrow keys resize too, mirrored in a right-to-left table.

<ComponentPreview name="data-table-column-resize" align="start" />

### Column reordering

Register `columnOrderingFeature` and keep the `columnOrder` state, starting with every column's id. Wrap the `Table` in a [Reorderable](/docs/tecton/reorderable) with `orientation="horizontal"`, render each movable header as a `ReorderableItem` with `render={<TableHead />}` and `dragHandle={false}`, and write the new order back to `columnOrder`. A header has no room for a grip, so it is its own handle: drag it from anywhere (a sort button inside it keeps its clicks), or Tab to it, press Enter or Space and pick the gap with the arrow keys. A column that must stay put (the identifying column, the selection column) is a plain `TableHead` left out of the `Reorderable`'s `value`.

<ComponentPreview name="data-table-column-reorder" align="start" />

### Row reordering

Keep the rows in React state, list their ids as the `Reorderable`'s `value`, render each row as a `ReorderableItem` (`render={<TableRow />}`) with a `ReorderableHandle` in its first cell, and reorder the data in `onValueChange`. Drag the handle, or press Enter or Space on it and pick the gap with the arrow keys. A sorted table has no manual order: hide the handles while a sort is applied, or clear the sort first.

<ComponentPreview name="data-table-row-reorder" align="start" />

### Tree table

Register `rowExpandingFeature` with `createExpandedRowModel()` and pass `getSubRows` (here fields → platforms → wells). In the first column, indent the cell by `row.depth` (`paddingInlineStart`, 1.25rem a level) and put a chevron button, styled like a Tree View row's, before the name of each row that `getCanExpand()`, with `aria-expanded` and an "Expand …" / "Collapse …" name; leaves keep the chevron's space so names line up. `toggleAllRowsExpanded` drives an Expand all / Collapse all button. For a hierarchy without columns, use a [Tree View](/docs/tecton/tree-view).

<ComponentPreview name="data-table-tree" align="start" />

### Virtual scrolling

For thousands of rows, set `virtualized` on the `Table` and give its parent a bounded height (here `h-96`, with the border). Pass `items={table.getRowModel().rows}` to `TableBody` and render one row with a function: only the rows in view are rendered, so sorting 10,000 rows renders a screenful. The header sticks while the rows scroll, the columns keep their first widths, and the row height is measured, so the Default / Compact switch works as it does on a short table. Rows must be one height within the table. For page-sized chunks instead, use [pagination](#pagination). `Reorderable` sees only the rows in view, so reordering a virtualized table moves rows within the visible window.

<ComponentPreview name="data-table-virtual" align="start" />

### Virtual tree table

A tree table of thousands of rows combines the two recipes above. `table.getRowModel().rows` holds only the open rows, flattened in order with their `depth`, so pass it as `items` to a `virtualized` table: expanding a field adds its rows to the scroll range, and Expand all opens 13,040 rows while only a screenful is rendered. A chevron that has focus keeps its row mounted while it scrolls out of view. The columns keep the widths they are first laid out with, so give the Name column room for the deepest indent (`w-[45%]` on its `TableHead`).
