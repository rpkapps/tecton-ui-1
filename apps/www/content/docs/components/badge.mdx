## Usage

```tsx
import { Badge } from "@tecton/react/components/badge"
```

```tsx
<Badge variant="default | outline | secondary | destructive">Badge</Badge>
```

## Variants

Use the `variant` prop to change the variant of the badge.

## With Icon

You can render an icon inside the badge. Use `data-icon="inline-start"` to render the icon on the left and `data-icon="inline-end"` to render the icon on the right.

## Status colours

The Tecton style overlay adds `variant="success" | "warning" | "info"` next to `destructive`, and an `appearance="outline"` for a transparent badge with a coloured border and text. The interactive, selectable and removable variant of the badge is the Tecton [Chip](/docs/tecton/chip), which reuses the same `variant`, `appearance` and `size` props.

## Usage guidelines

### Use it when

- A static label names a status, a category or a state: "Draft", "Producing", "12 errors".
- The label carries a severity: `variant="success" | "warning" | "info" | "destructive"`.
- The label links to the thing it names, inside a table cell, a list row or a card header.

### Not for

- a tag the user can select or remove: use [Chip](/docs/tecton/chip)
- a count or dot pinned to the corner of an icon or avatar: use [CountBadge](/docs/tecton/count-badge)
- a confirmation that disappears on its own: use [toast](/docs/components/sonner)
- a keyboard key or a shortcut hint: use [Kbd](/docs/components/kbd)

### Do

<DoList>

<Do>

Pick meaning with `variant`, weight with `appearance="solid" | "outline"`, height with `size="default" | "md" | "lg"` (20 / 24 / 28 px).

</Do>

<Do>

Give an icon or a `Spinner` child `data-icon="inline-start"` or `data-icon="inline-end"` so the badge trims its padding on that side.

</Do>

<Do>

Make it a link with `render={(props) => <a {...props} href="/wells/12" />}`; there is no `asChild`, and an outer `<a>` gets none of the badge's `[a]:hover:` rules.

</Do>

<Do>

A category colour that no `variant` carries is the one documented exception: a Tecton palette pair, `className="bg-blue-120 text-blue-830"`, never a stock Tailwind colour. Otherwise `className` is for placement.

</Do>

<Do>

Keep a `Badge` label to one or two words ("Shut in"); put longer detail in the adjacent cell or a `Tooltip`.

</Do>

<Do>

A `Badge` icon always sits beside a text label; never show an icon-only badge.

</Do>

<Do>

Show metadata (spud date, measured depth) as muted text (`text-muted-foreground`), not a `Badge`; badges name statuses, categories or states.

</Do>

<Do>

Use a dot (`CountBadge variant="dot"`) only for on/off signals like unread; a multi-state status is a text `Badge`.

</Do>

<Do>

A status shown without text (dense grid cell, map marker) uses a distinct icon shape per state with an `aria-label`, not a coloured dot.

</Do>

<Do>

Never show status by colour alone: every `Badge` has text, and a dot repeats its meaning nearby or in `aria-label`.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="Hand-colouring a status label with className">

<Wrong>

```tsx
<Badge className="bg-green-600 text-white">Producing</Badge>
```

</Wrong>

<Correct>

```tsx
<Badge variant="success">Producing</Badge>
```

</Correct>

`cn` merges away the variant's `bg-primary`, and `green-600` is not a Tecton step, so the reset palette emits no rule at all and the badge renders with no background.

</Dont>

<Dont severity="HIGH" title="Making a Badge clickable with a handler">

<Wrong>

```tsx
<Badge variant="info" onClick={() => setFilter("fault-seal")}>
  Fault seal
</Badge>
```

</Wrong>

<Correct>

```tsx
<ChipGroup
  aria-label="Filters"
  selectionMode="single"
  onSelectionChange={(keys) => setFilter([...keys][0])}
>
  <ChipList>
    <Chip id="fault-seal" variant="info">
      Fault seal
    </Chip>
  </ChipList>
</ChipGroup>
```

</Correct>

Badge renders a `span` with no `role`, no `tabIndex` and no key handling, so the label answers a mouse click and is unreachable by keyboard and silent to assistive technology.

</Dont>

<Dont severity="MEDIUM" title="An icon child without data-icon">

<Wrong>

```tsx
<Badge variant="warning">
  <TriangleAlertIcon />
  Unsaved
</Badge>
```

</Wrong>

<Correct>

```tsx
<Badge variant="warning">
  <TriangleAlertIcon data-icon="inline-start" />
  Unsaved
</Badge>
```

</Correct>

The padding compensation is `has-data-[icon=inline-start]:pl-1.5`, so without the attribute the icon sits in full text padding and the badge is wider than every other badge in the row.

</Dont>

{/* guidelines:end */}

## API Reference

### Badge

The `Badge` component displays a badge or a component that looks like a badge.

| Prop        | Type                                                                          | Default     |
| ----------- | ----------------------------------------------------------------------------- | ----------- |
| `variant`   | `"default" \| "secondary" \| "destructive" \| "outline" \| "ghost" \| "link"` | `"default"` |
| `className` | `string`                                                                      | -           |
