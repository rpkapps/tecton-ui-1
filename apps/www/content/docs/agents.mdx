`@tecton/react` ships two things for coding agents: one [Agent Skill](https://agentskills.io), distributed with [TanStack Intent](https://github.com/TanStack/intent), and a `tecton` command that looks components up. The skill is short and always relevant: the import and prop conventions, the checks every file has to pass, and when to run the command. The command answers one question at a time, so an agent reads only the guideline of the component it is about to use. Both travel with the package and update with it.

| | |
| --- | --- |
| `skills/tecton/SKILL.md` | The only skill: imports, prop conventions, the *Before you finish* checklist, how to use `tecton`. |
| `bin/tecton.mjs` | The `tecton` command. |
| `agent/` | The search index and one page per component, generated from the guidelines. |
| `guidelines/` | The sources: one guideline per component, `families.json` (families and their checklists) and `topics/` (rules, conventions, theming). |

Each guideline file has a "Use it when", "Do" and "Don't" section and is rendered twice: as the **Usage guidelines** section of the component's docs page, and as the page `tecton docs` prints.

## The `tecton` command

```bash title="Terminal"
npx tecton search "confirm before deleting a well"   # ranked components, import path, what each is not for
npx tecton docs alert-dialog,sonner                  # the guideline: Use it when, Not for, Do, Don't, checklist
npx tecton docs AlertDialogAction                    # any export resolves to its module
npx tecton docs icons                                # the oil & gas glyphs by name
npx tecton docs conventions                          # prop names, Root/Trigger/Content, render, state attributes
npx tecton docs theming                              # colour, tokens, modes, ThemeRoot, micro-frontends
npx tecton list                                      # every id with a one-line summary
npx tecton rules                                     # the rules every file follows
```

It runs on plain Node from `node_modules` — no network, no API key — and always matches the installed version. `--json` works on every command. The index is generated by `pnpm --filter @tecton/react agent:build`; a `notFor` entry is indexed under the component it points at, so "a confirmation that disappears on its own" finds `toast` although that phrase lives in `badge.md`. Retrieval accuracy is tracked in `packages/tecton-react/agent-eval/README.md`.

## Setting up a consuming app

Run Intent's installer from the application root. It finds the packages in `node_modules` that ship skills and writes a managed block (between `<!-- intent-skills:start -->` and `<!-- intent-skills:end -->`) into your agent config file (`CLAUDE.md`, `AGENTS.md`, `.cursorrules` or `.github/copilot-instructions.md`), telling the agent to run `intent list` and `intent load` before a substantial task.

```bash title="Terminal"
npx @tanstack/intent@latest install
```

Declare which packages' skills to surface in the root `package.json` (a workspace consumer writes `"workspace:@tecton/react"`):

```json title="package.json"
{
  "intent": {
    "skills": ["@tecton/react", "@tanstack/*"]
  }
}
```

Then:

```bash title="Terminal"
npx @tanstack/intent@latest list                        # available skills and their load commands
npx @tanstack/intent@latest load @tecton/react#tecton   # prints SKILL.md
npx @tanstack/intent@latest stale                       # has an installed skill fallen behind?
```

The skill describes intended usage rather than enforcing it: its *Before you finish* list (repeated at the end of each `tecton docs` page) is the self-check an agent runs against the file it just wrote.
