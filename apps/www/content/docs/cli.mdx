title: CLI & updates
description: How the generated components are managed with the shadcn CLI, and how to update them without losing the Tecton theme.

This page is for the maintainers of the library; applications never run the shadcn CLI for components (they import `@tecton/react`). Everything under `packages/tecton-react/src/components`, `src/hooks` and `src/lib` is generated by the shadcn CLI and **never edited by hand**. The Tecton look is applied through `tokens/tecton.map.json` → `globals.css` variables only, so updating a component is always a single CLI command.

## Registry mirror

The CLI reads `https://ui.shadcn.com/r`. In environments where that host is unreachable, the repository ships a mirror that builds the same registry from the pinned upstream commit:

```bash
scripts/registry-mirror.sh setup   # clone + build (once)
scripts/registry-mirror.sh serve & # http://127.0.0.1:4000
export REGISTRY_URL=http://127.0.0.1:4000/r
```

Unset `REGISTRY_URL` when the official host is reachable. The pinned commit and the exact generation commands are in `docs/UPSTREAM.md`.

## Updating a component

<Steps>

<Step>Preview the upstream diff</Step>

```bash
pnpm dlx shadcn@latest add button --diff button.tsx -c packages/tecton-react
```

<Step>Apply it</Step>

```bash
pnpm dlx shadcn@latest add button --overwrite -c packages/tecton-react
```

<Step>Re-apply the Tecton variables</Step>

The CLI may rewrite `globals.css` (for example when a component brings new variables). Re-run the token build, which patches only the variable values:

```bash
pnpm --filter @tecton/react tokens:build
pnpm --filter @tecton/react tokens:check
```

<Step>Verify nothing was hand-edited</Step>

```bash
pnpm generated:check   # runs `add <item> --diff` for all 60 items and expects no differences
```

</Steps>

## Adding a new shadcn component

```bash
pnpm dlx shadcn@latest add <name> -c packages/tecton-react
pnpm --filter www docs:sync   # pulls the upstream docs page + examples into this site
```

## Tecton components

Tecton-specific components live in `src/tecton` and are maintained in this repository. They compose the generated components (for example `StatusAlert` renders the shadcn `Alert`) and follow the same conventions (`data-slot`, `cva`, `cn`, React Aria primitives). They are published as registry items so consumers can also copy them with `npx shadcn@latest add @tecton/<name>`.

## Scripts

| Script | What it does |
| --- | --- |
| `pnpm build` | Builds the library type-check and the docs site |
| `pnpm --filter @tecton/react tokens:build` | Regenerates `tecton-theme.css`, patches `globals.css`, writes `docs/TOKEN-MAPPING.md` and the registry theme item |
| `pnpm --filter @tecton/react tokens:check` | Completeness, WCAG contrast and sanity checks of the mapping |
| `pnpm --filter @tecton/react icons:build` | Regenerates the icon components from `icons-src/` (falls back to Lucide) |
| `pnpm --filter @tecton/react registry:build` | Builds the `@tecton` registry into `apps/www/public/r` |
| `pnpm --filter www docs:sync` | Syncs the shadcn docs pages and examples for the React Aria base |
| `pnpm generated:check` | Diff every generated component against the registry |
