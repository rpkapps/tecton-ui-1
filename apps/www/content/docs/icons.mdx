Tecton UI gives you **two icon sets**:

- **Tecton icons** (`@tecton/react/icons`) — the 131 icons of the design system,
  including the domain glyphs (wells, horizons, seismic, drill bits…). Every icon is a
  React component taking `size`, `strokeWidth`, `className` and the usual SVG props,
  plus `variant="outlined" | "filled"`.
- **Lucide** (`lucide-react`) — the general-purpose set the components use internally
  for chevrons, check marks and close buttons. Use it for anything the Tecton set does
  not cover.

```tsx
import { SearchIcon } from "lucide-react"
import { WellIcon, SeismicIcon } from "@tecton/react/icons"

<Button>
  <WellIcon data-icon="inline-start" /> New well
</Button>
<SeismicIcon variant="filled" size={20} />
```

<Callout title="Sizing and spacing">
  Inside a button, an input group or a menu item, mark the icon with
  `data-icon="inline-start"` or `data-icon="inline-end"` instead of adding margin: the
  component then owns the gap, and the icon stays aligned at every size.
</Callout>

## Tecton glyphs inside the components

The components reach for Lucide internally. If you want them to render Tecton glyphs
too — a Tecton check mark in every checkbox, a Tecton chevron in every select — alias
`lucide-react` to the compatibility module in your bundler:

```ts title="vite.config.ts"
export default defineConfig({
  resolve: {
    alias: {
      "lucide-react": "@tecton/react/icons/lucide-compat",
    },
  },
})
```

The compat module re-exports every Lucide name the components use, mapped to the
matching Tecton icon where one exists and to Lucide otherwise, so nothing goes missing.
The alias is all-or-nothing and affects your own `lucide-react` imports as well.

## Missing a glyph?

The set is the design system's icon export, so it is not extended per application. If
you need a glyph Tecton does not have, use the closest Lucide icon and raise the gap
with the design system.
