Tecton UI is consumed as the **package** `@tecton/react`: components, Tecton components, icons and the theme are all imported from it and are not installed one by one. **Blocks** are the exception: they are starting points meant to be copied into your application, so they are published in a shadcn registry.

## Package

`@tecton/react` is a private workspace package. It is not published to the public npm registry; consume it from the monorepo (`workspace:*`), from a packed tarball, or from a private registry.

### Peer requirements

- React 19
- Tailwind CSS v4 (the package ships Tailwind sources, not compiled CSS)
- A bundler that resolves `package.json` `exports` (Vite, Next.js, TanStack Start all do)

### Stylesheet

Import the theme once. It contains Tailwind, the shadcn runtime styles, the Tecton tokens and the theme variables:

```css title="src/styles/app.css"
@import "@tecton/react/globals.css";
```

The stylesheet already declares `@source` for the package and for `apps/**`; if your app lives elsewhere, add your own `@source` directive after the import.

### Dark mode

Tecton is dark-first. Add the `dark` class to `<html>` (for example with `next-themes` and `attribute="class"`). Without the class you get the Tecton light theme.

```tsx title="app.tsx"
import { ThemeProvider } from "next-themes"

export function App({ children }) {
  return (
    <ThemeProvider attribute="class" defaultTheme="dark" enableSystem>
      {children}
    </ThemeProvider>
  )
}
```

### Usage

```tsx
import { Button } from "@tecton/react/components/button"
import { Badge } from "@tecton/react/components/badge"
import { WellIcon } from "@tecton/react/icons"

export function Example() {
  return (
    <div className="flex items-center gap-2">
      <Button>
        <WellIcon data-icon="inline-start" /> New well
      </Button>
      <Badge variant="success">Active</Badge>
    </div>
  )
}
```

### One import for everything

Every component, hook, utility and icon is *also* exported from the package
root, so the whole surface can be pulled from a single module:

```tsx
import { Button, Badge, Panel, WellIcon, useIsMobile, cn } from "@tecton/react"
```

The two forms cost the same in a production build. The package marks its
JavaScript side-effect-free, so a bundler drops everything you never
reference: importing `Button` through the root barrel and through
`@tecton/react/components/button` produce the same output to within rounding
(27.7 kB gzipped either way, measured with Vite), and adding `WellIcon` adds
0.6 kB rather than the whole icon set. Use whichever reads better — the
subpaths are what the shadcn CLI writes into the blocks it copies.

Where the root entry does matter is **Module Federation**. Shared modules are
declared one `shared` key at a time, so per-component subpaths mean dozens of
keys to declare, version and keep in sync across every remote. The root entry
collapses them to one:

```ts title="rspack.config.ts"
new ModuleFederationPlugin({
  shared: {
    react: { singleton: true, requiredVersion: "^19" },
    "react-dom": { singleton: true, requiredVersion: "^19" },
    // one entry, not one per component
    "@tecton/react": { singleton: true },
  },
})
```

Share it as a `singleton`. Two copies of Tecton in one page mean two copies of
the React Aria context that the overlays, the shell and the shortcut registry
read across a remote boundary — a menu that opens behind its trigger, or a
shortcut the host never receives. For the same reason, give each remote its own
overlay container with [`PortalProvider`](/docs/tecton/portal): it is built for
pages that mount several isolated React roots.

<Callout title="A federated share is all-or-nothing">
  Tree-shaking is your build's, not the share's. The chunk behind a `shared`
  key has to serve every remote that might ask for it, so the whole surface
  ships — roughly 500 kB gzipped, icons included. It is fetched once for the
  page and reused by every remote, which is the trade you make when you
  collapse the subpaths into a single key. Nothing changes for applications
  that import `@tecton/react` normally.
</Callout>

The root entry is generated from the component, hook, utility, Tecton and icon
modules by `pnpm barrel:build`, and `pnpm barrel:check` (wired into CI) fails
when a newly added component is missing from it.

## Blocks (shadcn registry)

Blocks are full compositions (panels, dashboards, forms, tables) that you copy into your application and adapt. The docs site serves them as a shadcn registry named `@tecton`. Point your `components.json` at it and add a block with the CLI; the copied files import the components from `@tecton/react`, so the package must already be installed.

```json title="components.json"
{
  "registries": {
    "@tecton": "https://<your-docs-host>/r/{name}.json"
  }
}
```

```bash
npx shadcn@latest add @tecton/dashboard-01
```

Every block on the [Blocks](/blocks) page shows its command. For a private host add `headers` to the registry entry (`"@tecton": { "url": "…", "headers": { "Authorization": "Bearer ${TECTON_TOKEN}" } }`).
