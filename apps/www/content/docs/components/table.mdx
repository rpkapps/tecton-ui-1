## Usage

```tsx lineNumbers
import {
  Table,
  TableBody,
  TableCaption,
  TableCell,
  TableHead,
  TableHeader,
  TableRow,
} from "@tecton/react/components/table"
```

```tsx lineNumbers
<Table>
  <TableCaption>A list of your recent invoices.</TableCaption>
  <TableHeader>
    <TableRow>
      <TableHead className="w-[100px]">Invoice</TableHead>
      <TableHead>Status</TableHead>
      <TableHead>Method</TableHead>
      <TableHead className="text-right">Amount</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableCell className="font-medium">INV001</TableCell>
      <TableCell>Paid</TableCell>
      <TableCell>Credit Card</TableCell>
      <TableCell className="text-right">$250.00</TableCell>
    </TableRow>
  </TableBody>
</Table>
```

## Composition

Use the following composition to build a `Table`:

```text
Table
├── TableCaption
├── TableHeader
│   └── TableRow
│       ├── TableHead
│       ├── TableHead
│       ├── TableHead
│       └── TableHead
├── TableBody
│   ├── TableRow
│   │   ├── TableCell
│   │   ├── TableCell
│   │   ├── TableCell
│   │   └── TableCell
│   └── TableRow
│       ├── TableCell
│       ├── TableCell
│       ├── TableCell
│       └── TableCell
└── TableFooter
```

## Size and stripes

Set `size="sm"` for a compact table: a shorter header and rows and smaller text, for dense data that is scanned rather than read. Set `striped` to put every even body row on an alternate surface, which helps the eye follow a wide row across its columns. Hover and selected rows keep their own fill over the stripe, and the footer is never striped.

<ComponentPreview name="table-size" />

```tsx
<Table size="sm" striped>
  …
</Table>
```

## Virtualized

Set `virtualized` on a table of hundreds of rows or more. The body then mounts only the rows in view, so a table of thousands renders, scrolls and sorts as fast as a short one. The table fills its parent and scrolls in it, so give the parent a bounded height (`h-80`, or `min-h-0 flex-1` in a flex column) and put the border and rounding on the parent too. The header sticks to the top while the rows scroll.

Pass the rows' data as `items` and render one row with a function: it is called only for the rows in view, so a new sort or filter renders a screenful rather than every row. Plain `TableRow` children work too, but every one of them is created on each render.

- **Row height:** the table measures it from the rows it renders, so `size="sm"` and the default size both work, and a switch between them is picked up. Within one table the rows must be one height: keep cells on one line.
- **Column widths:** the columns are locked in px at the width of their content when first laid out (the header and the first rows), so they do not jump as different rows scroll into view. The space left goes to the columns of text, the last one taking the rest; a column of controls only (a checkbox, a drag handle) stays as narrow as its control. In a container too narrow for them all, the table scrolls sideways. Values that no longer fit end with an ellipsis: give a column a width when its values vary in length. A table you make `table-fixed` with your own widths (column resizing) keeps them.
- **Focus:** a row whose checkbox or link has focus stays mounted when it scrolls out of view.
- **Screen readers:** they hear the true size, because the table carries `aria-rowcount` and each row `aria-rowindex`.
- **Striping:** with `striped`, each row keeps its stripe as rows mount and unmount. Hand-written `nth-child` striping (`[&_tbody_tr:nth-child(even)]`) shifts with the mounted rows and flickers, so use the prop.

<ComponentPreview name="table-virtualized" />

```tsx
<div className="h-80 overflow-hidden rounded-md border">
  <Table virtualized>
    <TableHeader>…</TableHeader>
    <TableBody items={readings}>
      {(reading) => <TableRow key={reading.depth}>…</TableRow>}
    </TableBody>
  </Table>
</div>
```

## Usage guidelines

### Use it when

- Records of the same shape have to line up in columns: invoices, wells, run results.
- A footer totals the columns, or a caption names the table; the rows are read, compared, selected or opened, with sorting and paging from TanStack Table on these parts.

### Not for

- sorting, filtering, paging or column visibility over the rows: use [TanStack Table](/docs/components/data-table)
- a list of rows with media, a title and actions rather than columns: use [Item](/docs/components/item)
- rows or columns the user drags into another order: use [Reorderable](/docs/tecton/reorderable)

### Do

<DoList>

<Do>

Compose plain HTML: `Table` > `TableHeader` > `TableRow` > `TableHead`, `TableBody` > `TableRow` > `TableCell`, optional `TableFooter` and `TableCaption`.

</Do>

<Do>

Set `size="sm"` for a compact table of dense data, and `striped` to put every even body row on an alternate surface; hover and selected rows keep their fill over the stripe.

</Do>

<Do>

Open a record from a link in its identifying cell.

</Do>

<Do>

For hundreds of rows or more, set `virtualized`, give the parent a bounded height (`h-96`, with the border) and pass `items` with a render function to `TableBody`; rows are one height within the table.

</Do>

<Do>

Show an empty result as `Empty` in place of the table, or as `TableBody empty={…}` (one row across every column) when the header must stay; keep `className` on the parts to alignment and width (`text-end`, `w-24`).

</Do>

<Do>

Give text-heavy columns (well name, remarks) a minimum width on `TableHead`; they never collapse when the panel narrows.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="A table built from divs and grid classes">

<Wrong>

```tsx
<div className="grid grid-cols-2 text-sm">
  <div className="bg-zinc-100 px-4 py-3 font-medium">Well</div>
  <div className="bg-zinc-100 px-4 py-3 font-medium">Status</div>
  <div className="px-4 py-3">34/10-A-12</div>
  <div className="px-4 py-3">Producing</div>
</div>
```

</Wrong>

<Correct>

```tsx
<Table>
  <TableHeader>
    <TableRow><TableHead>Well</TableHead><TableHead>Status</TableHead></TableRow>
  </TableHeader>
  <TableBody>
    <TableRow><TableCell>34/10-A-12</TableCell><TableCell>Producing</TableCell></TableRow>
  </TableBody>
</Table>
```

</Correct>

The grid emits no table semantics, so assistive technology reads a stream of unassociated cells with no row or column count, and `bg-zinc-100` is stock Tailwind the reset palette emits no CSS for — the header band is `bg-table-header` on `TableHead`.

</Dont>

<Dont severity="HIGH" title="Density and stripes from classes">

<Wrong>

```tsx
<Table className="text-xs [&_td]:py-1 [&_tbody_tr:nth-child(even)]:bg-surface-alt">{rows}</Table>
```

</Wrong>

<Correct>

```tsx
<Table size="sm" striped>{rows}</Table>
```

</Correct>

Hand-written classes miss the header's height, paint the stripe over the hover and selected fill, and shift as a virtualized table mounts and unmounts rows, so the stripes flicker while it scrolls. `size` and `striped` set every part and keep each row on its stripe.

</Dont>

<Dont severity="HIGH" title="Activating a row with onClick">

<Wrong>

```tsx
<TableRow onClick={() => openWell(well.id)}>
  <TableCell>{well.name}</TableCell>
</TableRow>
```

</Wrong>

<Correct>

```tsx
<TableRow>
  <TableCell><Link href={`/wells/${well.id}`}>{well.name}</Link></TableCell>
</TableRow>
```

</Correct>

A `tr` has no role, no tab stop and no Enter key, so the row opens with a mouse only. A link in the identifying cell is reachable, announced and middle-clickable.

</Dont>
