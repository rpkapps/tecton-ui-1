# Blocks

Ready-made compositions of Tecton components for the oil & gas / subsurface domain (wells, horizons, facies, field development alternatives). Each block is a folder: `page.tsx` default-exports a full-page composition usable as a route and named-exports its reusable parts, `components/*.tsx` hold those parts, and `data.ts` carries mock data and domain types so the block renders without a backend. `index.ts` exports the `blocks` list (`name`, `title`, `description`, `category`, lazy `component`) that the docs gallery renders.

Blocks import components from `@tecton/react/components/*` and `@tecton/react/tecton/*`, icons from `lucide-react`, use only theme tokens and Tecton palette steps (chart series use `var(--chart-n)`), are responsive and dark-first, and follow the Tecton prop conventions (`onClick`, `disabled`, `value` / `onValueChange`, `render`). They type-check under `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` on top of `strict`, so a project with those options can copy a block verbatim.

`registry:build` (`scripts/registry-build.mts`) publishes each folder as a `registry:block` and fails when a folder has no `index.ts` entry or no `page.tsx`, when a file imports a package that is not in `KNOWN_DEPENDENCIES` (besides `@tecton/react` and `react`), or when a file that calls a hook, creates a context or passes an event handler does not start with `"use client"`.
