`@tecton/react` ships [Agent Skills](https://agentskills.io) alongside its components, using [TanStack Intent](https://github.com/TanStack/intent). A skill is a short, versioned document that tells an agent how to use one part of the library — the props, the variants, the mistakes an agent's shadcn-on-Radix prior would otherwise lead it into. Skills travel with the package: update `@tecton/react`, and the guidance updates with it.

## What ships

Nineteen skills live at `packages/tecton-react/skills/<name>/SKILL.md` in the package source. Four are hand-written (`tecton`, `core`, `react-aria`, `theming`); the rest are generated per component family from the guideline files described below, one per family, so every one of the package's eighty modules is covered.

| Skill | Covers |
| --- | --- |
| `tecton` | The lean entry point: the React Aria prop map, the finish checklist, and how to look components up with the `tecton` command (below) instead of loading family skills. |
| `core` | Import paths, the reset Tailwind palette, semantic tokens versus Tecton steps, and variants own styling. Load before writing any Tecton markup. |
| `react-aria` | The Radix-to-React-Aria prop map: `onPress`, `isDisabled`, `isSelected`, `selectedKey`, `isOpen`, and what replaces `asChild`. |
| `theming` | How colour reaches the screen: the shadcn CSS variables, palette steps, dark-first, `ThemeRoot`, and micro-frontend scoping. |
| `choose-component` | The decision table across every family; maps a need to one component, its import path, and the family skill to load next. |
| `labels` | Badge, Chip and ChipGroup, CountBadge, Kbd. |
| `feedback` | Alert, toast, Empty, and FieldError. |
| `overlays` | Dialog, AlertDialog, Sheet, Drawer, Popover, HoverCard, Tooltip. |
| `selection` | Select, Combobox, NativeSelect, RadioGroup, ToggleGroup, Tabs, Command. |
| `actions` | Button, LinkButton, Link, ButtonGroup, Toggle, DropdownMenu, ContextMenu, CopyButton, ActionBar. |
| `progress` | Progress, CircularProgress, Meter, Spinner, Skeleton. |
| `surfaces` | Card, Panel, Item, PageHeader, AppShell, Separator. |
| `forms` | Field, Input, Textarea, Select, Checkbox, Switch, Slider, InputGroup, InputOTP, Label, and TanStack Form wiring. |

Every generated skill is distilled from the same **guideline files** — one Markdown file per component in `packages/tecton-react/guidelines/`, each with a "Use it when", "Do" and "Don't" section. Those files are rendered twice: as the **"Usage guidelines"** section you see on every component's docs page, and, grouped by family, into the skill table above. Change a guideline once and both the docs page and the shipped skill pick it up.

## Looking components up with `tecton`

The package also ships a `tecton` command that answers one question at a time, so an agent reads the guideline of the component it is about to use rather than a whole family skill:

```bash title="Terminal"
npx tecton search "confirm before deleting a well"   # ranked components, import path, what each is not for
npx tecton docs alert-dialog,sonner                  # the usage guideline: Use it when, Not for, Do, Don't
npx tecton docs AlertDialogAction                    # any export resolves to its module
npx tecton docs icons                                # the oil & gas glyphs by name
npx tecton rules                                     # the rules every file follows (the core skill)
```

It runs on plain Node from `node_modules` — no network, no API key — and always matches the installed version. A search prints about 450 tokens and a guideline 550 to 1,100, against 3,000 to 7,000 for a family skill. Pair it with the `tecton` skill (`intent load @tecton/react#tecton`, or copy `node_modules/@tecton/react/skills/tecton/SKILL.md` into your agent's skills folder), which carries the prop map and the checklist and tells the agent when to search.

The index behind `search` is generated from the guideline files by `pnpm --filter @tecton/react agent:build`. A `notFor` entry is indexed under the component it points at, so "a transient confirmation" finds `toast` even though that phrase lives in `badge.md`. Retrieval and end-to-end agent results are in `packages/tecton-react/agent-eval/README.md`.

## Setting up a consuming app

Run Intent's installer from the root of your application:

```bash title="Terminal"
npx @tanstack/intent@latest install
```

It scans your `node_modules` for packages that ship Intent skills, then writes (or updates) a managed block in an agent config file — `CLAUDE.md`, `AGENTS.md`, `.cursorrules` or `.github/copilot-instructions.md` — delimited by `<!-- intent-skills:start -->` / `<!-- intent-skills:end -->` markers, so re-running `install` later updates the block instead of duplicating it. The block tells your agent to run `intent list` before a substantial task and `intent load <package>#<skill>` when one matches.

<Callout title="Declare an allowlist">
  Without an `intent.skills` array in your root `package.json`, Intent surfaces every skill it
  finds and warns that a future version will require an explicit allowlist. Once the array
  exists, only the listed packages are surfaced and the rest are reported as hidden, so an
  unrelated dependency's skills don't leak in by accident. To pick up `@tecton/react`'s skills
  from an application that depends on it, add:

  ```json title="package.json"
  {
    "intent": {
      "skills": ["@tecton/react", "@tanstack/*"]
    }
  }
  ```

  A workspace consuming `@tecton/react` as `workspace:*` lists it as `"workspace:@tecton/react"`
  instead. The `@tanstack/*` entry picks up TanStack's own published skills (Router, Query,
  Table, …) the same way.
</Callout>

Once installed, discover and load skills directly:

```bash title="Terminal"
npx @tanstack/intent@latest list
npx @tanstack/intent@latest load @tecton/react#core
```

`list` prints every skill available locally with its description and load command; `load` prints one skill's full `SKILL.md` body to stdout for the agent to read.

## Optional: Claude Code hooks

`npx @tanstack/intent@latest hooks install` wires two Claude Code hooks so an agent can't skip the step above:

- **A session catalog.** On session start, a `SessionStart` hook runs `intent list` and injects the result as additional context, so the model sees which skills exist before it writes anything.
- **An edit gate.** A `PreToolUse` hook on `Write`, `Edit`, `MultiEdit` and `NotebookEdit` blocks the edit until that session has run `intent list` or `intent load` at least once, then lets subsequent edits through.

Hooks are entirely **opt-in**: `@tecton/react` does not install them, `intent install` does not install them, and this repository does not run `hooks install` on your behalf. They write to `.claude/settings.json` (or your home directory with `--scope user`), so run the command yourself if you want the gate enforced rather than advisory.

## Keeping skills current

Skills are versioned with the package: each `SKILL.md` records the `@tecton/react` version it was built from and lists the source files (guidelines, docs pages, component source) it was distilled from. Run `npx @tanstack/intent@latest stale` to check whether an installed skill has fallen behind either its declared version or its sources.

## Restyling and imports

Skills describe intended usage rather than enforcing it: the `core` skill's "Before you finish" list is the self-check an agent runs against the file it just wrote.
