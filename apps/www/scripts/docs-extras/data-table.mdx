## Tecton recipes

Tecton ships no `DataTable` component: build tables with [TanStack Table](https://tanstack.com/table/latest) and the `Table` components, as the guide above does. Each recipe below is a self-contained starting point built on `useTable`.

### Playground

Every recipe below at once, on up to 100,000 wells: switch between virtual scrolling and pages, compact and default rows, a flat list and a tree, and turn selection, column resizing, column reordering and row reordering on and off. Sort by any column header. The readout reports how long each click took to paint. A sort and a manual row order exclude each other: sorting by a column turns row reordering off, and turning row reordering on clears the sort. In pages mode, pick 10, 20, 40 or 100 rows per page.

### Density and alternating rows

Density is nothing more than Tailwind classes on the `Table`: an emphasised header (`[&_thead]:bg-muted`), alternating rows (`[&_tbody_tr:nth-child(even)]:bg-surface-alt`) and, for the compact variant, shorter rows and smaller text (`[&_th]:h-8 [&_td]:py-1 text-xs`).

### Row selection

`Table` is a plain HTML table, so selection is TanStack's `rowSelection` state: add a display column with a `Checkbox` in the header (`checked` when every row is selected, `indeterminate` when some are, `onCheckedChange` → `toggleAllRowsSelected`) and one in each cell (`row.getIsSelected()` / `row.toggleSelected`), and mark selected rows with `data-state="selected"`. Summarise the selection below the table.

### Column resizing

Register `columnSizingFeature`, keep the `columnSizing` state in React and put a `TableColumnResizer` (from `@tecton/react/tecton/table-column-resizer`) on the end edge of each `TableHead` (`className="relative"`, `style={{ width: header.getSize() }}`). Give the `Table` `table-fixed`, the total width (`table.getTotalSize()`) and `minWidth: "100%"`, leave the last column's width unset so it takes the space left, and let cells `truncate`. The limits come from `defaultColumn` (`minSize`, `maxSize`) or each column's own; `resetValue={column.columnDef.size}` is what Enter and a double click go back to. The resizer is a focusable separator: the arrow keys resize too, mirrored in a right-to-left table.

<ComponentPreview name="data-table-column-resize" align="start" />

`TableColumnResizer` is a focusable separator named `Resize {label}`. ArrowRight widens and ArrowLeft narrows (mirrored in a right-to-left table), with steps four times as large while Shift is held; Home sets `min`, End sets `max`, and Enter or a double click sets `resetValue`. Escape during a drag puts the width back. At rest it is a short line in the middle of the header between columns; dragging draws a guide down the table at the new edge, with a chip that shows the width.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number` | - | The column's width in px (controlled). |
| `defaultValue` | `number` | `150` | The initial width, when not controlled. |
| `onValueChange` | `(value: number, eventDetails) => void` | - | Called with each new width. `eventDetails.reason` is `"drag"`, `"keyboard"` or `"reset"`. |
| `onValueCommitted` | `(value: number, eventDetails) => void` | - | Called once a drag ends, and after each key. |
| `min` | `number` | `48` | The narrowest width. |
| `max` | `number` | `1000` | The widest width. |
| `step` | `number` | `8` | The arrow keys' step in px. Shift multiplies it by four. |
| `resetValue` | `number` | - | The width that Enter and a double click go back to. |
| `label` | `string` | - | The column's name, so the resizer is named `Resize {label}`. |
| `disabled` | `boolean` | `false` | Turns the resizer off. |

### Column reordering

Register `columnOrderingFeature` and keep the `columnOrder` state, starting with every column's id. Wrap the `Table` in a [Reorderable](/docs/tecton/reorderable) with `orientation="horizontal"`, render each movable header as a `ReorderableItem` with `render={<TableHead />}` and `dragHandle={false}`, and write the new order back to `columnOrder`. A header has no room for a grip, so it is its own handle: drag it from anywhere (a sort button inside it keeps its clicks), or Tab to it, press Enter or Space and pick the gap with the arrow keys. A column that must stay put (the identifying column, the selection column) is a plain `TableHead` left out of the `Reorderable`'s `value`.

<ComponentPreview name="data-table-column-reorder" align="start" />

### Row reordering

Keep the rows in React state, list their ids as the `Reorderable`'s `value`, render each row as a `ReorderableItem` (`render={<TableRow />}`) with a `ReorderableHandle` in its first cell, and reorder the data in `onValueChange`. Drag the handle, or press Enter or Space on it and pick the gap with the arrow keys. A sorted table has no manual order: hide the handles while a sort is applied, or clear the sort first.

### Tree table

Register `rowExpandingFeature` with `createExpandedRowModel()` and pass `getSubRows` (here fields → platforms → wells). In the first column, indent the cell by `row.depth` (`paddingInlineStart`, 1.25rem a level) and put a chevron button, styled like a Tree View row's, before the name of each row that `getCanExpand()`, with `aria-expanded` and an "Expand …" / "Collapse …" name; leaves keep the chevron's space so names line up. `toggleAllRowsExpanded` drives an Expand all / Collapse all button. For a hierarchy without columns, use a [Tree View](/docs/tecton/tree-view).

### Virtual scrolling

For thousands of rows, set `virtualized` on the `Table` and give its parent a bounded height (here `h-96`, with the border). Pass `items={table.getRowModel().rows}` to `TableBody` and render one row with a function: only the rows in view are rendered, so sorting 10,000 rows renders a screenful. The header sticks while the rows scroll, the columns keep their first widths, and the row height is measured, so the Default / Compact switch works as it does on a short table. Rows must be one height within the table. For page-sized chunks instead, use [pagination](#pagination).

**Fast sorting.** TanStack's own sorted row model calls a comparator, and through it `row.getValue`, about 2 · n · log n times: 3.4 million calls for 100,000 rows. The helper below goes in the same `sortedRowModel` slot. It reads each value once, turns each column into integer ranks in natural order (like `alphanumeric`), and sorts them with the engine's native typed-array sort. It keeps a column's ranks, so the other direction, or that column again later, is a single native sort, and it works out the ranks in idle time before the first click. It does not read a column's own `sortFn`, `invertSorting` or `sortUndefined`, so keep `createSortedRowModel()` for columns that need them. `Reorderable` sees only the rows in view, so reordering a virtualized table moves rows within the visible window.

### Virtual tree table

A tree table of thousands of rows combines the two recipes above. `table.getRowModel().rows` holds only the open rows, flattened in order with their `depth`, so pass it as `items` to a `virtualized` table: expanding a field adds its rows to the scroll range, and Expand all opens 13,040 rows while only a screenful is rendered. A chevron that has focus keeps its row mounted while it scrolls out of view. The columns keep the widths they are first laid out with, so give the Name column room for the deepest indent (`w-[45%]` on its `TableHead`).
