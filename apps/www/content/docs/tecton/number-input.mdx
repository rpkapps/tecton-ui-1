## Usage

```tsx
import { NumberInput } from "@tecton/react/tecton/number-input"
```

```tsx
<Field>
  <FieldLabel htmlFor="td">Planned TD</FieldLabel>
  <NumberInput id="td" value={depth} onValueChange={setDepth} min={0} />
</Field>
```

The value is a number, or `null` while the field is empty. `onValueChange` receives the number as it is typed, as it is stepped and when the field is emptied; the text is formatted when the field loses focus. Numbers are typed and shown in the locale of the [`TectonProvider`](/docs/tecton/provider): `1.234,5` in German, `1,234.5` in English.

The field is an `Input` with a decrease and an increase button at its end, the ghost icon buttons of an [`InputGroup`](/docs/components/input-group). It is a text field, not an `<input type="number">`, so the browser draws no spinners of its own. The buttons are left out of the tab order: the keyboard steps in the field.

| Key | Action |
| --- | --- |
| <Kbd>↑</Kbd> <Kbd>↓</Kbd> | Step by `step`. |
| <Kbd>Shift</Kbd> + <Kbd>↑</Kbd> <Kbd>↓</Kbd> | Step by `largeStep`. |
| <Kbd>Home</Kbd> <Kbd>End</Kbd> | Go to `min` or `max`, when they are set. |

## Minimum, maximum and step

`min` and `max` bound the value: what is typed past them is clamped, and the button that would go further is disabled at the bound. `step` (1 by default) is what the buttons and arrows change the value by, `largeStep` (10) what they change it by with Shift held.

## Units and formatting

`format` takes `Intl.NumberFormatOptions`: a unit, a currency, a percentage, the fraction digits. The unit is shown and parsed back, so the value stays a plain number: `3250`, not `"3,250 m"`. A percentage is held as a fraction (`0.215` for 21.5 %).

<ComponentPreview name="number-input-format" />

```tsx
<NumberInput
  value={depth}
  onValueChange={setDepth}
  format={{ style: "unit", unit: "meter", maximumFractionDigits: 1 }}
/>
```

## In a Field, with an error

`NumberInput` takes `id`, `aria-invalid` and `aria-describedby` on its text field, like `Input`: point `FieldLabel htmlFor` at it, set `aria-invalid` on it and `data-invalid` on the `Field`, and describe it with the `FieldError`. To report a value outside `min` / `max` rather than clamp it, set `allowOutOfRange`: what is typed is kept as it is, while the buttons and arrows still stay within the bounds.

## Variants and states

`variant` sets the surface, as on `Input`: `outline` in forms, `filled` in dense panels, `text` for inline editing. `size="sm"` makes it as tall as a small `SelectTrigger`, for a compact toolbar, and `steppers={false}` leaves the buttons out where the field is narrow (the page field of a [Data Table](/docs/components/data-table#datatablepagination)). A disabled field is dimmed with its buttons; a read-only one hides them.

## Usage guidelines

### Use it when

- The user types a quantity: a depth, a count, a rate, a percentage, a page number, often with a unit (metres, %, currency) shown in the locale's format.
- The value has bounds or a natural increment the user steps through with − and +, or the arrow keys.

### Not for

- free text, or digits that are not a quantity (a well name, an identifier, a phone number): use [Input](/docs/components/input)
- a one-time code typed one character per box: use [InputOTP](/docs/components/input-otp)
- a value picked by dragging along a scale: use [Slider](/docs/components/slider)

### Do

<DoList>

<Do>

Hold a number: `value` / `defaultValue` are `number | null` (`null` while empty) and `onValueChange(value, eventDetails)` reports each change.

</Do>

<Do>

Bound and step it with `min`, `max`, `step` and `largeStep` (Shift); Home and End go to the bounds.

</Do>

<Do>

Show units and decimals with `format` (`Intl.NumberFormatOptions`); the value stays a plain number and the locale is the `TectonProvider`'s.

</Do>

<Do>

Wire it like `Input`: `id` with `FieldLabel htmlFor`, `aria-invalid` with `data-invalid` on the `Field` and the message in `FieldError`; set `allowOutOfRange` when a value past `min` / `max` must be reported rather than clamped.

</Do>

<Do>

Match the form with `variant="outline" | "filled" | "text"` and `size="default" | "sm"`; `className` sets width and placement only.

</Do>

</DoList>

### Don't

<Dont severity="HIGH" title="An Input with type=&quot;number&quot;">

<Wrong>

```tsx
<Input id="td" type="number" min={0} value={depth} onChange={(e) => setDepth(e.target.value)} />
```

</Wrong>

<Correct>

```tsx
<NumberInput id="td" min={0} value={depth} onValueChange={setDepth} />
```

</Correct>

The browser draws its own unstyled spin buttons, the value arrives as a string, and a comma decimal typed in a German or French locale is rejected as invalid. (`NumberInput` has no `onChange` either: its text is formatted, so `Number("3,250")` would be `NaN`.)

</Dont>

<Dont severity="HIGH" title="Hand-built − and + buttons in an InputGroup">

<Wrong>

```tsx
<InputGroup>
  <InputGroupInput id="choke" value={String(choke)} onChange={(e) => setChoke(Number(e.target.value))} />
  <InputGroupAddon align="inline-end">
    <InputGroupButton size="icon-xs" onClick={() => setChoke(choke + 2)}>
      <PlusIcon />
    </InputGroupButton>
  </InputGroupAddon>
</InputGroup>
```

</Wrong>

<Correct>

```tsx
<NumberInput id="choke" value={choke} onValueChange={setChoke} min={8} max={128} step={2} />
```

</Correct>

The hand-built buttons have no accessible name, ignore the bounds, sit in the tab order and leave the arrow keys, Shift, Home and End doing nothing.

</Dont>

<Dont severity="MEDIUM" title="A percentage held as the number shown">

<Wrong>

```tsx
<NumberInput id="porosity" defaultValue={21.5} format={{ style: "percent" }} />
```

</Wrong>

<Correct>

```tsx
<NumberInput id="porosity" defaultValue={0.215} format={{ style: "percent", maximumFractionDigits: 1 }} />
```

</Correct>

A percent format multiplies by 100, so `21.5` shows as "2,150%", and percent formatting rounds to whole percents unless `maximumFractionDigits` says otherwise.

</Dont>

<Dont severity="MEDIUM" title="A range error that clamping never shows">

<Wrong>

```tsx
<NumberInput id="wd" max={6000} value={depth} onValueChange={setDepth} aria-invalid={(depth ?? 0) > 6000} />
```

</Wrong>

<Correct>

```tsx
<NumberInput id="wd" max={6000} allowOutOfRange value={depth} onValueChange={setDepth} aria-invalid={(depth ?? 0) > 6000} />
```

</Correct>

Without `allowOutOfRange` a typed 7200 is clamped to 6000 as it is typed, so the check never fails and the user's number is silently replaced.

</Dont>

{/* guidelines:end */}

## API Reference

### NumberInput

The field's outer element carries `data-slot="number-input"` and `className`; the bordered group is `number-input-group` (with `data-variant`), the text field `number-input-input`, and the buttons `number-input-decrement` and `number-input-increment` (`data-disabled` at a bound). Every other prop of an `<input>` (`placeholder`, `aria-*`, `autoFocus`, `enterKeyHint`, `onKeyDown`, `onFocus`, `onBlur`) and `ref` go to the text field.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `number \| null` | - | The value, controlled; `null` is empty. |
| `defaultValue` | `number \| null` | `null` | The value it starts with, uncontrolled. |
| `onValueChange` | `(value: number \| null, eventDetails) => void` | - | Called with each new value. `eventDetails.reason` is `"input-change"`, `"input-clear"`, `"input-blur"`, `"input-paste"`, `"keyboard"`, `"increment-press"` or `"decrement-press"`. |
| `min` | `number` | - | The smallest value. |
| `max` | `number` | - | The largest value. |
| `step` | `number` | `1` | What the buttons and arrow keys change the value by. |
| `largeStep` | `number` | `10` | What they change it by with Shift held. |
| `format` | `Intl.NumberFormatOptions` | - | How the value is shown and parsed, in the provider's locale. |
| `allowOutOfRange` | `boolean` | `false` | Keep a typed value outside `min` / `max` instead of clamping it. |
| `variant` | `"outline" \| "filled" \| "text"` | `"outline"` | The surface, as on `Input`. |
| `size` | `"default" \| "sm"` | `"default"` | The height: `Input`'s, or that of a small `SelectTrigger` and `Button`. |
| `steppers` | `boolean` | `true` | The decrease and increase buttons; without them the value is typed and stepped with the keys. |
| `disabled` | `boolean` | `false` | Ignores input; dims the field. |
| `readOnly` | `boolean` | `false` | Shows the value without changing it; hides the buttons. |
| `required` | `boolean` | `false` | A value must be entered before the form is submitted. |
| `name` | `string` | - | Submits the value with a form, under this name. |
| `id` | `string` | - | The text field's id, for `FieldLabel htmlFor`. |
| `placeholder` | `string` | - | Shown while the field is empty. |
| `className` | `string` | - | On the outer element: width and placement. |
