This page is for the maintainers of the library; applications import `@tecton/react` and never run the shadcn CLI for components. Everything under `packages/tecton-react/src/components`, `src/hooks` and `src/lib` is generated by the CLI and **never edited by hand**. It is installed from the Tecton style `base-tecton` (the `tecton` preset on shadcn's `base` base), so updating a component is one CLI command. The pinned commit and the full generation commands are in `docs/UPSTREAM.md`.

## The Tecton style

shadcn authors every preset (Vega, Nova, …) as a CSS file of Tailwind `@apply` lists that its registry build inlines into the component sources. Tecton is one more preset, in `scripts/registry-mirror/overlay/`:

- `style-tecton.css` — `style-vega.css` with the Tecton deviations (solid 2px focus ring, flat controls, buttons that lighten on hover and press, Tecton tab and toggle colours) and the class lists of the extra variants;
- `tecton.patch` — registers the style and patches upstream sources: variant axes on `alert`, `badge`, `separator`, `input`, `textarea` and the `select` trigger, `data-variant` / `data-size` on `button`, the Tecton portal container on every overlay, logical corners on `button-group`, the Tecton tab and toggle colours, tabs that follow their `orientation` and select on arrow keys, an `AlertDialogAction` that closes the prompt, a focus-keeping `calendar`, pagination links announced as links, `aria-label` on the `slider` thumbs, outlined status colours on `sonner`, physical sides and `cookieName` on the `sidebar` (and no built-in keyboard shortcut), and classes outside a `className` moved into a `cva` on `calendar` and `input-otp`. The full list is in `docs/UPSTREAM.md`.

The installed files contain plain Tailwind class strings; `globals.css` keeps only the Tecton values of the shadcn variables.

## Registry mirror

`base-tecton` exists only here, so the CLI always reads from a local mirror that clones shadcn/ui at the pinned commit, applies the overlay and builds the style:

```bash
scripts/registry-mirror.sh setup   # clone + install + overlay + build (once)
scripts/registry-mirror.sh serve & # http://127.0.0.1:4000
export REGISTRY_URL=http://127.0.0.1:4000/r
```

## Updating a component

Run the CLI with `packages/tecton-react/dist/` absent.

```bash
pnpm dlx shadcn@4.21.0 add button --diff button.tsx -c packages/tecton-react   # preview
pnpm dlx shadcn@4.21.0 add button --overwrite -c packages/tecton-react          # apply
pnpm --filter @tecton/react use-client:restore   # the CLI drops some "use client" directives
pnpm tokens:build && pnpm tokens:check           # re-apply the Tecton variable values
pnpm generated:check                             # every item matches the registry
```

## Changing the Tecton style

Edit the class lists in `overlay/style-tecton.css`. A new variant axis also needs a change to the upstream source: edit it in the mirror clone (`apps/v4/registry/bases/base/ui/`) and run `scripts/registry-mirror.sh export` to refresh `tecton.patch`. Then:

```bash
scripts/registry-mirror.sh build   # re-applies the overlay, builds base-tecton (restart serve)
pnpm dlx shadcn@4.21.0 add <item> --overwrite -c packages/tecton-react
pnpm --filter @tecton/react use-client:restore
pnpm generated:check
```

A Tecton look for an existing shadcn component is always a variant in the overlay, never a second component.

## Bumping upstream

Update the commit in `docs/UPSTREAM.md` and run `scripts/registry-mirror.sh setup`. The overlay is applied with a 3-way merge, so an upstream change to the same lines is a conflict in the mirror clone rather than a silent failure. Port upstream's `style-vega.css` changes into `style-tecton.css`, resolve `tecton.patch` and `export` it, then rebuild, re-add every item with `--overwrite` and run `use-client:restore`, `tokens:build`, `generated:check` and `docs:sync`.

## Adding a shadcn component

```bash
pnpm dlx shadcn@4.21.0 add <name> -c packages/tecton-react
pnpm --filter @tecton/react use-client:restore
pnpm docs:sync   # pulls the upstream docs page and examples into this site
```

Add a usage guideline in `packages/tecton-react/guidelines/<name>.md`. Tecton additions to a synced page live in `apps/www/scripts/docs-extras/<name>.mdx`; the sync inserts them before the upstream API reference.

## Tecton components

A Tecton component exists only when shadcn has no counterpart (Chip, TreeView, Meter, Stat, Panel, AppShell…). They live in `src/tecton`, compose the generated components and follow their conventions (`data-slot`, `cva`, `cn`, the same prop names).

## Scripts

| Script | What it does |
| --- | --- |
| `scripts/registry-mirror.sh setup / build / serve / export` | Clone, overlay + build, serve the `base-tecton` registry, write the overlay patch back |
| `pnpm generated:check` | Diffs every generated file against the registry |
| `pnpm --filter @tecton/react use-client:restore` / `use-client:check` | Restores / verifies the `"use client"` directives |
| `pnpm tokens:build` / `pnpm tokens:check` | Regenerates the theme and `docs/TOKEN-MAPPING.md` / checks completeness and contrast |
| `pnpm --filter @tecton/react icons:build` | Regenerates the icon components from `icons-src/tecton/` |
| `pnpm registry:build` | Builds the `@tecton` blocks registry into `apps/www/public/r` |
| `pnpm docs:sync` | Syncs the shadcn docs pages and examples of the `base` base |
