Upstream shadcn has the conversation layer (`Message`, `Bubble`, `MessageScroller`, `Attachment`)
but no composer, so this one is Tecton's, following the survey of chat composers in
`docs/research/composer.md`.

## Usage

```tsx
import {
  Composer,
  ComposerField,
  ComposerHint,
  ComposerInput,
  ComposerStatusMessage,
  ComposerSubmit,
  ComposerToolbar,
} from "@tecton/react/tecton/composer"
```

```tsx
<Composer status={status} onStop={stop} onSubmit={({ text }) => send(text)}>
  <ComposerField>
    <ComposerInput />
    <ComposerToolbar>
      <ComposerSubmit />
    </ComposerToolbar>
  </ComposerField>
  <ComposerHint />
  <ComposerStatusMessage />
</Composer>
```

## Keyboard

| Where | Key | Does |
| --- | --- | --- |
| Textarea | <Kbd>Enter</Kbd> | Sends (a new line with `submitMode="mod-enter"`) |
| Textarea | <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd> | A new line |
| Textarea | <Kbd>⌘</Kbd>/<Kbd>Ctrl</Kbd> + <Kbd>Enter</Kbd> | Sends, in either mode |
| Textarea, while an IME composes | any | Nothing: the Enter that confirms a conversion never sends |
| Textarea, while a reply arrives | <Kbd>Esc</Kbd> | Stops the reply, and announces it |
| Textarea, caret on the first line | <Kbd>↑</Kbd> | Loads the previous message from `history` |
| Textarea, browsing `history`, caret on the last line | <Kbd>↓</Kbd> | Loads the next message; past the newest, the draft comes back |
| Textarea, commands listed | <Kbd>↑</Kbd> <Kbd>↓</Kbd> | Moves through the commands |
| Textarea, commands listed | <Kbd>Enter</Kbd> / <Kbd>Tab</Kbd> | Picks the command instead of sending |
| Textarea, commands listed | <Kbd>Esc</Kbd> | Closes the list until the text changes |
| Toolbar, suggestions | <Kbd>←</Kbd> <Kbd>→</Kbd> <Kbd>Home</Kbd> <Kbd>End</Kbd> | Moves between buttons: each row is one tab stop |
| Attachment chip | <Kbd>Delete</Kbd> / <Kbd>Backspace</Kbd> | Removes it; after the last, focus returns to the textarea |

The textarea stays enabled while a reply streams, so the next message can be drafted; it only
does not send until the chat is `ready` again, and focus stays in it after sending. Send is
`aria-disabled`, not disabled, while the box is empty, so it keeps its place in the tab order.
While a reply arrives, Stop takes its place, a second button with a name of its own, and focus
moves to it if it was on Send.

## Toolbar

`ComposerToolbar` takes any buttons as they are, a tooltip trigger included, and makes them one
tab stop moved through with the arrow keys; `ComposerSubmit` goes last.

```tsx
<ComposerToolbar>
  <Tooltip>
    <TooltipTrigger render={<InputGroupButton size="icon-xs" aria-label="Attach file" />}>
      <PaperclipIcon />
    </TooltipTrigger>
    <TooltipContent>Attach</TooltipContent>
  </Tooltip>
  <ComposerSubmit />
</ComposerToolbar>
```

## History

Pass the prompts the user has sent as `history`, oldest first, and the arrows walk through them
as in a terminal: <Kbd>↑</Kbd> on the first line the box shows loads the previous prompt with the
caret at its end, and keeps stepping back while it is unedited; <Kbd>↓</Kbd> on the last line
goes forward, and past the newest brings back the draft, even after a loaded prompt was edited.
Elsewhere the arrows move the caret. A run of the same prompt is shown once, `historyLimit` caps
how many of the newest are reached, and sending or a change from outside the textarea ends
browsing.

```tsx
<Composer
  history={turns.filter((turn) => turn.role === "user").map((turn) => turn.text)}
  onSubmit={({ text }) => send(text)}
>
```

A global shortcut that focuses the composer is the application's: give it a modifier and call
`focus` from `useComposer`.

## Announcements

`ComposerStatusMessage` is a polite status region for the composer's own changes: sent, stopped,
failed. The reply is the transcript's to announce: set `aria-busy` on `MessageScrollerContent`
while a reply streams, so screen readers read it once it is complete.

## Context and suggestions

`ComposerAttachments` shows what goes with the message besides its text as removable
[Chips](/docs/tecton/chip); mark an item's `icon` `data-icon="inline-start"`. A
`ComposerSuggestion` fills the box to edit, sends at once with `submit`, or hands the click to
`onSelect`.

## Commands

`ComposerCommands`, rendered inside `ComposerField`, lists commands above the field when the box
starts with a `/`. Typing narrows the list by the start of the command, then a word of its label;
commands stay in their `group`, each group where its best match ranks. With no match, or a slash
later in the text, the list stays closed and Enter sends. Picking empties the box and calls
`onCommand` with the command and the composer's `setValue`, `send` and `focus`.

```tsx
<ComposerField>
  <ComposerCommands
    items={[{ id: "new", command: "new", label: "Start a new conversation" }]}
    onCommand={(item) => startOver()}
  />
  <ComposerInput />
</ComposerField>
```

Focus stays in the textarea, which points at the list with `aria-controls` and at the active
command with `aria-activedescendant`; a mouse over a command makes it the active one. A polite
status says how many commands match (`countMessage` translates it).

## Usage guidelines

### Use it when

- The user writes to an assistant or agent: the message box under a transcript.
- A reply streams back and the user must be able to stop it, and keep typing the next message meanwhile.
- The message carries something besides its text (a selection, a file) that the user can see and remove before sending.
- The user types slash commands (`/new`, `/summarise`) in the message box and picks one from a list.

### Not for

- a one-line search or filter box: use [InputGroup](/docs/components/input-group)
- a form field for a long description: use [Textarea](/docs/components/textarea)
- a structured question with choices for the user to answer: use [Questionnaire](/docs/components/questionnaire)

### Do

<DoList>

<Do>

Pass the chat's `status` (`"ready" | "submitted" | "streaming" | "error"`) and `onStop`; `ComposerSubmit` swaps Send for Stop and Escape stops the reply.

</Do>

<Do>

Keep `ComposerHint` (visible, or `visible={false}`) so the textarea is described by its keys, and `ComposerStatusMessage` for sent, stopped and failed.

</Do>

<Do>

Pair it with a transcript whose `MessageScrollerContent` has `aria-busy` while a reply streams, so the reply is announced once, complete.

</Do>

<Do>

Pass the prompts already sent as `history` (oldest first) for ArrowUp and ArrowDown, and use `submitMode="mod-enter"` for long-form input.

</Do>

<Do>

Put extra context in `ComposerAttachments`, prompts to start from in `ComposerSuggestions`, slash commands in `ComposerCommands` inside `ComposerField`, and your own buttons (`InputGroupButton`, with or without a tooltip) straight into `ComposerToolbar` before `ComposerSubmit`.

</Do>

</DoList>

### Don't

<Dont severity="HIGH" title="Disabling the textarea while a reply streams">

<Wrong>

```tsx
<InputGroupTextarea disabled={status === "streaming"} value={text} onChange={(event) => setText(event.target.value)} />
```

</Wrong>

<Correct>

```tsx
<Composer status={status} onStop={stop} onSubmit={({ text }) => send(text)}>
  <ComposerField>
    <ComposerInput />
    <ComposerToolbar>
      <ComposerSubmit />
    </ComposerToolbar>
  </ComposerField>
</Composer>
```

</Correct>

A disabled textarea drops focus to the page body mid-reply and stops the user drafting; `Composer` keeps it enabled and simply does not send until the chat is ready.

</Dont>

<Dont severity="HIGH" title="An Enter handler that ignores IME composition">

<Wrong>

```tsx
<InputGroupTextarea onKeyDown={(event) => { if (event.key === "Enter" && !event.shiftKey) send() }} />
```

</Wrong>

<Correct>

```tsx
<Composer onSubmit={({ text }) => send(text)}>
  <ComposerField>
    <ComposerInput />
  </ComposerField>
</Composer>
```

</Correct>

The Enter that confirms a Japanese or Chinese conversion arrives as a keydown too, and in Safari after `compositionend`, so the half-typed message is sent; `ComposerInput` ignores `isComposing` and key code 229.

</Dont>

<Dont severity="MEDIUM" title="One send button whose label flips to Stop">

<Wrong>

```tsx
<InputGroupButton aria-label={busy ? "Stop" : "Send"} onClick={busy ? stop : send}>
  {busy ? <SquareIcon /> : <ArrowUpIcon />}
</InputGroupButton>
```

</Wrong>

<Correct>

```tsx
<ComposerToolbar>
  <ComposerSubmit />
</ComposerToolbar>
```

</Correct>

Screen readers do not reliably announce a name that changes under focus, and a click landing as the state flips stops a reply the user meant to send after; `ComposerSubmit` renders two named buttons and moves focus between them.

</Dont>

{/* guidelines:end */}

## API Reference

### Composer

A `form` that holds the value and the chat's state for its parts.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onSubmit` | `({ text }) => void` | - | The trimmed text; the box is cleared after. |
| `onStop` | `() => void` | - | Stops the reply; Escape and the Stop button call it. |
| `status` | `"ready" \| "submitted" \| "streaming" \| "error"` | `"ready"` | The chat's state. Nothing sends while `submitted` or `streaming`. |
| `submitMode` | `"enter" \| "mod-enter"` | `"enter"` | Which key sends. |
| `history` | `readonly string[]` | - | The prompts already sent, oldest first. |
| `historyLimit` | `number` | all | How many of the newest entries of `history` are reached. |
| `value`, `defaultValue`, `onValueChange` | `string` | - | The text, controlled or not. |
| `disabled` | `boolean` | `false` | Disables the whole composer. |

### Parts

| Part | Is |
| --- | --- |
| `ComposerField` | The bordered `InputGroup` around the textarea and the toolbar. |
| `ComposerInput` | The textarea, named "Message" and described by every `ComposerHint`. It grows with its text up to `max-h-48`, then scrolls. |
| `ComposerToolbar` | The row under the textarea: one tab stop, arrow keys between its buttons. |
| `ComposerSubmit` | Send, or Stop while busy. `sendLabel`, `stopLabel`. |
| `ComposerHint` | The keys that send (⌘ on an Apple keyboard, Ctrl elsewhere); `visible={false}` keeps it for screen readers only, `children` replaces the text. |
| `ComposerStatusMessage` | The polite status region; `messages` overrides its three texts. |
| `ComposerAttachments` | Removable chips: `items` (`id`, `label`, `description`, `icon`), `onRemove(id)`, `aria-label` ("Attachments"). |
| `ComposerSuggestions`, `ComposerSuggestion` | A toolbar of prompts: `value`, `submit` to send at once, `onSelect` to handle the click. |
| `ComposerCommands` | The `/` list: `items`, `onCommand(item, { setValue, send, focus })`, `countMessage`, `aria-label` ("Commands"). |
| `useComposer()` | `value`, `setValue`, `status`, `isBusy`, `canSubmit`, `submit`, `stop`, `focus`. |

A `ComposerCommandItem` has an `id` (unique), the `command` typed after the slash (one word), a
`label`, and optionally a `description`, a `group` and an `icon`.

The active command has `aria-selected="true"` and `data-highlighted`, for styling.
