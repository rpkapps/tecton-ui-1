Everything under `packages/tecton-react/src/components`, `src/hooks` and `src/lib` is
generated by the [shadcn](https://ui.shadcn.com) CLI and **never edited by hand**. The
components are installed from a Tecton **style**, `aria-tecton`, built the same way
upstream builds its own presets, so updating a component is always a single CLI command.

Applications never run any of this: they import `@tecton/react`.

## The Tecton style

shadcn authors every preset (Vega, Nova, …) as a CSS file of Tailwind `@apply` lists,
one rule per component part, and its registry build inlines those classes into the
component sources before they are published. Tecton is one more preset:
`scripts/registry-mirror/overlay/` holds

- `style-tecton.css` — a copy of `style-vega.css` with the Tecton deviations (solid 2px
  focus ring, flat controls, buttons that lighten on hover and press) and the class
  lists of the extra variants;
- `tecton.patch` — a small patch that registers the style and adds variant axes to six
  upstream sources: `alert` (`variant` success / warning / info and `appearance`
  default / outline / filled), `badge` (status `variant`s, `appearance` solid / outline,
  `size`), `separator` (`emphasis`), `input`, `textarea` and the `select` trigger
  (`variant` outline / filled / text); it also strips the hard-coded selected colours
  from `tabs` and the hard-coded hover colour from `toggle` so the style file can set
  the Tecton ones, makes `button-group` corners logical for RTL and gives `sonner`
  outlined status colours (the popover surface with a status border and text, matching
  `alert` with `appearance="outline"`).

Nothing of this ships to applications: the installed files contain plain Tailwind class
strings, exactly like the Vega ones did, and `globals.css` keeps only the Tecton values
of the theme variables.

## Registry mirror

Because `aria-tecton` exists only here, the CLI always reads from the local mirror,
which clones shadcn/ui at the pinned commit, applies the overlay and builds the style:

```bash
scripts/registry-mirror.sh setup   # clone + install + overlay + build (once, ~5 min)
scripts/registry-mirror.sh serve & # http://127.0.0.1:4000
export REGISTRY_URL=http://127.0.0.1:4000/r
```

The pinned commit and the exact generation commands are in `docs/UPSTREAM.md`.

## Updating a component

<Steps>

<Step>Preview the upstream diff</Step>

```bash
pnpm dlx shadcn@latest add button --diff button.tsx -c packages/tecton-react
```

<Step>Apply it</Step>

```bash
pnpm dlx shadcn@latest add button --overwrite -c packages/tecton-react
```

<Step>Re-apply the Tecton variables</Step>

The CLI may rewrite `globals.css` (for example when a component brings new variables).
Re-run the token build, which patches only the variable values:

```bash
pnpm --filter @tecton/react tokens:build
pnpm --filter @tecton/react tokens:check
```

<Step>Verify nothing was hand-edited</Step>

```bash
pnpm generated:check   # runs `add <item> --diff` for all 60 items and expects no differences
```

</Steps>

## Changing the Tecton style

<Steps>

<Step>Edit the overlay</Step>

Change the class lists in `scripts/registry-mirror/overlay/style-tecton.css`. A new
variant axis needs a change to the upstream source as well: edit it in the mirror clone
(`registry/bases/aria/ui/`) and run `scripts/registry-mirror.sh export` to refresh
`tecton.patch`.

<Step>Rebuild and re-install</Step>

```bash
scripts/registry-mirror.sh build            # re-applies the overlay, builds aria-tecton
pnpm dlx shadcn@latest add button --overwrite -c packages/tecton-react
pnpm generated:check
```

<Step>Document the variant for applications</Step>

The extra axes are Tecton's, so they are not in the upstream page. Put them in
`apps/www/scripts/docs-extras/<name>.mdx` and run `pnpm docs:sync` — see
[Docs site](/docs/contributing/docs-site#tecton-sections).

</Steps>

## Bumping upstream

Update the commit in `docs/UPSTREAM.md` and run `scripts/registry-mirror.sh setup`. The
overlay is applied with a 3-way merge, so an upstream change to the same lines shows up
as a conflict in the mirror clone instead of a silent failure. Port upstream's changes
to `style-vega.css` into `style-tecton.css`, resolve `tecton.patch` if needed and
`export` it, then rebuild, re-add all items with `--overwrite`, run `tokens:build`,
`generated:check` and `docs:sync`.

## Adding a new component

```bash
pnpm dlx shadcn@latest add <name> -c packages/tecton-react
pnpm --filter www docs:sync   # pulls the upstream docs page + examples into this site
```

## Tecton components

A Tecton component exists only when upstream has no counterpart (Chip groups,
CountBadge, TreeView, Meter, Stat, Panel, AppShell…). They live in `src/tecton`, compose
the generated components and follow the same conventions (`data-slot`, `cva`, `cn`,
React Aria primitives). A Tecton look for an existing component is never a second
component: it is a variant added through the overlay.

## Scripts

| Script | What it does |
| --- | --- |
| `pnpm build` | Builds the library type-check and the docs site |
| `scripts/registry-mirror.sh setup / build / serve / export` | Clone, overlay + build, serve the `aria-tecton` registry, write the overlay patch back |
| `pnpm --filter @tecton/react tokens:build` | Regenerates `tecton-theme.css`, patches `globals.css`, writes `docs/TOKEN-MAPPING.md` |
| `pnpm --filter @tecton/react tokens:check` | Completeness, WCAG contrast and sanity checks of the mapping |
| `pnpm --filter @tecton/react icons:build` | Regenerates the icon components from `icons-src/` (falls back to Lucide) |
| `pnpm --filter @tecton/react registry:build` | Builds the `@tecton` blocks registry into `apps/www/public/r` |
| `pnpm --filter www docs:sync` | Syncs the upstream docs pages and examples for the React Aria base |
| `pnpm generated:check` | Diff every generated component against the registry |
