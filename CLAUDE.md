# Working in this repository

- **Never hand-edit** `packages/tecton-react/src/components/**`, `src/hooks/**`, `src/lib/**` or the structure of `src/styles/globals.css`. They are generated by the shadcn CLI (`docs/UPSTREAM.md` has the pinned commit and commands). Update them with `shadcn add <item> --overwrite` and verify with `pnpm generated:check`.
- **Theme changes go through `packages/tecton-react/tokens/tecton.map.json`** (or `src/styles/tecton-tokens.css` for raw values), then `pnpm tokens:build && pnpm tokens:check`. Only the values of the shadcn CSS variables in `globals.css` may change; do not add `.style-*`, `[data-slot]` or `@layer` overrides for generated components.
- Tecton-specific behaviour belongs in `packages/tecton-react/src/tecton/` (shadcn conventions: `data-slot`, `cva`, `cn` from "cn", React Aria primitives, `onPress` not `onClick`).
- Docs pages under `apps/www/content/docs/components/` and `content/docs/utils/`, and examples starting with `// Synced from shadcn/ui`, are generated by `pnpm docs:sync`; edit `apps/www/scripts/sync-upstream-docs.mts` instead.
- Docs-site CSS (`apps/www/src/styles/app.css`) must stay inside `@layer base` / `@layer components` / `@utility`, and prose rules go through the `typeset` system only. Never add unlayered or bare-element rules: they would override the example components, which must render exactly as in an application (`data-not-typeset` opts a subtree out of prose styling).
- Icons under `src/icons/` are generated by `icons:build` from the vendored Tecton export in `icons-src/tecton/*.ts` (never edit either by hand; replace the export); the manifest is `icons/icons.json`.
- The shadcn CLI needs `REGISTRY_URL=http://127.0.0.1:4000/r` when `ui.shadcn.com` is blocked (`scripts/registry-mirror.sh serve`).
- Package manager: pnpm (workspace). Scripts run with bun (`/root/.bun/bin/bun` if not on PATH).
