## Usage

```tsx
import {
  createColumns,
  DataTable,
  DataTableActionBar,
  DataTableContent,
  DataTableFilter,
  DataTableFooter,
  DataTablePagination,
  DataTableSearch,
  DataTableToolbar,
} from "@tecton/react/tecton/data-table"
```

```tsx
const columns = createColumns<Well>([
  { id: "name", header: "Well" },
  { id: "status", header: "Status", type: "options", options: STATUSES },
  { id: "depth", header: "TD (m)", type: "number" },
  { id: "spud", header: "Spud date", type: "date" },
])

<DataTable items={wells} columns={columns} selectionMode="multiple" filterable pagination>
  <DataTableToolbar>
    <DataTableSearch />
    <DataTableFilter column="status" />
  </DataTableToolbar>
  <DataTableActionBar>
    <Button size="sm" onClick={shutIn}>Shut in</Button>
  </DataTableActionBar>
  <DataTableContent aria-label="Wells" />
  <DataTableFooter>
    <DataTablePagination pageSizes={[10, 25, 50]} />
  </DataTableFooter>
</DataTable>
```

Each item needs an `id` (or pass `itemToId`). Make the columns once, at module level or in a `React.useMemo`. Use [Table](/docs/components/table) for a short table that is read, not worked with.

## Composition

```text
DataTable
├── DataTableToolbar
│   ├── DataTableSearch
│   ├── DataTableFilter
│   ├── DataTableGroupBy
│   └── DataTableColumnsMenu
├── DataTableActionBar
├── DataTableActiveFilters
├── DataTableContent
│   └── DataTableRowActions (in a column's cell)
└── DataTableFooter
    └── DataTablePagination
```

The root holds the state and turns features on (`selectionMode`, `pagination`, `filterable`, `groupable`, `…Columns`); a part for a feature that is off renders nothing and warns in development.

A `DataTableFooter` right after `DataTableContent` is the table's last band, inside its border and below the totals row: its rows scroll above it in a virtualized table. Put `DataTablePagination` there. A second footer, or one placed elsewhere, is a plain row under the table.

## Columns

A column's `type` sets how its values are shown, aligned and sorted; `cell` draws your own content, and a column with `columns` is a group. With `reorderableColumns`, as here, drag a header to move its column (a grouped column moves among its group's, a group with its columns); a line shows where it will drop.

<ComponentPreview name="data-table-columns" align="start" />

| `type` | Align | Shown as | Sorted |
| --- | --- | --- | --- |
| `"text"` (default) | start | the text | natural, case-insensitive |
| `"number"` | end | `Intl.NumberFormat` with `format` | numerically |
| `"date"` | start | `Intl.DateTimeFormat` with `format` | chronologically |
| `"boolean"` | center | a check for `true` | `false` first |
| `"options"` | start | a [Badge](/docs/components/badge) per option | in `options` order |

Empty values sort last and show a muted dash ([Empty values](#empty-values)). Return raw numbers and `Date`s from `accessor`, not formatted text.

### Sorting by several columns

A click on a header sorts by that column alone; <Kbd>Shift</Kbd> + click (or <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd>) adds it as the next sort, or turns it round where it is. The table above starts sorted by Field, then MD: while two or more columns sort, each sorted header shows its place by the arrow, and screen readers hear it with the direction ("2 of 2 in sort order").

With a column menu (`resizableColumns`, `hideableColumns`, `pinnableColumns` or `groupable`), the menu does the same without the keyboard: while another column sorts, **Add to sort** with Ascending or Descending appends the column; on a column already in the sort, the group shows its place (**Sort order: 2 of 3**) and changes its direction there, and **Remove from sort** takes it out. **Sort ascending** and **Sort descending** still sort by the column alone, and **Clear sort** removes every sort.

```tsx
<DataTable
  items={wells}
  columns={columns}
  defaultView={{
    sorting: [
      { column: "field", direction: "ascending" },
      { column: "md", direction: "descending" },
    ],
  }}
>
```

`view.sorting` lists the sorts in order, first one first; in [server mode](#server-data) the server gets the whole list from `onViewChange`. `multiSort={false}` keeps the table to one sort: <Kbd>Shift</Kbd> + click sorts alone, the menus have no **Add to sort** and a view keeps its first sort.

## Hiding, pinning and reordering

`DataTableColumnsMenu` lists the columns to show, hide or pin; each header's menu has the same actions.

<ComponentPreview name="data-table-column-pinning" align="start" />

| Root prop | The user | View field | Column opt-out |
| --- | --- | --- | --- |
| `resizableColumns` | drags or fits a column's width | `columns.widths` | `resizable: false` |
| `reorderableColumns` | drags a header to a new place | `columns.order` | `reorderable: false` |
| `hideableColumns` | hides a column | `columns.hidden` | `hideable: false` |
| `pinnableColumns` | pins a column to the start or end | `columns.pinned` | `pinnable: false` |

Pinned cells are opaque in `var(--surface)`; a custom surface sets it: `className="bg-muted [--surface:var(--color-muted)]"`.

## Search and filters

`filterable` turns on `DataTableSearch`, a `DataTableFilter` per column and `DataTableActiveFilters`. The toolbar collapses its items into an overflow menu when it runs out of room.

<ComponentPreview name="data-table-filters" align="start" />

| `type` | Filter | Value in the view |
| --- | --- | --- |
| `text` | contains the text | `{ type: "text", value }` |
| `number` | minimum and maximum | `{ type: "number", min?, max? }` |
| `date` | a [date range picker](/docs/components/date-picker) | `{ type: "date", from?, to? }` |
| `boolean` | Any, Yes or No | `{ type: "boolean", value }` |
| `options` | a checkbox per option, with counts | `{ type: "options", values }` |

Each filter also offers "No value" (`empty: true`) for a column with empty values. Search matches the shown columns' display text, ignoring case and accents. A column's own `filter(item, value)` replaces its type's.

## Empty values

A value that is `null`, `undefined`, `""`, `NaN` or an invalid `Date` shows as a muted em dash in the column's alignment, which screen readers read as "No value". Return `null` from `accessor` for a missing value, never a placeholder such as "N/A". Some wells in the example above have no status, TD, spud date or subsea flag.

| Where | An empty value |
| --- | --- |
| Cell | A muted "—", read as "No value"; the column's `emptyValue` replaces it, `null` leaves the cell blank. |
| Custom `cell` | Gets the column's `emptyValue` in its details, to return when `text` is `""`. |
| Search, CSV | Empty text: never matched, an empty field. |
| Sorting | Last, ascending and descending. |
| Grouping | One group, "No value", last. |
| Totals | Left out of the built-in aggregates. |

```tsx
const columns = createColumns<Well>([
  { id: "operator", header: "Operator", emptyValue: "Unassigned" },
  {
    id: "report",
    header: "Report",
    cell: (well, { text, emptyValue }) => (text === "" ? emptyValue : <Link href={well.reportUrl}>{text}</Link>),
  },
])
```

While a row has no value in a column, its filter offers "No value": the last option of an options filter, apart, with its count; a checkbox under a text or number filter's fields and beside a date filter's Clear; a fourth choice after Any, Yes and No. It keeps the rows without a value besides those the rest of the filter keeps, or only those when the rest is unset, and its chip reads "Status: Producing, No value" or "TD (m): 1,000–2,000 or no value".

In the view it is `empty: true` on the filter's value. A value without it matches as before, so saved views keep working; in server mode, where the table sees only the loaded rows, "No value" is always offered and reaches `onViewChange` for the server to apply (`OR depth IS NULL`).

```ts
{ type: "number", min: 1000, max: 2000, empty: true } // 1,000 to 2,000, or no value
{ type: "options", values: [], empty: true } // no value only
{ type: "boolean", empty: true } // no value only
```

## Selection

`selectionMode="single"` or `"multiple"` adds a checkbox column. `DataTableActionBar` shows while rows are selected, with the count, Clear and your actions.

<ComponentPreview name="data-table-selection" align="start" />

| Prop | Does |
| --- | --- |
| `value` / `onValueChange` | The selected row ids. |
| `isItemDisabled` | Disables rows; `disabledBehavior="selection"` keeps them focusable and openable. |
| `onActivate(id, item)` | Called when a row opens: <Kbd>Enter</Kbd>, a double click, or a click while no row is selected. |
| `itemToHref` | Makes each row header a link, followed through the [TectonProvider](/docs/tecton/provider)'s router. |

Select all selects every row the view matches, on every page.

`itemToDisabledReason` says why a disabled row cannot be selected: the reason shows in a tooltip on its checkbox, on hover and when the arrow keys reach it (`disabledBehavior="selection"`), and screen readers announce it with the row.

## Row reordering

`reorderableRows` adds a drag handle at the start of each row. Drag it, or reach it with <Kbd>→</Kbd> and press <Kbd>Enter</Kbd>: <Kbd>↑</Kbd> / <Kbd>↓</Kbd> move it one place at a time, each place announced ("Insert between 34/7-D-2 and 2/8-C-3"), <Kbd>Enter</Kbd> drops and <Kbd>Escape</Kbd> cancels. `onRowOrderChange(ids, eventDetails)` gets every item's id in the new order: put `items` in that order.

<ComponentPreview name="data-table-row-reordering" align="start" />

```tsx
<DataTable
  items={jobs}
  columns={columns}
  reorderableRows
  onRowOrderChange={(ids) => setJobs(ids.map((id) => byId.get(id)!))}
>
```

- Rows move in the items' order: while the view sorts, searches, filters or groups, the handles are hidden (their column stays).
- On pages, a row moves within its page; in a virtualized table, the keyboard steps through every row.
- Flat lists only: off in a tree.

## Load more

For rows sent in batches, `hasMore` says more follow and `onLoadMore` loads the next batch: add it to `items`. Set `loading` while a batch is out, and `error` with `onRetry` when it fails: the error shows after the loaded rows, with Retry. Here the server sends 50 of 500 readings at a time: switch between loading on scroll and with a button, and turn on "Fail the next batch" to see the error.

<ComponentPreview name="data-table-load-more" align="start" />

```tsx
<DataTable
  items={rows}
  columns={columns}
  dataMode="server"
  rowCount={total}
  hasMore={rows.length < total}
  onLoadMore={loadNext}
  loading={isLoading}
  error={error}
  onRetry={loadNext}
  className="h-96"
>
  <DataTableContent aria-label="Meter readings" virtualized />
</DataTable>
```

`loadMore` sets how the next batch is asked for:

| `loadMore` | Next batch | Use it when |
| --- | --- | --- |
| `"scroll"` (default) | Loads as the end of the rows comes near, with loading rows after the last row. | The table has a bounded height (`virtualized`) or is the last thing on the page: the user only scrolls. |
| `"button"` | Loads when the user presses Show more, after the last row, beside "Showing 50 of 500" (of `rowCount` in server mode; "Showing 50 rows" without it). | Something follows the table (a footer, the page's next section) that loading on scroll would keep pushing away, or the user should decide when to load. |

With `"button"`, the button spins while the batch loads and keeps focus; once no more rows follow, focus moves to the first new row, and screen readers hear "Loaded 50 more rows". Load more is off with `pagination`, and in client mode while a search or filter is in effect: use server mode to load what matches.

## Server data

With `dataMode="server"`, the table reports each view and page change and shows the `items` the server returns; `rowCount` is the server's total. Here <Kbd>Shift</Kbd> + click a second header: `view.sorting` holds both sorts, in order, and the request below carries them.

<ComponentPreview name="data-table-server" align="start" />

| | Client | Server |
| --- | --- | --- |
| Sort, search, filter, page | the table | the server, from `onViewChange` / `onPageChange` |
| Option counts | from `items` | each option's `count` |
| "No value" filter | while a row has no value | always; `empty: true` in the filter |
| Totals, export | every matching row | the loaded rows |
| "Select all N" | every matching row | all matching: `eventDetails.allMatching.except` |

## The view

The sorting, search, filters, grouping and column layout are one JSON object: start from `defaultView`, or control it with `view` / `onViewChange`.

```tsx
<DataTable
  items={wells}
  columns={columns}
  defaultView={JSON.parse(savedView)}
  onViewChange={(view) => saveView(JSON.stringify(view))}
>
```

A saved view is reconciled with the columns: unknown or opted-out columns are dropped, never thrown on.

## Keyboard

The table is one tab stop; focus is on a row, or on a cell once the arrows move into the row.

| Key | Does |
| --- | --- |
| <Kbd>↓</Kbd> / <Kbd>↑</Kbd> | Next / previous row, or cell below / above |
| <Kbd>→</Kbd> / <Kbd>←</Kbd> | Into and between cells and their controls; opens / closes a tree row, group or detail row |
| <Kbd>Home</Kbd> / <Kbd>End</Kbd> | First / last row, or cell of the row |
| <Kbd>Ctrl</Kbd> / <Kbd>⌘</Kbd> + <Kbd>Home</Kbd> / <Kbd>End</Kbd> | First / last cell of the table |
| <Kbd>Page Up</Kbd> / <Kbd>Page Down</Kbd> | A screenful of rows |
| Letters | Next row whose row header starts with the text |
| <Kbd>Space</Kbd> | Selects or clears the row, or a group's rows |
| <Kbd>Shift</Kbd> + <Kbd>Space</Kbd> / <Kbd>↓</Kbd> / <Kbd>↑</Kbd> | Extends the selection |
| <Kbd>Ctrl</Kbd> / <Kbd>⌘</Kbd> + <Kbd>A</Kbd> | Selects every row |
| <Kbd>Escape</Kbd> | Clears the selection |
| <Kbd>Enter</Kbd> | Opens the row (`onActivate`, its link) |
| <Kbd>Enter</Kbd> / <Kbd>F2</Kbd> | Into a cell's field; <Kbd>Escape</Kbd> back to the cell |
| <Kbd>Enter</Kbd> on a header's sort button | Sorts by the column: ascending, descending, off |
| <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd> on a header's sort button | Adds the column to the sort, or turns it round there (`multiSort`) |
| <Kbd>Enter</Kbd> / <Kbd>Space</Kbd> on a header | Starts moving the column (`reorderableColumns`) |
| <Kbd>Enter</Kbd> / <Kbd>Space</Kbd> on a row's handle | Starts moving the row (`reorderableRows`): <Kbd>↑</Kbd> / <Kbd>↓</Kbd>, then <Kbd>Enter</Kbd> or <Kbd>Escape</Kbd> |
| <Kbd>←</Kbd> / <Kbd>→</Kbd> on a resizer | Narrows / widens the column; <Kbd>Enter</Kbd> keeps, <Kbd>Escape</Kbd> reverts |

## Accessibility

- A grid, or a treegrid with trees, details or groups.
- Name it with `aria-label` on `DataTableContent`.
- Rows named by their row header column.
- Sort, selection and result counts announced.
- Full `aria-rowcount` on pages and virtualized rows.
- Focus never drops to the page.

## RTL

Direction and locale come from the [TectonProvider](/docs/tecton/provider): columns, arrow keys and pinning mirror, and numbers, dates and the table's own texts are localized. Column headers are your own texts.

## Usage guidelines

### Use it when

- An application shows records in columns, a data grid of wells, work orders, run results or documents. Use `DataTable` for every such table, even one that only sorts today, so tables look and behave the same in every application.
- Rows are sorted, searched, filtered, grouped, selected, paged or opened, or the user hides, pins, resizes or reorders the columns.
- The rows are many (`virtualized`, or loaded in batches with `hasMore`: as the user scrolls, or from Show more with `loadMore="button"` when content follows the table), come page by page from a server (`dataMode="server"`), or form a hierarchy with columns (`itemToChildren`) or detail rows (`renderDetail`).

### Not for

- a short static table of a few rows that is only read, such as a spec sheet, a legend or the figures of a report: use [Table](/docs/components/table)
- a hierarchy that is browsed, with no columns: use [TreeView](/docs/tecton/tree-view)
- a list of rows with media, a title and actions rather than columns: use [Item](/docs/components/item)
- rows the user drags into an order of their own: use [Reorderable](/docs/tecton/reorderable)

### Do

<DoList>

<Do>

Make the columns once with `createColumns`, at module level or in a `React.useMemo`: each has an `id`, a plain-text `header` and a `type` (`text`, `number`, `date`, `boolean`, `options`) that sets the alignment, format, sort and filter. Return raw numbers and `Date`s from `accessor`, format with `format`, and use `cell(item, { text })` only to draw the value differently. Leave a missing value empty (`null` from `accessor`): the cell shows a muted em dash read as "No value", it exports as an empty field, sorts last, groups under "No value" and is offered as each filter's "No value". Change it per column with `emptyValue`; a `cell` of your own returns `emptyValue` from its details when `text` is `""`.

</Do>

<Do>

Turn features on at the root (`selectionMode`, `pagination`, `filterable`, `groupable`, `resizableColumns`, `reorderableColumns`, `hideableColumns`, `pinnableColumns`; sorting is on, by several columns with Shift + click or a column menu's "Add to sort", one only with `multiSort={false}`), then place their parts: `DataTableToolbar` with `DataTableSearch`, a `DataTableFilter column` per filter, `DataTableGroupBy` and `DataTableColumnsMenu`; `DataTableActiveFilters`; `DataTableContent`; `DataTableFooter` with `DataTablePagination`.

</Do>

<Do>

Name the table with `aria-label` on `DataTableContent`, open a row with `itemToHref` or `onActivate` on the root, say why a disabled row cannot be selected with `itemToDisabledReason`, put a row's commands in a `DataTableRowActions` in a column's `cell`, and the actions on the selected rows in `DataTableActionBar` (each in an `OverflowItem`; the bar shows the count and Clear itself).

</Do>

<Do>

Set `size="sm"` and `striped` on `DataTable` for dense data; show the states with `loading`, `error` with `onRetry`, and `empty` / `noResults` on `DataTableContent`.

</Do>

<Do>

With `dataMode="server"`, pass the page's `items`, `rowCount` and `loading`, and load from `onViewChange` (its `view.sorting` lists every sort, first one first), `onPageChange` and `onPageSizeChange`; keep a saved view with `defaultView` and `onViewChange`. A part of your own reads the table with `useDataTable()` (`value`, `clearSelection`, `exportCsv`).

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="A records table hand-built on Table">

<Wrong>

```tsx
const rows = [...wells].sort(byDepth).slice(page * 10, page * 10 + 10)
<Table>
  <TableHeader>
    <TableRow>
      <TableHead><Checkbox checked={allSelected} onCheckedChange={toggleAll} /></TableHead>
      <TableHead><button onClick={() => setSort("depth")}>Depth</button></TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>{rows.map((well) => <WellRow key={well.id} well={well} />)}</TableBody>
</Table>
<Button onClick={() => setPage(page + 1)}>Next</Button>
```

</Wrong>

<Correct>

```tsx
<DataTable items={wells} columns={columns} selectionMode="multiple" pagination>
  <DataTableContent aria-label="Wells" />
  <DataTableFooter>
    <DataTablePagination />
  </DataTableFooter>
</DataTable>
```

</Correct>

Every hand-built table sorts, selects and pages a little differently, with no `aria-sort`, no grid keyboard, no announcements and no selection across pages; `DataTable` gives every application the same table.

</Dont>

<Dont severity="HIGH" title="Formatting values inside a cell">

<Wrong>

```tsx
const columns = createColumns<Well>([
  { id: "depth", header: "Depth (m)", cell: (well) => <div className="text-end">{well.depth.toLocaleString()}</div> },
])
```

</Wrong>

<Correct>

```tsx
const columns = createColumns<Well>([
  { id: "depth", header: "Depth (m)", type: "number", format: { maximumFractionDigits: 0 } },
])
```

</Correct>

Without `type` the column is text: it sits at the start, sorts and filters as text and has no sum, and `toLocaleString()` formats in the browser's locale, not the provider's.

</Dont>

<Dont severity="HIGH" title="Placeholder text for missing values">

<Wrong>

```tsx
const columns = createColumns<Well>([{ id: "depth", header: "Depth (m)", type: "number", accessor: (well) => well.depth ?? "N/A" }])
```

</Wrong>

<Correct>

```tsx
const columns = createColumns<Well>([{ id: "depth", header: "Depth (m)", type: "number", accessor: (well) => well.depth }])
```

</Correct>

"N/A" is a value: it is drawn as text instead of the table's muted dash, read as "N/A" in every locale, written to the CSV, and the filters' "No value" does not find it.

</Dont>

## API Reference

### DataTable

The root `div`. Every `on…Change` gets the new value and `eventDetails` (`reason`, `event`, `cancel()`).

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `ReadonlyArray<T>` | - | The rows; in server mode, the view's page. |
| `columns` | `DataTableColumns<T>` | - | From `createColumns`. |
| `itemToId` | `(item: T) => string` | `String(item.id)` | A row's id. |
| `itemToChildren` | `(item: T) => ReadonlyArray<T> \| undefined` | - | Makes the rows a tree. |
| `itemToHref` | `(item: T) => string \| undefined` | - | Makes each row a link. |
| `isItemDisabled` | `(item: T) => boolean` | - | Disables rows. |
| `itemToDisabledReason` | `(item: T) => ReactNode \| undefined` | - | Why a disabled row cannot be selected: a tooltip on its checkbox. |
| `disabledBehavior` | `"all" \| "selection"` | `"all"` | What a disabled row cannot do. |
| `dataMode` | `"client" \| "server"` | `"client"` | Who sorts, filters and pages. |
| `rowCount` | `number` | - | Server mode: rows the view matches. |
| `loading` | `boolean` | `false` | Shows the loading state. |

### DataTablePagination

A rows-per-page [Select](/docs/components/select), the rows shown and [Pagination](/docs/components/pagination), for `pagination`; takes the props of a `div`. The page resets to 1 when the view changes. It stays on one line: as its width shrinks it drops the "Rows per page" label (kept as the Select's name), then the words of Previous and Next, then the pages but the current one and its neighbours, and below about 400 px shows "Page 3 of 5" between the arrows. An ellipsis, or "Page 3 of 5" at the narrowest, opens "Go to page": a popover with a page field and Go. Enter or Go opens that page, focus moving to its button; a page outside 1 to the last shows the field's error; the up and down arrows step through the pages; Escape closes it. Its controls keep their places as the page changes: each row of pages has as many slots on every page, the rows shown keep the width of their widest text, and the last page, short of rows, keeps the height of a full one, so the button under the pointer stays there.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `pageSizes` | `ReadonlyArray<number>` | the root's `pageSizes` | The page sizes offered; `[]` leaves the Select out. |

### DataTableView

```ts
type DataTableView = {
  sorting: ReadonlyArray<{ column: string; direction: "ascending" | "descending" }>
  search: string
  filters: Readonly<Record<string, DataTableFilterValue>>
  grouping: ReadonlyArray<string>
  columns: {
    order: ReadonlyArray<string>
    hidden: ReadonlyArray<string>
    widths: Readonly<Record<string, number>>
    pinned: { start: ReadonlyArray<string>; end: ReadonlyArray<string> }
  }
}

// `view` and `defaultView` take a DataTablePartialView: every part optional.
// `empty: true` is "No value": the rows without a value match too, or alone
// when the rest is unset (`value: ""`, no range, no `value`, `values: []`).
type DataTableFilterValue =
  | { type: "text"; value: string; empty?: boolean }
  | { type: "number"; min?: number; max?: number; empty?: boolean }
  | { type: "date"; from?: Date; to?: Date; empty?: boolean }
  | { type: "boolean"; value?: boolean; empty?: boolean }
  | { type: "options"; values: ReadonlyArray<string>; empty?: boolean }
  | { type: "custom"; value: unknown }
```
