## Usage

```tsx showLineNumbers
import {
  Card,
  CardAction,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "@tecton/react/components/card"
```

```tsx showLineNumbers
<Card>
  <CardHeader>
    <CardTitle>Card Title</CardTitle>
    <CardDescription>Card Description</CardDescription>
    <CardAction>Card Action</CardAction>
  </CardHeader>
  <CardContent>
    <p>Card Content</p>
  </CardContent>
  <CardFooter>
    <p>Card Footer</p>
  </CardFooter>
</Card>
```

## Composition

Use the following composition to build a `Card`:

```text
Card
├── CardHeader
│   ├── CardTitle
│   ├── CardDescription
│   └── CardAction
├── CardContent
└── CardFooter
```

## Spacing

In addition to the `size` prop, you can use the `--card-spacing` CSS variable to control the spacing between sections and the inset of card parts.

  name="card-spacing"
  previewClassName="h-[34rem]"

Use negative margins with `-mx-(--card-spacing)` to make content go edge to edge while keeping it aligned with the card inset. When the edge-to-edge content sits above a footer, use `-mb-(--card-spacing)` on `CardContent` to remove the section gap.

## Usage guidelines

### Use it when

- A self-contained piece of content stands on its own: a summary, a sign-in form, a media tile.
- The card is as tall as its content — it does not scroll and it is not part of the app chrome.
- It sits in a grid or a stack of siblings that should all look the same.

### Not for

- a titled tool surface whose body scrolls and whose footer stays put: use [Panel](/docs/tecton/panel)
- one row in a list of records: use [Item](/docs/components/item)
- the title block at the top of a page: use [PageHeader](/docs/tecton/page-header)
- rows with sorting, paging and selection: use [TanStack Table](/docs/components/data-table)

### Do

<DoList>

<Do>

Compose it: `CardHeader` with `CardTitle`, `CardDescription` and `CardAction`, then `CardContent`, then `CardFooter`.

</Do>

<Do>

Set density with `size="sm"`, or with the documented `[--card-spacing:--spacing(4)]` on `Card` when a design needs another step.

</Do>

<Do>

Divide sections with a bare `border-b` on `CardHeader` or `border-t` on `CardFooter`; the card adds the matching padding itself.

</Do>

<Do>

Bleed content to the edges with `-mx-(--card-spacing)`, so it still lines up with the card inset.

</Do>

<Do>

Keep `className` to placement and width (`w-full max-w-sm`): the card owns the surface, ring, radius and padding.

</Do>

</DoList>

### Don't

<Dont severity="HIGH" title="Re-declaring the card's own padding and shape">

<Wrong>

```tsx
<Card className="rounded-xl border border-gray-200 bg-white p-6 shadow-sm">
  <CardTitle>Reserves</CardTitle>
</Card>
```

</Wrong>

<Correct>

```tsx
<Card size="sm" className="w-full max-w-sm">
  <CardHeader>
    <CardTitle>Reserves</CardTitle>
  </CardHeader>
</Card>
```

</Correct>

`Card` pads itself through `--card-spacing` and its parts read the same variable, so `p-6` double-pads the header; `border-gray-200` is stock Tailwind, which Tecton resets to nothing, and `no-restyle` reports the colour, radius and padding.

</Dont>

<Dont severity="MEDIUM" title="A hand-drawn rule between header and content">

<Wrong>

```tsx
<Card>
  <CardHeader className="border-b border-gray-200 pb-4">
    <CardTitle>Alternative B</CardTitle>
  </CardHeader>
  <CardContent>4 wells, 1 template</CardContent>
</Card>
```

</Wrong>

<Correct>

```tsx
<Card>
  <CardHeader className="border-b">
    <CardTitle>Alternative B</CardTitle>
  </CardHeader>
  <CardContent>4 wells, 1 template</CardContent>
</Card>
```

</Correct>

`CardHeader` already carries `[.border-b]:pb-(--card-spacing)`, so the bare `border-b` picks up the themed border colour and the right padding, while `border-gray-200` emits no CSS and `pb-4` fights the spacing variable.

</Dont>

{/* guidelines:end */}

## API Reference

### Card

The `Card` component is the root container for card content.

| Prop        | Type                | Default     |
| ----------- | ------------------- | ----------- |
| `size`      | `"default" \| "sm"` | `"default"` |
| `className` | `string`            | -           |

### CardHeader

The `CardHeader` component is used for a title, description, and optional action.

| Prop        | Type     | Default |
| ----------- | -------- | ------- |
| `className` | `string` | -       |

### CardTitle

The `CardTitle` component is used for the card title.

| Prop        | Type     | Default |
| ----------- | -------- | ------- |
| `className` | `string` | -       |

### CardDescription

The `CardDescription` component is used for helper text under the title.

| Prop        | Type     | Default |
| ----------- | -------- | ------- |
| `className` | `string` | -       |

### CardAction

The `CardAction` component places content in the top-right of the header (for example, a button or a badge).

| Prop        | Type     | Default |
| ----------- | -------- | ------- |
| `className` | `string` | -       |

### CardContent

The `CardContent` component is used for the main card body.

| Prop        | Type     | Default |
| ----------- | -------- | ------- |
| `className` | `string` | -       |

### CardFooter

The `CardFooter` component is used for actions and secondary content at the bottom of the card.

| Prop        | Type     | Default |
| ----------- | -------- | ------- |
| `className` | `string` | -       |
