## Usage

```tsx
import {
  Reorderable,
  ReorderableHandle,
  ReorderableItem,
} from "@tecton/react/tecton/reorderable"
```

```tsx
const [order, setOrder] = React.useState(["a12", "b3", "c7"])

<Reorderable value={order} onValueChange={setOrder}>
  {order.map((id) => (
    <ReorderableItem key={id} value={id} label={names[id]}>
      {names[id]}
      <ReorderableHandle />
    </ReorderableItem>
  ))}
</Reorderable>
```

The order is yours: `value` lists the items' values, the items render in that order, and `onValueChange` hands back the whole new array after a drop.

## Composition

```text
Reorderable
└── ReorderableItem
    └── ReorderableHandle
```

`Reorderable` is a `div` that also holds the drop line and the keyboard drop targets. Each `ReorderableItem` renders a `div`, or the element you pass to `render`; its `ReorderableHandle` can sit anywhere inside it. With `dragHandle={false}` an item has no handle and is its own: it is dragged from anywhere, its buttons included. A press that moves drags the item, and a press that doesn't is still the button's click, so a column header's sort button keeps sorting. Only text fields keep their presses. The item is a Tab stop where Enter or Space starts a keyboard drag; on its buttons, Enter and Space still press them.

## Tables

Wrap the whole `Table`, not its body, and render each row with `render={<TableRow />}`. For columns, set `orientation="horizontal"` and render each header with `render={<TableHead />}` and `dragHandle={false}`: a header has no room for a grip, so the header itself is dragged and focused. The Data Table page has both recipes with TanStack Table: [row reordering](/docs/components/data-table#row-reordering) and [column reordering](/docs/components/data-table#column-reordering).

Items left out of the page, such as another page of rows or a hidden column, keep their place in `value`: a dropped item lands next to the item it was dropped beside.

To reorder both the rows and the columns of one table, put one `Reorderable` inside the other around the `Table`. An item belongs to the nearest `Reorderable` whose `value` holds it, so the column headers join the horizontal list and the rows the vertical one. The Data Table [playground](/docs/components/data-table#playground) does this.

## Grid

<ComponentPreview name="reorderable-grid" />

Set `orientation="grid"` for items in rows that wrap: a CSS grid of cards, or a wrapping flex row. Lay the items out with your own classes on `Reorderable` (`grid grid-cols-2 gap-3 sm:grid-cols-3`); the order is still one array, read row by row. The pointer drops before or after the card under it, and the line spans that card's row only. From the keyboard, Left and Right (or Tab) step through the gaps in reading order, and Up and Down jump to the nearest gap in the row above or below.

For tiles of several sizes, use `mode="swap"` below: in an order, the grid re-places every mixed-size tile after the moved one and can leave holes.

## Swap

<ComponentPreview name="reorderable-swap" />

With `mode="swap"` the layout stays put and the items swap places, like tiles on a dashboard. Render a `ReorderableSlot` for each entry of `value`, in order and keyed by its index, and put the item it holds inside; `value[i]` is the item of slot `i`, or `null` for an empty slot. Give each slot its size in the grid (`col-span-2 row-span-2`).

```tsx
const [layout, setLayout] = React.useState(["oil", "gas", null])

<Reorderable mode="swap" value={layout} onValueChange={setLayout} className="grid grid-cols-3 gap-3">
  {layout.map((id, index) => (
    <ReorderableSlot key={index} className={SPANS[index]}>
      {id && (
        <ReorderableItem value={id} label={names[id]} render={<Card />}>
          {names[id]}
          <ReorderableHandle />
        </ReorderableItem>
      )}
    </ReorderableSlot>
  ))}
</Reorderable>
```

Dragging an item over another slot swaps it with the item there as you hover: the other item glides into the dragged one's slot, and a plain placeholder (a tinted, dashed outline) shows where the dragged one will land, while its content travels with the pointer. Over an empty slot it moves there, and the slot it leaves shows as empty. Back over its own slot, everything returns. On the drop, the item under the pointer glides into its placeholder, taking the slot's size, and fades into the item there. Only the two slots change, whatever their sizes, so nothing else moves.

An item takes the size of its slot, including the slot it is shown in during a drag. Make the item a size container (`className="[container-type:size]"`) and show more when there is room: a wide slot's detail with `@min-[14rem]:grid`, a tall slot's list with `[@container(min-height:18rem)]:flex`, as the tiles above do.

## Keyboard and screen readers

- **Pointer:** press the handle (or the item, with `dragHandle={false}`) and drag. Near the edge of the scroll container (a table's, or the page) the list scrolls, up and down for rows and sideways for columns of a wide table. A finger on an item without a handle drags after a long press, so a quick swipe still scrolls. A line shows where the item will land. Escape cancels.
- **Keyboard:** focus the handle and press Enter or Space. The arrow keys (or Tab) move between gaps, each one announced ("Insert between B-3 and C-7"). Enter or Space drops and Escape cancels. The list scrolls to keep the aimed gap in view, clear of a sticky header. Focus returns to the moved item's handle.
- **Screen reader on a touch screen:** activating the handle turns every gap into a button. Double tap one to drop.
- **Swap:** Enter or Space starts with the item where it is ("Keep Pressure here"). The arrow keys move to the nearest slot wholly in that direction, the same row or column first, and Tab steps through the slots in order. Each slot is announced ("Swap with Alarms", "Move to empty slot 8") and shows its swap. Give an empty slot a `label` to announce it by name.

## Animation

A drop animates: the dropped item glides from where it was let go (from its old place, after a keyboard drop) into its new one, and the items it passes slide aside. The items move inside their list, so a table's scroll container still clips them and its sticky header stays on top, and the page stays interactive while they settle. Nothing moves when the user has asked for reduced motion.

Set `dropAnimation={false}` to drop without it:

```tsx
<Reorderable value={order} onValueChange={setOrder} dropAnimation={false}>
```

## Usage guidelines

### Use it when

- The user puts rows of a table in their own order: a drilling queue, a run sequence, a playlist of logs.
- The user moves the columns of a data table into the order they read them in.
- A short stack of items (steps, tracks, layers) has an order the user decides.
- The user arranges a grid of cards: equal cards put in order (`orientation="grid"`), or tiles of several sizes swapped between the fixed slots of a bento grid (`mode="swap"`).

### Not for

- open workspace tabs the user drags into another order: use [DocumentTabs](/docs/tecton/document-tabs)
- moving rows between folders of a hierarchy: use [TreeView](/docs/tecton/tree-view)
- sorting rows by a column's values: use [TanStack Table](/docs/components/data-table)

### Do

<DoList>

<Do>

Keep the order in state as an array of item values, pass it as `value`, render the items in that order and write `onValueChange`'s array back. With `mode="swap"`, `value[i]` is the item of slot `i` (or `null`): render a `ReorderableSlot` per entry, keyed by its index and sized from your layout data, with its item inside as a size container (`[container-type:size]`).

</Do>

<Do>

Wrap the whole `Table` in `Reorderable` and render each row as `ReorderableItem` with `render={<TableRow />}`, or each header with `render={<TableHead />}` and `orientation="horizontal"`.

</Do>

<Do>

Give every item a `label` (the row's or column's name) and a `ReorderableHandle` in a row; a column header gets `dragHandle={false}` instead and is dragged and focused itself, with no grip.

</Do>

<Do>

To reorder rows and columns of one table, nest the two `Reorderable`s around it: an item joins the nearest one whose `value` holds it.

</Do>

<Do>

Leave a column that must stay put (the identifying or selection column) out of `value` and render it as a plain `TableHead`; turn every handle off with `disabled` while a sort is applied.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="Hand-rolled drag events on table rows">

<Wrong>

```tsx
<TableRow draggable onDragStart={() => setDragged(well.id)} onDrop={() => move(dragged, well.id)}>
  <TableCell>{well.name}</TableCell>
</TableRow>
```

</Wrong>

<Correct>

```tsx
<ReorderableItem value={well.id} label={well.name} render={<TableRow />}>
  <TableCell><ReorderableHandle /></TableCell>
  <TableCell>{well.name}</TableCell>
</ReorderableItem>
```

</Correct>

Native drag events never fire from the keyboard, a screen reader or a touch screen, so the order cannot be changed without a mouse.

</Dont>

<Dont severity="HIGH" title="Reorderable placed inside the table body">

<Wrong>

```tsx
<TableBody>
  <Reorderable value={order} onValueChange={setOrder}>{rows}</Reorderable>
</TableBody>
```

</Wrong>

<Correct>

```tsx
<Reorderable value={order} onValueChange={setOrder}>
  <Table><TableBody>{rows}</TableBody></Table>
</Reorderable>
```

</Correct>

`Reorderable` renders a `div` holding the drop line and the keyboard drop targets, which is invalid inside `tbody` and breaks the row layout.

</Dont>

<Dont severity="HIGH" title="Reorder callbacks from other libraries">

<Wrong>

```tsx
<Reorderable items={order} onReorder={(from, to) => move(from, to)}>{rows}</Reorderable>
```

</Wrong>

<Correct>

```tsx
<Reorderable value={order} onValueChange={(next) => setOrder(next)}>{rows}</Reorderable>
```

</Correct>

The order is `value` and the whole new array arrives in `onValueChange`; `items` and `onReorder` are ignored, so nothing moves.

</Dont>

## API Reference

### Reorderable

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string[]`, or `(string \| null)[]` with `mode="swap"` | - | The items' values, in order; with `mode="swap"`, the item of each slot, `null` for an empty one (controlled). |
| `defaultValue` | same as `value` | `[]` | The initial value, when not controlled. |
| `onValueChange` | `(value, eventDetails) => void` | - | Called with the new value after a drop. `eventDetails.reason` is `"pointer"`, `"keyboard"` or `"virtual"`. |
| `mode` | `"insert" \| "swap"` | `"insert"` | `"insert"`: a drop moves the item into a gap. `"swap"`: the items sit in `ReorderableSlot`s and a drop swaps two of them. |
| `orientation` | `"vertical" \| "horizontal" \| "grid"` | `"vertical"` | Stacked items (rows), items side by side (columns), or items in rows that wrap (a grid of cards). Not used with `mode="swap"`. |
| `disabled` | `boolean` | `false` | Turns every handle off. |
| `dropAnimation` | `boolean` | `true` | Animates a drop: the dropped item glides into its place and the others slide aside. Never with reduced motion. |
| `render` | `ReactElement \| function` | `<div />` | Replaces the element. |

### ReorderableItem

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | - | The item's value in `value`. |
| `label` | `string` | - | The item's name, used for the handle (`Drag {label}`) and the announcements. |
| `dragHandle` | `boolean` | `true` | `false` makes the item its own handle (table column headers): dragged from anywhere, buttons included (a press without movement is still their click), focused with Tab, Enter or Space starts a keyboard drag. |
| `render` | `ReactElement \| function` | `<div />` | Replaces the element: `<TableRow />` or `<TableHead />` in a table. |

Carries `data-dragging` while it is dragged.

### ReorderableSlot

A fixed place of a `Reorderable mode="swap"`, rendered once per entry of `value`, in order, keyed by its index.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | - | The slot's name, announced for an empty slot (`Move to {label}`). |
| `render` | `ReactElement \| function` | `<div />` | Replaces the element. |

Carries `data-empty` when it holds no item (or a drag moves its item into an empty slot) and `data-drop-target` while a drag is aimed at it.

### ReorderableHandle

A ghost icon button with a grip icon, unless you pass children. Forwards `className`, `disabled` and the button's other props.
