## Usage

```tsx
import {
  Toolbar,
  Overflow,
  OverflowItem,
  OverflowLabel,
  OverflowDivider,
  OverflowSpacer,
  OverflowGroup,
  OverflowMenu,
} from "@tecton/react/tecton/overflow"
```

```tsx
<Toolbar aria-label="Well actions">
  <OverflowItem value="share" label="Share" icon={<ShareIcon />} priority={1} onClick={share}>
    <Button variant="outline">
      <ShareIcon data-icon="inline-start" />
      <OverflowLabel>Share</OverflowLabel>
    </Button>
  </OverflowItem>
  <OverflowDivider />
  <OverflowItem value="delete" label="Delete" variant="destructive" labelBehavior="keep" onClick={remove}>
    <Button variant="destructive">Delete</Button>
  </OverflowItem>
  <Button>New well</Button>
</Toolbar>
```

Wrap every control that may leave the row in an `OverflowItem`. Unwrapped children are fixed: they never leave, so the primary action goes in bare. Put the label text in an `OverflowLabel` so it can drop to icon-only; only an item whose control has an icon (an `svg`, `img` or `[data-icon]`) collapses. The `More` menu is rendered at the end automatically; `overflowBadge` on the row shows how many items it holds.

<Callout>
  `Toolbar` is a `role="toolbar"`: the arrow keys along its axis move between every visible control in it, whatever renders it (mirrored in right-to-left layouts, stopping at the ends), a text field keeps them until its caret reaches the edge, and Tab leaves the row. Use `Overflow` when the row is not a toolbar semantically (a breadcrumb, a chip row, a header with a tab list). Both need their items and dividers as direct children.
</Callout>

## Stages

The row gives up space one stage at a time and takes it back in reverse. The full contract, including the tie-break, group and focus rules, is in `docs/OVERFLOW-RULES.md` in the repository.

| Stage | What gives |
| --- | --- |
| 1 | Elastic items shrink to their minimum. |
| 2 | Labels drop; items with an icon become icon-only with a tooltip. Items with `labelBehavior="keep"` and text-only items stay as they are. |
| 3 | Items move into the More menu, lowest `priority` first, ties from the end of the row inward. |
| 4 | The host compacts its own summary (see [Action Bar](/docs/tecton/action-bar)). |
| 5 | Fixed items alone do not fit: the row wraps (`lastResort="wrap"`, default) or scrolls. |

Stage 2 collapses every label at once and brings them back only when every item fits again with its label, so the row never flickers between the two. Stage 3 is the only stage that moves items; nothing is ever reordered.

## Priority

`priority` decides who leaves first, never where an item sits. The menu keeps source order. `labels="always"` skips the icon-only stage.

## Other controls

Each item declares what it becomes in the menu with `overflow`. A button needs nothing: its menu item is built from `label`, `icon`, `shortcut` and `onClick`, and the item passes `onClick` and `disabled` on to its single control element too, so the handler is written once. Other controls pass their own menu form:

| Control | Overflow form |
| --- | --- |
| Toggle | `DropdownMenuCheckboxItem` bound to the same state |
| Dropdown trigger | `DropdownMenuSub` with the same items |
| Select | `DropdownMenuSub` with a `DropdownMenuRadioGroup` |
| Text input | `DropdownMenuItem` that opens a `Dialog` holding the same input |
| Anything else | Any menu content, or `overflow="never"` to keep it fixed |

An input is usually `elastic`: it shrinks between `min` and `max` before any label collapses. A dropdown trigger keeps its label (`labelBehavior="keep"`) so the chevron makes sense; give it a `Tooltip` yourself if you want one. An item whose own menu or popover is open is not hidden until it closes.

<ComponentPreview name="overflow-forms" align="start" />

A divider stays as long as something is visible on both sides of it and leaves once one side is empty; two dividers never show side by side (the last of them stays, beside what follows). In the menu it becomes a separator between the hidden items on either side of it. `OverflowGroup` renders its hidden members as a labelled menu section; `collapse="together"` moves the whole group at once.

## Vertical

`orientation="vertical"` lays the row out as a column and measures heights instead of widths: items leave from the bottom, the More menu sits at the bottom and opens to the side. A tool rail is icon-only already, so give it `labels="never"` and the tooltips show the labels from the start.

## Cost

One `ResizeObserver` per row observes the row and its direct children. Sizes are cached per element, hidden items keep their last size and are not measured again, and the visible set lives in a store outside React. Each pass is one walk over the row: a running total is reduced as items are hidden, so cost grows linearly with the number of items. Each item subscribes to its own visibility and the menu to the hidden list, so a resize that hides two items re-renders those two and the menu. A resize that changes nothing notifies nobody. Hidden items stay mounted (`display: none`), so their state survives, and the More menu reads their menu forms only when it opens, so a hidden item re-rendering costs nothing while the menu is closed.

## Usage guidelines

### Use it when

- A row of controls has to survive a container that gets narrow: a panel toolbar, a table header, a card's action row.
- The actions matter enough to stay reachable, so hiding them outright is not acceptable.
- The row is measured by its own width, not by a breakpoint — the same toolbar sits in a wide page and a 320 px aside.

### Not for

- two or three buttons welded into one control: use [ButtonGroup](/docs/components/button-group)
- actions that appear only while rows are selected: use [ActionBar](/docs/tecton/action-bar)
- every action behind one button from the start: use [DropdownMenu](/docs/components/dropdown-menu)

### Do

<DoList>

<Do>

Wrap every control that may leave the row in an `OverflowItem` with a stable `value`; leave the primary action unwrapped so it is fixed and never collapses.

</Do>

<Do>

Put the text in an `OverflowLabel` beside an icon and describe the menu entry with `label`, `icon`, `shortcut` and `onClick`; only an item with a `label` and an icon in its control goes icon-only, a text-only item keeps its label.

</Do>

<Do>

Decide who leaves first with `priority` (higher stays longer); the menu always keeps source order.

</Do>

<Do>

Use `Toolbar` with an `aria-label` when the row is a toolbar (arrow keys move between every visible control, Tab leaves it) and `Overflow` when it is not, such as a chip row or a header with a tab list.

</Do>

<Do>

Give a non-button its menu form through `overflow`: a `DropdownMenuSub` for a select or submenu, a `DropdownMenuItem` opening a `Dialog` for a text input, or `"never"` to pin the item in the row.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="Bare controls in the row">

<Wrong>

```tsx
<Toolbar aria-label="Well actions">
  <Button variant="outline"><TagIcon data-icon="inline-start" />Add tag</Button>
  <Button variant="outline"><ShareIcon data-icon="inline-start" />Share</Button>
  <Button onClick={create}>New well</Button>
</Toolbar>
```

</Wrong>

<Correct>

```tsx
<Toolbar aria-label="Well actions">
  <OverflowItem value="tag" label="Add tag" icon={<TagIcon />} onClick={addTag}>
    <Button variant="outline"><TagIcon data-icon="inline-start" /><OverflowLabel>Add tag</OverflowLabel></Button>
  </OverflowItem>
  <OverflowItem value="share" label="Share" icon={<ShareIcon />} onClick={share}>
    <Button variant="outline"><ShareIcon data-icon="inline-start" /><OverflowLabel>Share</OverflowLabel></Button>
  </OverflowItem>
  <Button onClick={create}>New well</Button>
</Toolbar>
```

</Correct>

Only an `OverflowItem` registers itself with the row's store, so only it can be measured, collapsed or moved into the menu: a row of bare buttons is entirely fixed, no More button is ever rendered, and the row wraps or scrolls instead.

</Dont>

<Dont severity="HIGH" title="Label text that is not in an OverflowLabel">

<Wrong>

```tsx
<OverflowItem value="export" label="Export" icon={<DownloadIcon />} onClick={exportRows}>
  <Button variant="outline"><DownloadIcon data-icon="inline-start" />Export</Button>
</OverflowItem>
```

</Wrong>

<Correct>

```tsx
<OverflowItem value="export" label="Export" icon={<DownloadIcon />} onClick={exportRows}>
  <Button variant="outline"><DownloadIcon data-icon="inline-start" /><OverflowLabel>Export</OverflowLabel></Button>
</OverflowItem>
```

</Correct>

The icon-only stage works by putting `sr-only` on `OverflowLabel` alone, so plain text keeps its width: the item never reaches a compact size, the measured pair is wrong, and the row skips the collapse stage and starts hiding items instead.

</Dont>

<Dont severity="HIGH" title="The handler on the button instead of on the item">

<Wrong>

```tsx
<OverflowItem value="delete" label="Delete" icon={<Trash2Icon />} variant="destructive">
  <Button variant="destructive" onClick={remove}><Trash2Icon data-icon="inline-start" /><OverflowLabel>Delete</OverflowLabel></Button>
</OverflowItem>
```

</Wrong>

<Correct>

```tsx
<OverflowItem value="delete" label="Delete" icon={<Trash2Icon />} variant="destructive" onClick={remove}>
  <Button variant="destructive"><Trash2Icon data-icon="inline-start" /><OverflowLabel>Delete</OverflowLabel></Button>
</OverflowItem>
```

</Correct>

The item's `onClick` (and `disabled`) is both the handler of the generated `DropdownMenuItem` and passed on to the single control element inside the item, so it fires in both places; left on the button alone, the More-menu entry is built with no handler and does nothing once the item is hidden.

</Dont>

{/* guidelines:end */}

## API Reference

### Toolbar, Overflow

`Toolbar` is a `div` with `role="toolbar"` and the keyboard described above (give it an `aria-label`); `Overflow` is a plain `div`. Both accept `div` props and:

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `orientation` | `"horizontal" \| "vertical"` | "horizontal" | Axis of the row; a vertical row measures heights. |
| `labels` | `"auto" \| "always" \| "never"` | "auto" | `auto` collapses labels before hiding items; `always` keeps them; `never` is icon-only from the start. |
| `minimumVisible` | `number` | 0 | Items kept in the row regardless of width. |
| `lastResort` | `"wrap" \| "scroll"` | "wrap" | What happens when fixed items alone do not fit. A vertical row always scrolls. |
| `menu` | `boolean` | true | Render the trailing `OverflowMenu`; pass `false` to place one yourself. |
| `overflowBadge` | `boolean` | false | Show how many items are in the More menu as a count badge on the trigger of the automatic menu (`badge` on `OverflowMenu`). |

### OverflowItem

A `div` wrapper around one control. Must be a direct child of the row.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `value` | `string` | - | Stable identity of the item, also the key of its menu item. |
| `priority` | `number` | 0 | Higher stays in the row longer. |
| `label` | `string` | - | Menu item text, tooltip, and the accessible name while icon-only. |
| `icon` | `ReactNode` | - | Icon of the menu item. |
| `shortcut` | `ReactNode` | - | Shortcut hint of the menu item. |
| `onClick` | `() => void` | - | Handler of the default menu item; also passed to the item's single control element. |
| `disabled` | `boolean` | - | Disables the menu item and the item's single control element. |
| `variant` | `"default" \| "destructive"` | "default" | Menu item variant. |
| `labelBehavior` | `"collapse" \| "keep"` | "collapse" when `label` is set and the control has an icon (`svg`, `img` or `[data-icon]`), else "keep" | Whether the label drops to icon-only. A text-only item cannot go icon-only; `"collapse"` without an icon warns in development. |
| `tooltip` | `boolean` | `labelBehavior !== "keep"` | Show `label` as a tooltip on the item's single control element while icon-only. |
| `elastic` | `boolean \| { min?: string; max?: string }` | - | Shrink between these inline sizes before anything collapses (`12rem` to `100%` by default). |
| `overflow` | `ReactNode \| "never"` | - | Menu form; `"never"` makes the item fixed. Omit for a button. |

### OverflowLabel

A `span` for the label text of an item; visually hidden while the row is icon-only.

### OverflowDivider

A `Separator` across the row, hidden once nothing visible remains on one side of it or when it would sit next to another divider.

### OverflowSpacer

A zero-cost flexible space. Items before it sit at the start of the row, items after it at the end. Like a divider, it leaves once one side of it is empty.

### OverflowGroup

Renders no element. `value` (stable identity), optional `label` (menu section heading) and `collapse` (`"individually"` or `"together"`).

### OverflowMenu

The trailing More button and its menu. Rendered automatically unless the row has `menu={false}`.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | "More actions" | Accessible name of the default trigger. |
| `trigger` | `ReactElement` | - | A custom trigger button element (`<Button variant="outline">More</Button>`) instead of the ellipsis. |
| `badge` | `boolean` | false | Show how many items are in the menu as a count badge on the trigger ("99+" above 99). The badge is visual only: the menu lists the items it counts. |
| `className` | `string` | - | Classes for the wrapper around the trigger. |

### useIsOverflowItemVisible(value)

Returns whether the item is currently in the row.
