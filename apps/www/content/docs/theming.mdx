Tecton UI applies the Tecton visual language **only through the shadcn CSS variables**: the theme is a set of values for `--background`, `--primary`, `--ring` and friends in `globals.css`, plus a few extra tokens for Tecton-only semantics. No CSS targets the generated components. Underneath, the Tecton colour ramps replace Tailwind's stock palette, so `bg-red-140` in application code is a Tecton colour too.

## How it works

<Steps>

<Step>Raw tokens</Step>

`src/styles/tecton-tokens.css` is the Tecton CSS export, pasted verbatim: every token as a custom property (`--tecton-color-bg-default`, `--tecton-radius-50`, …) with a light block (`:root`) and a dark block (`.dark` / `[data-theme="dark"]`). `tokens/tecton.tokens.json`, the Figma variables export, is the source of the [palette](#palette).

<Step>Mapping as data</Step>

`tokens/tecton.map.json` says which Tecton token each shadcn variable takes, with a confidence (`exact` or `approximated`) and a note. The export is themed, so one `var(--tecton-…)` reference serves both modes.

<Step>Generated theme</Step>

`pnpm --filter @tecton/react tokens:build` writes `tecton-palette.css` and `tecton-theme.css`, patches the variable values, `@theme inline`, the imports and the `dark` variant in `globals.css` (nothing else) and writes `docs/TOKEN-MAPPING.md`.

<Step>Verification</Step>

`tokens:check` verifies completeness, WCAG contrast of every surface / foreground pair, and that every semantic colour is a member of an exposed palette ramp. The tables below come from the same data.

</Steps>

## Dark and light

Both modes come from the Tecton export: `--background` is `var(--tecton-color-bg-default)` in `:root` and `.dark`, and the token itself switches (`#f6f4f7` light, `#1d1c1f` dark). Applications are dark-first. Switch the mode with the `dark` class on `<html>` (this site uses `next-themes` with `attribute="class"`); `data-theme="dark"` on the document root works the same way.

### Inverted sections

Put the `light` or `dark` class on any element — or `theme="light"` / `theme="dark"` on [`ThemeRoot`](/docs/tecton/theme-root) for a mounted application — and everything below it follows: `color-scheme`, the raw tokens, the palette, the shadcn variables and the `dark:` utilities. Inside a page use the class; `data-theme` switches a whole document.

```tsx
<div className="light rounded-lg bg-background p-6 text-foreground">
  {/* a light panel in a dark page */}
</div>
```

<Callout>
  The `dark:` utilities follow one inversion: a light island in a dark page renders completely, and so does a dark island in a light one. A third marker nested inside still switches its variables, but its `dark:` utilities read the inversion above it.
</Callout>

## Extra tokens

Semantics shadcn does not have, added the documented shadcn way (a variable in `:root` / `.dark` plus a `--color-*` entry in `@theme inline`):

| Token | Utilities | Used for |
| --- | --- | --- |
| `--success`, `--warning`, `--info`, `--neutral` | `text-success`, `border-warning`, `bg-info` | Status text, borders and icons; with `--<status>-foreground` also a solid surface |
| `--success-surface`, `--warning-surface`, `--info-surface`, `--neutral-surface`, `--destructive-surface` | `bg-warning-surface`, `text-warning-surface-foreground` | Filled status surfaces (filled alerts, solid status badges) |
| `--destructive-foreground` | `text-destructive-foreground` | Text on a `destructive` surface |
| `--surface-alt` | `bg-surface-alt` | Alternate table rows |
| `--border-subtle`, `--border-strong` | `border-border-subtle`, `bg-border-strong` | Separator emphasis levels |
| `--font-sans`, `--font-mono` | `font-sans`, `font-mono` | Figtree / IBM Plex Mono |
| `--radius-sm` … `--radius-2xl` | `rounded-sm` … `rounded-2xl` | Tecton radius scale (2/4/8/12/16px) |

## Palette

Tecton's foundational colours are **contrast ramps**: fifteen families of twenty-three steps, from `50` (barely off the page background) to `1570` (maximum contrast), with separate values for light and dark. A step is the same perceived distance from the background in both modes, so one class serves both and `dark:` variants are not needed.

`tokens:build` exposes them in `tecton-palette.css` as `--tecton-palette-<family>-<step>` and one `--color-<family>-<step>` theme entry each, so `bg-blue-560`, `text-orchid-830` or `border-yellow-160` work. **Tailwind's stock palette is removed** (`--color-*: initial`): `bg-red-500` or `text-zinc-400` produce no CSS. Only `white` and `black` are kept (for overlays such as `bg-black/10`).

<PaletteTable feedback="toast" />

| Recipe | Classes | Where Tecton uses it |
| --- | --- | --- |
| Tinted surface with readable text | `bg-<family>-120 text-<family>-830` | Filled status badges and alerts |
| Solid fill with light text | `bg-<family>-560 text-<family>-50` | Filled status buttons, avatar badges |
| Coloured text or icon | `text-<family>-560` | Status text, links |
| Border | `border-<family>-160` | Tinted alerts |

Prefer a semantic token (`bg-primary`, `text-success`, `bg-warning-surface`) whenever one exists; use a palette step for the rest (a chart series, a tag colour) instead of a hex value. Not exposed: the `core` ramps, the `surface` / `transparent` / `saturations` / `washes` sub-ramps (use an opacity modifier, `bg-gray-370/20`), the chart colormaps and the app accent colours. The focus outline is `--ring`.

To update the palette, replace `tokens/tecton.tokens.json` with a newer Figma export and run `tokens:build` and `tokens:check`; the family list is under `palette` in `tokens/tecton.map.json`.

## Beyond the variables

The rest of the Tecton look comes from the `base-tecton` style (see [CLI & updates](/docs/cli)), not from overrides:

- **Focus ring** — a solid 2px `ring-2 ring-ring` instead of Vega's soft 3px halo.
- **Hover and press** — buttons lighten towards the foreground instead of darkening with `primary/80`.
- **Flat controls** — no `shadow-xs` on buttons, inputs and triggers.
- **Variants** — status and appearance on [Alert](/docs/components/alert) and [Badge](/docs/components/badge), `emphasis` on [Separator](/docs/components/separator), filled and text [Input](/docs/components/input), [Textarea](/docs/components/textarea) and [Select](/docs/components/select).

## Adding your own tokens

Declare the variable and expose it to Tailwind. Pick the value from the palette so it follows both modes without a `.dark` entry:

```css title="app.css"
:root {
  --highlight: var(--tecton-palette-yellow-830);
}
@theme inline {
  --color-highlight: var(--highlight);
}
```

Inside the library, add the entry to `tokens/tecton.map.json` under `extra` and run `tokens:build` instead.
