## Usage

```tsx
import {
  createColumns,
  DataTable,
  DataTableActionBar,
  DataTableContent,
  DataTableFilter,
  DataTableFooter,
  DataTablePagination,
  DataTableSearch,
  DataTableToolbar,
} from "@tecton/react/data-table"
```

```tsx
const columns = createColumns<Well>([
  { id: "name", header: "Well" },
  { id: "status", header: "Status", type: "options", options: STATUSES },
  { id: "depth", header: "TD (m)", type: "number" },
  { id: "spud", header: "Spud date", type: "date" },
])

<DataTable items={wells} columns={columns} selectionMode="multiple" filterable pagination>
  <DataTableToolbar>
    <DataTableSearch />
    <DataTableFilter column="status" />
  </DataTableToolbar>
  <DataTableActionBar>
    <Button size="sm" onClick={shutIn}>Shut in</Button>
  </DataTableActionBar>
  <DataTableContent aria-label="Wells" />
  <DataTableFooter>
    <DataTablePagination pageSizes={[10, 25, 50]} />
  </DataTableFooter>
</DataTable>
```

- Each item needs an `id`, or pass `itemToId`.
- Make the columns once, at module level or in a `React.useMemo`.
- For a short table that is read, not worked with, use [Table](/docs/components/table).

## Composition

```text
DataTable
├── DataTableToolbar
│   ├── DataTableSearch
│   ├── DataTableFilter
│   ├── DataTableGroupBy
│   └── DataTableColumnsMenu
├── DataTableActionBar
├── DataTableActiveFilters
├── DataTableContent
│   └── DataTableRowActions (in a column's cell)
└── DataTableFooter
    └── DataTablePagination
```

The root holds the state and turns features on: `selectionMode`, `pagination`, `filterable`, `groupable` and the `…Columns` props. A part whose feature is off renders nothing and warns in development.

Put `DataTablePagination` in a `DataTableFooter` right after `DataTableContent`. That footer is the table's last band: inside its border, below the totals row, and fixed while a virtualized table's rows scroll. A second footer, or one placed elsewhere, is a plain row under the table.

## Columns

A column's `type` sets how its values are shown, aligned and sorted. A `cell` draws your own content ([Custom cells](#custom-cells)), and a column with `columns` is a group.

This example has `reorderableColumns`: drag a header to move its column. A line shows where it will drop.

<ComponentPreview name="data-table-columns" align="start" />

| `type`             | Align  | Shown as                                     | Sorted                    |
| ------------------ | ------ | -------------------------------------------- | ------------------------- |
| `"text"` (default) | start  | the text                                     | natural, case-insensitive |
| `"number"`         | end    | `Intl.NumberFormat` with `format`            | numerically               |
| `"date"`           | start  | `Intl.DateTimeFormat` with `format`          | chronologically           |
| `"boolean"`        | center | a check for `true`                           | `false` first             |
| `"options"`        | start  | a [Badge](/docs/components/badge) per option | in `options` order        |

- Return raw numbers and `Date`s from `accessor`, not formatted text.
- Numbers and dates use IBM Plex Mono with tabular figures. A column's values line up, and a changing value keeps its width.
- Empty values sort last and show a muted dash ([Empty values](#empty-values)).
- A column in a group moves only among its group's columns. A group moves with all its columns.

### Sorting by several columns

Click a header to sort by that column alone. <Kbd>Shift</Kbd> + click adds it as the next sort.

- <Kbd>Shift</Kbd> + click, or <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd>, adds a
  column to the sort. On a column already in the sort, it reverses the
  direction.
- While two or more columns sort, each sorted header shows its place beside the arrow. Screen readers hear it with the direction: "2 of 2 in sort order".
- The table above starts sorted by Field, then MD.

Column menus do the same without the keyboard. A column has a menu when `resizableColumns`, `hideableColumns`, `pinnableColumns` or `groupable` is on.

| Menu item                                     | Does                                                                |
| --------------------------------------------- | ------------------------------------------------------------------- |
| **Sort ascending**, **Sort descending**       | Sorts by this column alone.                                         |
| **Add to sort**, then Ascending or Descending | Appends the column to the sort. Shown while another column sorts.   |
| **Sort order: 2 of 3**                        | On a column in the sort: shows its place and changes its direction. |
| **Remove from sort**                          | Takes the column out of the sort.                                   |
| **Clear sort**                                | Removes every sort.                                                 |

```tsx
<DataTable
  items={wells}
  columns={columns}
  defaultView={{
    sorting: [
      { column: "field", direction: "ascending" },
      { column: "md", direction: "descending" },
    ],
  }}
>
```

- `view.sorting` lists the sorts in order, first one first.
- In [server mode](#server-data), the server gets the whole list from `onViewChange`.
- `multiSort={false}` keeps the table to one sort. <Kbd>Shift</Kbd> + click then sorts alone, the menus have no **Add to sort**, and a view keeps only its first sort.

### Custom cells

`cell(item, details)` draws a column's cell. It changes only how the value looks: sorting, filters, search, power search, grouping, totals and the CSV export still use the `accessor` value and the column's `type`.

In this example, each well links to its page, with its field below. The engineer has an [Avatar](/docs/components/avatar), the water cut has a [Meter](/docs/tecton/meter), and the oil rate shows how it moved. The table is sorted by oil rate, and every header still sorts by the column's value.

<ComponentPreview name="data-table-custom-cells" align="start" />

| `details` field | Holds                                                                                |
| --------------- | ------------------------------------------------------------------------------------ |
| `value`         | The raw value, from `accessor`.                                                      |
| `text`          | The value formatted as the column formats it, with `format` and the provider locale. |
| `emptyValue`    | What a missing value shows: the muted dash, read as "No value".                      |
| `id`            | The row's id.                                                                        |
| `column`        | The column.                                                                          |
| `depth`         | The row's depth in a tree or in groups.                                              |

- Draw `text` rather than formatting the value again.
- For a missing value, return `emptyValue`, so the cell keeps the table's convention.
- Controls in a cell, such as a link, a button or an input, are reached with <Kbd>Enter</Kbd> or <Kbd>F2</Kbd> from the cell ([Keyboard](#keyboard)).
- Give a graphic a name, like the meter's `aria-label` here.
- Put into words what a colour or an icon says, like the trend's "since last month".

`renderHeader` draws a header's content, while `header` stays the plain text that menus and screen readers use. `renderAggregate` draws a totals or subtotal cell.

## Hiding, pinning and reordering

`DataTableColumnsMenu` lists the columns to show, hide or pin. Each header's menu has the same actions.

<ComponentPreview name="data-table-column-pinning" align="start" />

| Root prop            | The user                          | View field       | Column opt-out       |
| -------------------- | --------------------------------- | ---------------- | -------------------- |
| `resizableColumns`   | drags or fits a column's width    | `columns.widths` | `resizable: false`   |
| `reorderableColumns` | drags a header to a new place     | `columns.order`  | `reorderable: false` |
| `hideableColumns`    | hides a column                    | `columns.hidden` | `hideable: false`    |
| `pinnableColumns`    | pins a column to the start or end | `columns.pinned` | `pinnable: false`    |

Pinned cells are opaque, filled with `var(--surface)`. On a custom surface, set that variable too: `className="bg-muted [--surface:var(--color-muted)]"`.

## Search and filters

`filterable` turns on `DataTableSearch`, a `DataTableFilter` per column and `DataTableActiveFilters`. When the toolbar runs out of room, it moves its items into an overflow menu.

<ComponentPreview name="data-table-filters" align="start" />

| `type`    | Filter                                              | Value in the view                                                            |
| --------- | --------------------------------------------------- | ---------------------------------------------------------------------------- |
| `text`    | contains any of the texts, added as chips           | `{ type: "text", values }`                                                   |
| `number`  | Min and Max side by side, with the column's unit    | `{ type: "number", ranges: [{ min?, max?, minExclusive?, maxExclusive? }] }` |
| `date`    | a [date range picker](/docs/components/date-picker) | `{ type: "date", ranges: [{ from?, to? }] }`                                 |
| `boolean` | Yes and No, checkboxes with counts                  | `{ type: "boolean", values }`                                                |
| `options` | a checkbox per option, with counts                  | `{ type: "options", values }`                                                |

- Every filter value is a list. A row matches when it matches any item: a text it contains, a value, or a range it is in.
- Search matches the shown columns' display text, ignoring case and accents.
- Each filter offers "No value" (`empty: true`) when the column has empty values ([Empty values](#empty-values)).
- A column's own `filter(item, value)` replaces its type's filter.
- A yes / no filter is laid out like an options filter. With neither chosen it keeps every row, and Clear goes back to that.

Text filters:

- Type a text and press <Kbd>Enter</Kbd> or a comma to add it as a chip. Each chip has a remove button.
- <Kbd>Backspace</Kbd> in the empty field removes the last chip.
- What you type applies as you type, beside the chips. Under the field, the filter shows how many rows match.

Number filters:

- Min and Max are [number fields](/docs/tecton/number-field). Step them with their minus and plus buttons or the arrow keys.
- The unit sits on the side where the column writes it: a unit, a percent sign or a currency, from the column's `format`.
- Type a percent as the column shows it: 12.5 for 0.125.
- Under the fields, the filter shows how many rows match as you type ("12 of 120 match"). It counts the rows the search and the other filters keep. In server mode there is no count, since the table holds only the loaded rows.
- Both bounds are included. `minExclusive: true` or `maxExclusive: true` leaves out the bound itself, as `>` and `<` do in a [power search](#power-search).
- An exclusive bound reads "> 3,000 m" or "> 1,000 and ≤ 3,000" on the button and chip. Editing that bound in the filter includes it again.
- In server mode, apply exclusive bounds yourself: `minExclusive` means `value > min`, otherwise `value >= min`.

Number and date filters with several ranges:

- A [power search](#power-search) can set several ranges (`td:<1000,>3000`). The button and chip show them all: "< 1,000, > 3,000".
- The popover edits the first range. A muted line under it says how many more there are. Editing keeps them, and Clear removes the whole filter.

## Power search

`<DataTableSearch syntax="query" />` turns the search into a query field, for people who filter all day. Typed terms set the same column filters as the filter buttons, and free words are the search.

<ComponentPreview name="data-table-power-search" align="start" />

### Syntax

| Term                                                                                             | Filter                                                                                    |
| ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `gullfaks`, `"aker bp"`                                                                          | the search: text in any shown column                                                      |
| `status:drilling,producing`                                                                      | an options column: any of the values, by value or label                                   |
| `subsea:yes`                                                                                     | yes / no                                                                                  |
| `well:a-12`, `well:a-12,b-3`                                                                     | a text column contains any of the texts                                                   |
| `td:3000`, `td:>=3000`, `td:>3000`, `td:<3000`, `td:1000..3000`                                  | a number column; `..` includes both ends, `>` and `<` are `minExclusive` / `maxExclusive` |
| `td:<1000,>3000`                                                                                 | a number in any of the ranges                                                             |
| `spud:2015`, `spud:2015-06`, `spud:jun 2015`, `spud:2015-06-30`, `spud:<2015`, `spud:2015..2016` | a date column, by whole days in the column's time zone                                    |
| `spud:last30d`, `spud:thismonth`, `spud:today`                                                   | a relative date (`last<N>d`, `w`, `m`, `y`; kept as such in the field)                    |
| `spud:2015,last30d`                                                                              | a date in any of the ranges                                                               |
| `td:none`, `td:>=3000,none`                                                                      | "No value", alone or beside the rest                                                      |

- A comma always means "any of". Each column type says what one item is: a text, a value, or a number or date range.
- A comma in quotes belongs to the text: `well:"a,b"`.
- A number or date keeps its own comma: `td:1,234.5`, `spud:jun 30, 2015`. In a locale that writes decimals with a comma, quote a number that follows another: `td:3,"5"`.
- A column's key is its header or its id. Case, accents, spaces and punctuation don't matter, so `spuddate` and `spud_date` both match "Spud date".
- Numbers and dates are read in the provider's locale. Quotes keep spaces together.
- Terms side by side all apply.
- Filters the query cannot write stay in the view: a column's own `filter`, a column with no key, or a number range with both ends and one of them exclusive beside other ranges.
- A filter button, a chip or a controlled `view` rewrites the query from the view, keeping the free words.

### Problems

A term with a problem is not applied. Examples are an unknown column or value, or a backwards range.

- Once typing pauses, the term is underlined. Its message shows at the top of the suggestions, and in a tooltip on the underline.
- `OR`, `NOT` and a leading `-` are not supported. They show as problems and are never applied another way. The term after `-` or `NOT` is left out with them.
- The message says what to type instead, using the table's own columns. For one of several values, it lists the first options column's values with commas (`status:drilling,producing`). For an exclusion, it suggests listing the values to keep.

### Suggestions

The suggestion list opens when the field gets focus and stays open the whole time it has focus. Typing, picking, moving the caret and pressing the field's buttons never close it.

- It closes when focus leaves the field. <Kbd>Escape</Kbd> closes it until you type, click in the field or press <Kbd>↓</Kbd>.
- A pick that completes a term keeps it open with the next term's columns. A comma typed right after it adds another value to the term instead.
- With nothing to suggest, it shows one muted line about the term at the caret: "Searching all columns for “pump”", the filter in its chip's words ("TD: ≥ 1,500 m"), or "No suggestions". Screen readers hear it politely.
- The clear button (✕) empties the field and keeps focus in it, with the list open.
- The "?" button lists the table's own columns, with examples, in the list's place. A press anywhere in an example's row adds it to the query and returns to the field.

The suggestions follow the caret:

- columns, with their type
- an options column's values, and a text column's, with their row counts
- after a comma, the next item of the same column, without the values already listed
- "No value"
- a number column's comparisons, with the data's range
- a date column's presets with the days they cover, the data's years and months, and the date filter's calendar, which writes the days it picks

Counts apply the rest of the query, as the filter popovers' counts do.

| Key                         | Does                                                                          |
| --------------------------- | ----------------------------------------------------------------------------- |
| <Kbd>↑</Kbd> / <Kbd>↓</Kbd> | Moves through the suggestions                                                 |
| <Kbd>Enter</Kbd>            | Picks the highlighted suggestion, else applies the query; the list stays open |
| <Kbd>Tab</Kbd>              | Completes what is typed; with nothing to complete, moves focus on             |
| <Kbd>Escape</Kbd>           | Closes the list; pressed again, clears the field                              |

### Server mode and loading

- In server mode, the field sends the filters and search through `onViewChange`, as the filter buttons do. The counts are the options' own `count`.
- The query field loads on demand. A plain field of the same size renders at once.
- The query code arrives in idle time, or when the field is pointed at or focused. Anything typed before then is kept and read once it arrives.
- A table with the plain search never loads it.

## Empty values

A value that is `null`, `undefined`, `""`, `NaN` or an invalid `Date` is empty. It shows as a muted em dash in the column's alignment, which screen readers read as "No value".

Return `null` from `accessor` for a missing value, never a placeholder such as "N/A". Some wells in the example above have no status, TD, spud date or subsea flag.

| Where         | An empty value                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------- |
| Cell          | A muted "—", read as "No value". The column's `emptyValue` replaces it; `null` leaves the cell blank. |
| Custom `cell` | Gets the column's `emptyValue` in its details, to return when `text` is `""`.                         |
| Search, CSV   | Empty text: never matched, an empty field.                                                            |
| Sorting       | Last, ascending and descending.                                                                       |
| Grouping      | One group, "No value", last.                                                                          |
| Totals        | Left out of the built-in aggregates.                                                                  |

```tsx
const columns = createColumns<Well>([
  { id: "operator", header: "Operator", emptyValue: "Unassigned" },
  {
    id: "report",
    header: "Report",
    cell: (well, { text, emptyValue }) =>
      text === "" ? emptyValue : <Link href={well.reportUrl}>{text}</Link>,
  },
])
```

While any row has no value in a column, that column's filter offers "No value":

| Filter       | "No value" is                                          | Chip                              |
| ------------ | ------------------------------------------------------ | --------------------------------- |
| Options      | the last option, set apart, with its count             | "Status: Producing, No value"     |
| Text, number | a checkbox under the fields                            | "TD: 1,000 m–2,000 m or no value" |
| Date         | a checkbox beside Clear                                |                                   |
| Yes / no     | a checkbox after Yes and No, set apart, with its count | "Subsea: Yes or no value"         |

- It keeps the rows without a value, as well as those the rest of the filter keeps. When the rest is unset, it keeps only the rows without a value.
- In the view it is `empty: true` on the filter's value, beside its list. A value without it matches as before, so saved views keep working.
- In server mode the table sees only the loaded rows, so "No value" is always offered. It reaches `onViewChange` for the server to apply (`OR depth IS NULL`).

```ts
{ type: "number", ranges: [{ min: 1000, max: 2000 }], empty: true } // 1,000 to 2,000, or no value
{ type: "options", values: [], empty: true } // no value only
{ type: "text", values: [], empty: true } // no value only
{ type: "boolean", values: [true], empty: true } // yes, or no value
{ type: "boolean", values: [], empty: true } // no value only
```

## Selection

`selectionMode="single"` or `"multiple"` adds a checkbox column. `DataTableActionBar` shows while rows are selected, with the count, Clear and your actions.

<ComponentPreview name="data-table-selection" align="start" />

| Prop                      | Does                                                                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| `value` / `onValueChange` | The selected row ids.                                                                                |
| `isItemDisabled`          | Disables rows; `disabledBehavior="selection"` keeps them focusable and openable.                     |
| `itemToDisabledReason`    | Says why a disabled row cannot be selected.                                                          |
| `onActivate(id, item)`    | Called when a row opens: <Kbd>Enter</Kbd>, a double click, or a click while no row is selected.      |
| `itemToHref`              | Makes each row header a link, followed through the [TectonProvider](/docs/tecton/provider)'s router. |

- **Select all** selects every row the view matches, on every page.
- The disabled reason shows in a tooltip on the row's checkbox. It appears on hover, and when the arrow keys reach the row (`disabledBehavior="selection"`).
- Screen readers announce the disabled reason with the row.

## Row reordering

`reorderableRows` adds a drag handle at the start of each row. `onRowOrderChange(ids, eventDetails)` gets every item's id in the new order: put `items` in that order.

<ComponentPreview name="data-table-row-reordering" align="start" />

```tsx
<DataTable
  items={jobs}
  columns={columns}
  reorderableRows
  onRowOrderChange={(ids) => setJobs(ids.map((id) => byId.get(id)!))}
>
```

- Drag the handle, or reach it with <Kbd>→</Kbd> and press <Kbd>Enter</Kbd>.
- From the keyboard, <Kbd>↑</Kbd> / <Kbd>↓</Kbd> move the row one place at a time. Each place is announced, such as "Insert between 34/7-D-2 and 2/8-C-3".
- <Kbd>Enter</Kbd> drops the row and <Kbd>Escape</Kbd> cancels.
- Rows move in the items' order. While the view sorts, searches, filters or groups, the handles are hidden, but their column stays.
- With pages, a row moves within its page. In a virtualized table, the keyboard steps through every row.
- Flat lists only: row reordering is off in a tree.

## Load more

For rows sent in batches, `hasMore` says more follow and `onLoadMore` loads the next batch. Add each batch to `items`.

Set `loading` while a batch is out. When it fails, set `error` and `onRetry`: the error shows after the loaded rows, with Retry.

In this example the server sends 500 readings, 50 at a time. Switch between loading on scroll and with a button, and turn on "Fail the next batch" to see the error.

<ComponentPreview name="data-table-load-more" align="start" />

```tsx
<DataTable
  items={rows}
  columns={columns}
  dataMode="server"
  rowCount={total}
  hasMore={rows.length < total}
  onLoadMore={loadNext}
  loading={isLoading}
  error={error}
  onRetry={loadNext}
  className="h-96"
>
  <DataTableContent aria-label="Meter readings" virtualized />
</DataTable>
```

`loadMore` sets how the next batch is asked for:

| `loadMore`           | Next batch                                                                     | Use it when                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `"scroll"` (default) | Loads as the end of the rows comes near, with loading rows after the last row. | The table has a bounded height (`virtualized`) or is the last thing on the page, so the user only scrolls.          |
| `"button"`           | Loads when the user presses Show more, after the last row.                     | Content follows the table and loading on scroll would keep pushing it away, or the user should decide when to load. |

- Beside Show more, a count reads "Showing 50 of 500", out of `rowCount` in server mode. Without `rowCount` it reads "Showing 50 rows".
- The button spins while the batch loads, and keeps focus. Once no more rows follow, focus moves to the first new row.
- Screen readers hear "Loaded 50 more rows".
- Load more is off with `pagination`.
- In client mode, load more is also off while a search or filter is in effect. Use server mode to load what matches.

## Live data

For rows that arrive while the user watches, set `highlightChanges`. Examples are alarms, events or readings pushed by a subscription. It shows what came without moving what the user is looking at.

Put each new record in `items`, as for any change.

In this example, start the feed: an alarm is raised every two seconds and lands where the sort by pressure puts it. Scroll down, point at a row or open its menu, and pause the feed to compare.

- **Pages** shows ten rows a page instead of a scrolling table.
- **Group by severity** puts the alarms in groups. Close a group to see its row take the highlight.
- **Stripes** turns the alternate row fills on and off under the highlight.

<ComponentPreview name="data-table-live" align="start" />

```tsx
<DataTable items={alarms} columns={columns} highlightChanges className="h-96">
  <DataTableContent aria-label="Pressure alarms" virtualized />
</DataTable>
```

### Highlight

A new row goes straight to its sorted place and is tinted until the user sees it.

- The tint is a light shade of the info colour, unlike hover or selection. It covers the whole row, pinned columns included.
- A striped, hovered or selected row keeps its own fill under the tint.
- A row counts as seen when half of it is in view, on the page shown. Its tint then fades out over 1.5 s.
- A row that lands in view fades at once. One that lands out of view, or on another page, keeps its tint until the user scrolls or pages to it.
- A row added inside a closed group, or under a closed tree row, highlights the group's row or the tree row.
- `highlightChanges={{ duration: 3000 }}` lengthens the fade.

### New-row buttons

New rows the user has not seen are counted in a button at each edge of the table.

| Button                                     | Counts                                   | Pressed                            |
| ------------------------------------------ | ---------------------------------------- | ---------------------------------- |
| "↑ 3 new rows", at the top                 | Rows above the view                      | Scrolls up to the topmost of them. |
| "↓ 2 new rows", at the bottom              | Rows below the view, on this page        | Scrolls down to the nearest.       |
| "3 new rows on other pages", at the bottom | Rows on other pages, once none are below | Turns to the first one's page.     |

- A button stays until each row it counts has been seen.
- Its accessible name says it in full, such as "3 new rows above".
- Rows that the search or filters hide are not counted.
- The buttons follow the table in the tab order while they show. They never take focus by themselves.
- Pressed from the keyboard, a button moves focus to the new row.
- They scroll smoothly to rows near the view, and jump to rows further away.

### The row the user is on

As rows land or leave above it, the row the user is on keeps its place on screen. That row is the first of these:

1. the row whose menu or popover is open
2. the row with focus
3. the row under the pointer
4. once the table is scrolled, the first row in view

- Rows added above it go above it, out of view if need be. The top button counts them.
- A row landing below it moves the rows under it down.
- At the top of the table, with nothing in use, new rows push the others down.
- With `pagination`, a row added to an earlier page would shift the whole page shown. While the pointer is over the rows, focus is in them or a row's menu is open, such rows wait.
- Waiting rows count in "on other pages", and arrive 0.3 s after the user is done.
- Only additions wait. Rows the application removes or changes apply at once.

### Which rows are added

A row is added when its id is in `items` but not in the previous `items`. In client mode `items` are compared, not the rows the view shows. A search or filter that brings rows back adds none.

These rows are not added:

- the rows of the first render, and the first rows of a table that starts empty
- rows that come with a load: while `loading`, in the change that ends it, and the batch `onLoadMore` asked for
- in server mode, the first `items` after the search, filters, sorting, grouping, page or page size change. Only `items` that change while the view stays the same are compared, so set `loading` while the server answers a view change.
- the children of a tree row, loaded as it opens. A child added to a row whose children were already there is added, open or not.

### Announcements and motion

- Screen readers hear "3 rows added", at most once a second, for the rows the view shows.
- With reduced motion, the buttons always jump instead of scrolling, and show and hide without moving.
- The highlight still fades with reduced motion: it is a change of colour, not of place.

## Server data

With `dataMode="server"`, the table reports each view and page change and shows the `items` the server returns. `rowCount` is the server's total.

In this example, <Kbd>Shift</Kbd> + click a second header. `view.sorting` holds both sorts, in order, and the request below carries them.

<ComponentPreview name="data-table-server" align="start" />

|                            | Client                   | Server                                           |
| -------------------------- | ------------------------ | ------------------------------------------------ |
| Sort, search, filter, page | the table                | the server, from `onViewChange` / `onPageChange` |
| Option counts              | from `items`             | each option's `count`; none for yes / no         |
| "No value" filter          | while a row has no value | always; `empty: true` in the filter              |
| Totals, export             | every matching row       | the loaded rows                                  |
| "Select all N"             | every matching row       | all matching: `eventDetails.allMatching.except`  |

Each filter in `view.filters` is a list. Match a row when it matches any item, and send the whole list, not its first item:

- `values` for text (contains), options and yes / no (equals);
- `ranges` for numbers and dates, each with its own bounds;
- `empty: true` also keeps the rows with no value.

```ts
function depthWhere(filter: DataTableFilterValue) {
  if (filter.type !== "number") return null
  const ranges = filter.ranges.map((range) =>
    [
      range.min === undefined
        ? null
        : `depth ${range.minExclusive ? ">" : ">="} ${range.min}`,
      range.max === undefined
        ? null
        : `depth ${range.maxExclusive ? "<" : "<="} ${range.max}`,
    ]
      .filter(Boolean)
      .join(" AND ")
  )
  if (filter.empty) ranges.push("depth IS NULL")
  return ranges.map((range) => `(${range})`).join(" OR ")
}
```

## The view

The sorting, search, filters, grouping and column layout are one JSON object. Start from `defaultView`, or control it with `view` / `onViewChange`.

A saved view is checked against the columns. Unknown or opted-out columns are dropped, without an error.

## Usage guidelines

### Use it when

- An application shows records in columns: a data grid of wells, work orders, run results or documents. Use `DataTable` for every such table, even one that only sorts today, so all tables look and behave the same.
- Users sort, search, filter, group, select, page or open rows, or hide, pin, resize or reorder the columns.
- The rows are many (`virtualized`), load as the user scrolls or presses Show more (`hasMore`), come from a server (`dataMode="server"`), or form a tree (`itemToChildren`) or detail rows (`renderDetail`). Rows that arrive while the user watches, such as alarms, events or readings from a subscription, use `highlightChanges`.

### Not for

- a short static table of a few rows that is only read, such as a spec sheet, a legend or the figures of a report: use [Table](/docs/components/table)
- a hierarchy that is browsed, with no columns: use [TreeView](/docs/tecton/tree-view)
- a list of rows with media, a title and actions rather than columns: use [Item](/docs/components/item)
- rows the user drags into an order of their own: use [Reorderable](/docs/tecton/reorderable)

### Do

<DoList>

<Do>

Make the columns once with `createColumns`, at module level or in a `React.useMemo`, each with an `id`, a plain-text `header` and a `type`. Return raw numbers and `Date`s from `accessor`, `null` for a missing value, and use `cell` only to draw a value differently.

</Do>

<Do>

Turn features on at the root (`selectionMode`, `pagination`, `filterable`, `groupable`, the `…Columns` props), then place their parts. For a table people filter all day, use the power search `<DataTableSearch syntax="query" />`, never a query parser of your own. Its suggestions and "?" help come with it: add no syntax legend or suggestion list.

</Do>

<Do>

Name the table with `aria-label` on `DataTableContent`. Open rows with `itemToHref` or `onActivate`, explain disabled rows with `itemToDisabledReason`, and put actions in `DataTableRowActions` and `DataTableActionBar`.

</Do>

<Do>

Set `size="sm"` and `striped` for dense data. Show states with `loading`, `error` with `onRetry`, and `empty` / `noResults` on `DataTableContent`.

</Do>

<Do>

In server mode, pass the page's `items`, `rowCount` and `loading`, and load from `onViewChange`, `onPageChange` and `onPageSizeChange`. Every filter in `view.filters` is a list a row matches any item of (`values` for text, options and yes / no, `ranges` for numbers and dates), plus `empty` for "No value": send the whole list, not its first item. For live data, set `highlightChanges` and never tint, animate or scroll rows yourself.

</Do>

</DoList>

### Don't

<Dont severity="CRITICAL" title="A records table hand-built on Table">

<Wrong>

```tsx
const rows = [...wells].sort(byDepth).slice(page * 10, page * 10 + 10)
<Table>
  <TableHeader>
    <TableRow>
      <TableHead><Checkbox checked={allSelected} onCheckedChange={toggleAll} /></TableHead>
      <TableHead><button onClick={() => setSort("depth")}>Depth</button></TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>{rows.map((well) => <WellRow key={well.id} well={well} />)}</TableBody>
</Table>
<Button onClick={() => setPage(page + 1)}>Next</Button>
```

</Wrong>

<Correct>

```tsx
<DataTable items={wells} columns={columns} selectionMode="multiple" pagination>
  <DataTableContent aria-label="Wells" />
  <DataTableFooter>
    <DataTablePagination />
  </DataTableFooter>
</DataTable>
```

</Correct>

Every hand-built table sorts, selects and pages a little differently, with no `aria-sort`, no grid keyboard, no announcements and no selection across pages; `DataTable` gives every application the same table.

</Dont>

<Dont severity="HIGH" title="Formatting values inside a cell">

<Wrong>

```tsx
const columns = createColumns<Well>([
  { id: "depth", header: "Depth (m)", cell: (well) => <div className="text-end">{well.depth.toLocaleString()}</div> },
])
```

</Wrong>

<Correct>

```tsx
const columns = createColumns<Well>([
  { id: "depth", header: "Depth (m)", type: "number", format: { maximumFractionDigits: 0 } },
])
```

</Correct>

Without `type` the column is text: it sits at the start, sorts and filters as text and has no sum, and `toLocaleString()` formats in the browser's locale, not the provider's.

</Dont>

<Dont severity="HIGH" title="Placeholder text for missing values">

<Wrong>

```tsx
const columns = createColumns<Well>([{ id: "depth", header: "Depth (m)", type: "number", accessor: (well) => well.depth ?? "N/A" }])
```

</Wrong>

<Correct>

```tsx
const columns = createColumns<Well>([{ id: "depth", header: "Depth (m)", type: "number", accessor: (well) => well.depth }])
```

</Correct>

"N/A" is a value: it is drawn as text instead of the table's muted dash, read as "N/A" in every locale, written to the CSV, and the filters' "No value" does not find it.

</Dont>

A spreadsheet-style page strip, for `pagination`. It takes the props of a `div`.

- At the start: "Rows", a rows-per-page [Select](/docs/components/select) named "Rows per page", and the rows shown ("21–30 of 50").
- At the end: [Pagination](/docs/components/pagination) with First, Previous, the page field, Next and Last. The arrows are disabled at the ends.
- The page field reads "Page [3] of 5". It is a [Number Field](/docs/tecton/number-field) from 1 to the last page, without minus and plus buttons.
- The page resets to 1 when the view changes.

In the page field:

- <Kbd>Enter</Kbd> opens the page typed, kept within the pages there are. An
  empty field goes back to the current page.
- Leaving the field also opens the page typed. A page out of range, a fraction or an empty field goes back to the current page.
- <Kbd>↑</Kbd>, <Kbd>↓</Kbd>, <Kbd>Home</Kbd> and <Kbd>End</Kbd> move through
  the pages at once.

Size and width:

- It follows the table's `size`. The default size has `icon-sm` arrows and the default Select and field. Compact (`size="sm"`) has `icon-xs` arrows and a small, borderless Select and field.
- It stays on one line. As it narrows, it drops, in turn: the "Rows" label (the Select keeps its name), the Select, First and Last, the words around the field ("[3] / 5" instead), and the rows shown.
- Previous, the page field and Next always stay. When each part drops depends on the size and on the digits of the last page.
- Its controls keep their places as the page changes, so the button under the pointer stays put. The rows shown keep the width of their widest text, and the field the width of the last page's number.
- A last page that is short of rows keeps the height of a full page.

| Prop        | Type                    | Default                | Description                                         |
| ----------- | ----------------------- | ---------------------- | --------------------------------------------------- |
| `pageSizes` | `ReadonlyArray<number>` | the root's `pageSizes` | The page sizes offered; `[]` leaves the Select out. |

Each page change calls the root's `onPageChange` with a `reason`:

| `reason`                                       | Source                                                               |
| ---------------------------------------------- | -------------------------------------------------------------------- |
| `"first"`, `"previous"`, `"next"`, `"last"`    | The pager's arrow buttons.                                           |
| `"page"`                                       | The page field: typed, or stepped with the arrow keys, Home and End. |
| `"new-rows"`                                   | The "new rows on other pages" button ([Live data](#live-data)).      |
| `"reset"`, `"page-size"`, `"clamp"`, `"group"` | Any other change.                                                    |

### createColumns

`createColumns<T>(columns)` validates the columns for `DataTable`; it throws on an empty or repeated id.

| Field                                              | Type                                                                         | Default                       | Description                                          |
| -------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------- | ---------------------------------------------------- |
| `id`                                               | `string`                                                                     | -                             | Unique id, used by the view.                         |
| `header`                                           | `string`                                                                     | -                             | Header text and accessible name.                     |

| `format`                                           | `Intl.NumberFormatOptions \| Intl.DateTimeFormatOptions`                     | -                             | Number or date format.                               |
| `options`                                          | `ReadonlyArray<DataTableOption>`                                             | -                             | `{ value, label, variant?, count? }`, in sort order. |
| `cell`                                             | `(item: T, details) => ReactNode`                                            | -                             | Custom cell content.                                 |

| `renderHeader`                                     | `(details) => ReactNode`                                                     | -                             | Custom header content.                               |
| `align`                                            | `"start" \| "center" \| "end"`                                               | by type                       | Cell and header alignment.                           |
| `compare`                                          | `(a: T, b: T) => number`                                                     | -                             | Custom ascending sort.                               |
| `filter`                                           | `(item: T, value: DataTableFilterValue) => boolean`                          | -                             | Custom filter.                                       |
| `aggregate`                                        | `"sum" \| "avg" \| "min" \| "max" \| "count" \| "countDistinct" \| function` | by type                       | Group and totals figure.                             |
| `renderAggregate`                                  | `(value, { items }) => ReactNode`                                            | -                             | Custom aggregate content.                            |
| `rowHeader`                                        | `boolean`                                                                    | first column                  | Names each row.                                      |
| `description`                                      | `string`                                                                     | -                             | Info popover in the header.                          |
| `width`                                            | `number`                                                                     | content                       | Initial width in px.                                 |
| `minWidth`, `maxWidth`                             | `number`                                                                     | `48`, -                       | Width bounds in px.                                  |
| `hideBelow`                                        | `"sm" \| "md" \| "lg"`                                                       | -                             | Hidden below the breakpoint.                         |

A group is `{ id, header, description?, columns }`. `cell` gets `{ id, column, value, text, depth, emptyValue }`; `renderHeader` gets `{ column, header, sorted }`.

### DataTableView

```ts
type DataTableView = {
  sorting: ReadonlyArray<{
    column: string
    direction: "ascending" | "descending"
  }>
  search: string
  filters: Readonly<Record<string, DataTableFilterValue>>
  grouping: ReadonlyArray<string>
  columns: {
    order: ReadonlyArray<string>
    hidden: ReadonlyArray<string>
    widths: Readonly<Record<string, number>>
    pinned: { start: ReadonlyArray<string>; end: ReadonlyArray<string> }
  }
}

// `view` and `defaultView` take a DataTablePartialView: every part optional.
// Every filter is a list: a row matches when it matches any item. `empty: true`
// is "No value": the rows without a value match too, or alone when the list
// is empty.
type DataTableFilterValue =
  | { type: "text"; values: ReadonlyArray<string>; empty?: boolean }
  | {
      type: "number"
      ranges: ReadonlyArray<DataTableNumberRange>
      empty?: boolean
    }
  | { type: "date"; ranges: ReadonlyArray<DataTableDateRange>; empty?: boolean }
  | { type: "boolean"; values: ReadonlyArray<boolean>; empty?: boolean }
  | { type: "options"; values: ReadonlyArray<string>; empty?: boolean }
  | { type: "custom"; value: unknown }

// Both ends are included, but with `minExclusive` / `maxExclusive: true`
// (`value > min`, `value < max`).
type DataTableNumberRange = {
  min?: number
  max?: number
  minExclusive?: true
  maxExclusive?: true
}

// Both ends are included; a `to` at midnight includes that whole day.
type DataTableDateRange = { from?: Date; to?: Date }
```

### TableColumnResizer

`@tecton/react/table-column-resizer`: the resize grip of a column header, for a plain [Table](/docs/components/table).

| Prop               | Type                            | Default | Description                                |
| ------------------ | ------------------------------- | ------- | ------------------------------------------ |
| `value`            | `number`                        | -       | Width in px (controlled).                  |
| `defaultValue`     | `number`                        | `150`   | Initial width.                             |
| `onValueChange`    | `(value, eventDetails) => void` | -       | Called while the width changes.            |
| `onValueCommitted` | `(value, eventDetails) => void` | -       | Called when a drag or key ends.            |
| `min`              | `number`                        | `48`    | Narrowest width.                           |
| `max`              | `number`                        | `1000`  | Widest width.                              |
| `step`             | `number`                        | `8`     | Arrow key step.                            |
| `resetValue`       | `number`                        | -       | Width on <Kbd>Enter</Kbd> or double click. |
| `label`            | `string`                        | -       | Column name, for `"Resize {label}"`.       |
| `disabled`         | `boolean`                       | `false` | Turns it off.                              |
